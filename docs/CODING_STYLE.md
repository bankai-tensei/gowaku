# gowaku coding style

[日本語](CODING_STYLE.ja.md)

Scope: the gowaku library and its examples. For the overall structure, see [ARCHITECTURE.md](ARCHITECTURE.md).

These rules are for looking things up when in doubt. For anything not covered here, follow [Effective Go](https://go.dev/doc/effective_go) and
[Go Code Review Comments](https://go.dev/wiki/CodeReviewComments).
If a rule has to be broken, write the reason in a comment where it is broken, or fix the rule.

---

## 1. Five principles

1. **Write for the reader.** Boring code over clever code. One concept per file, one job per function.
2. **Dependencies point down only.** Upper layers may know lower layers, never the reverse (§3). Lint stops violations mechanically.
3. **Hot paths allocate nothing.** Code that runs every frame is checked with `go test -bench` for allocs/op = 0 (§7).
4. **Keep unsafe and OS calls at the boundary.** `unsafe`, `syscall` and `purego` do not leave `platform/*` and `gpu/*` (§8).
5. **Make it testable without a GPU.** `core` / `layout` / `paint` / `text` / `theme` / `motion` pass `go test ./...` with no GPU and no window (§10).

| What | Command | When |
|------|----------|------|

| Shader generation | `go generate ./gpu/...` | When shaders change |

- The lint configuration is `.golangci.yml` at the repository root. `depguard` stops layer dependency violations.
- `//nolint` is per line and always has a reason: `//nolint:gocritic // vtable call needs raw uintptr`. File-level nolint is forbidden.
- Generated files start with `// Code generated by <tool>; DO NOT EDIT.` and are not edited by hand.

## 3. Packages and dependency direction

### 3.1 Layers and allowed imports

```
widgets/* ─→ core, layout, paint, icons, text, theme, motion, input, semantics, geom (6 tiers inside; an upper tier imports only lower tiers. ADR 0081)
motion   ─→ core, geom
theme    ─→ text, paint (types only), geom
layout   ─→ core, paint, input, semantics, geom
core     ─→ paint, text, input, semantics, geom
text     ─→ paint (types only), geom
icons    ─→ paint, geom (stock icons as paths. ADR 0127)
paint    ─→ geom
render   ─→ paint, text, gpu, geom
gpu      ─→ platform (NativeHandle only), geom
platform ─→ input, semantics, geom
semantics ─→ geom (the accessibility tree; visible from both core and platform. ADR 0042)
input    ─→ nothing
geom     ─→ standard library only
gowaku (root) ─→ everything (holds only the app and window entry points; does not re-export widget or lower-layer types. ADR 0081)
```

- `core` does not know `layout`. The standard RenderObjects (Padding, Flex, Stack) live in `layout`, which implements the `core.RenderObject` interface.
- `core` / `layout` / `paint` / `text` / `theme` / `motion` **do not import `gpu` or `platform`**. This is what makes "testable without a GPU" true.
- Only `render` knows both the `paint` DisplayList and `gpu`.
- Sideways imports (between packages in the same tier) are also forbidden. If one is needed, move the shared part down a layer.
- Apps import the layer packages they use directly (`widgets/basic`, `widgets/control`, and so on). The root holds type aliases only for what every widget writes: `Widget`, `BuildContext`, `State` and similar. Dot imports are not used.

### 3.2 Package conventions

- Directory name = package name. Lowercase, singular, no underscores (`widgets` is the exception).
- Do not repeat the package name in identifiers: `paint.Canvas`, not `paint.PaintCanvas`.
- Anything not meant for outside use goes in `internal/`: `internal/testutil`, `internal/cmd/*`.
- Each package has a `doc.go` whose package comment states the layer's responsibility and what it must not import.
- `init()` has no side effects. It does not register GPU backends either (`gowaku.Run` picks one explicitly).
- Mutable package-level variables are forbidden. The exceptions are the in-process GPU device in `app` and the check flags under `-tags gowakudebug`. Both are listed in `doc.go`.

## 4. Naming

### 4.1 General

- Follow Go conventions: `MixedCaps`; acronyms are all upper case or all lower case (`ID`, `HTTP`, `hwnd`, `dpi`).
- No `Get` on getters: `w.Size()`, not `w.GetSize()`. Setters are `SetX`.
- Booleans are positive: `Enabled`, `Visible`. Do not create `Disabled` or `Hidden`. The exceptions are `Disabled` on option types (`RadioOption`, `DropdownOption`), so that a zero-value option is not disabled (ADR 0054), and on `field.Input`, which keeps its own text and so cannot use a nil callback for disabled as `Button` does (ADR 0143).
- Units are expressed by type. Time is `time.Duration`; lengths are `float32` logical pixels. No suffixes like `WidthPx`. Only places that handle physical pixels (`platform`, `gpu`) include `physical` in the name.
- Enumerations are typed constants plus `String()`:
  ```go
  type Axis uint8
  const (
      Horizontal Axis = iota
      Vertical
  )
  ```
  Order them so the zero value is the most natural default.

### 4.2 Common abbreviations (spell out everything else)

| Abbreviation | Meaning | Where |
|------|------|----------|
| `ctx` | `BuildContext` | Argument of Build functions |
| `cv` | `*paint.Canvas` | Argument of Paint functions |
| `c` | `layout.Constraints` | Argument of Layout functions |
| `el` | `Element` | Inside core |
| `ro` | `RenderObject` | Inside core / layout |
| `w` | `Widget` or `Window` | Only when unambiguous in context |
| `pos`, `off`, `sz` | Offset, Offset, Size | Local variables |
| `rr` | `RRect` | Local variables |
| `dt` | Elapsed time | motion |

### 4.3 Familiar names

Prefer the names that UI developers already know: `Padding`, `Row`, `Column`, `Expanded`, `Stack`, `State`, `Build`, `Key`. Render objects start with `Render` (`RenderPadding`). Geometry types live in `geom` (`Offset`, `Size`, `Rect`, `RRect`, `Color`, `Insets`). Do not carry over habits of other languages, such as nullable fields everywhere or copy-with helpers; make **the zero value a meaningful default** instead.

## 5. Type and API design

### 5.1 Widget

- A widget is a **value-type struct**. Do not pass it by pointer. Do not change it after creating it.
- Fields are exported, and every option is a field. No constructor functions (helpers such as `VStack` are the exception; §5.3).
- **Make the zero value usable.** `Text{}` draws an empty string, and `Padding{}` draws its child with zero inset. "Panic if a required field is unset" applies only to structurally required things such as `Child`.
- Callbacks start with `On`: `OnPress func()`, `OnChange func(string)`. If there are more than 2 arguments, use an event struct.
- Children are `Child Widget` (singular) or `Children []Widget` (plural). No other names.

### 5.2 Interfaces

- Small, and defined in the package that uses them. 1 to 3 methods is the guideline.
- Do not use `any` as an argument or return value. The exception is `Key`.
- reflect is allowed only for **type identity comparison** and the type key of `Inherited[T]`. Enumerating struct fields and reading tags are forbidden.
- Use generics to avoid reflect (`Tween[T]`, `Inherited[T]`). Not because they look nice.

### 5.3 Functions and arguments

- With more than 4 arguments, use an options struct. Do not use the functional options pattern (`WithX(...)`). Struct literals work better with diffing.
- Do not create method chains (`.Spacing(8).Children(...)`). A single-step method that returns a copy with one value replaced (`Color.WithAlpha`, `TextStyle.WithColor`) is neither a chain nor a functional option. Provide one only for fields that change often; otherwise copy and assign the field (ADR 0031).
- Variadic helpers (`VStack(a, b)`) are one-line functions that just return the matching struct, collected in `widgets/basic/helpers.go`.
- Do not use `context.Context`. A UI has no request scope. If cancellation is needed, express it with `Ticker` and `Dispose`.
- Do not mix `(T, bool)` and `(T, error)` in return values. Use `bool` if not finding something is normal, `error` if it is a failure.

### 5.4 Structs

- Field order: exported settings → exported state → unexported. Only `gpu` instance structs and `platform` ABI structs care about layout padding, and those have `unsafe.Sizeof` tests (§8).
- Embed only for "is-a" (`StateBase`, `RenderBase`). No embedding for convenience.
- Do not embed `sync.Mutex`. Keep it as a field `mu`, placed directly above what it guards.

## 6. Errors and panics

Initialization returns `error`; fatal errors at run time `panic`.

- **Where to return error**: `Run`, `platform.CreateWindow`, `gpu.New*`, `CreateTexture`, font loading, image decoding.
- **Where to panic**: `DEVICE_LOST` during a frame, API contract violations (SetState during Build, SetState from outside the UI goroutine, a Key that is not comparable).
- Panic messages start with `gowaku: ` and say which contract was violated:
  ```go
  panic("gowaku: SetState called during Build; move the call to a callback or InitState")
  ```
- Do not `recover` inside the library. Panics in user code propagate as they are.
- Wrap errors with the package name as a prefix, like `fmt.Errorf("d3d11: create swapchain: %w", err)`. Lowercase start, no trailing period.
- Errors that callers need to tell apart are exported as sentinels, like `var ErrNoGPU = errors.New("gowaku: no compatible GPU found")`, so they can be compared with `errors.Is`.
- When discarding an error, write `_ = f()` with a comment giving the reason. `errcheck` stops silent discards.
- Do not use the `log` package. The library logs to the default `log/slog` logger at `Debug` level, and only during `platform` and `gpu` initialization. Never on hot paths.

## 7. Performance rules (hot paths)

A hot path is **code that may run every frame**: reconcile, Layout, Paint, DisplayList → Batch conversion, the cache-hit path of text layout, hit testing, Ticker-driven value updates.

- **Do not allocate.** Reuse slices with `s = s[:0]`. Keep buffers that live across frames in struct fields.
- Each hot path has a `Benchmark*` that checks **allocs/op = 0** with `b.ReportAllocs()`. Where 0 is not possible, write the reason in the benchmark's comment.
- Do not use `fmt.Sprintf`, string concatenation other than `strings.Builder`, `any` arguments that involve conversion to `interface`, `defer` (inside loops), or `map` iteration (order-dependent).
- Use **float32** throughout. The `math` package is float64, so `geom` has `Sqrt32`, `Abs32`, `Floor32` and so on; use those.
- Use `reflect.TypeOf` only for type comparison in reconcile, and cache the result in the Element.
- Text is cached by `(text, style, maxWidth)`. A cache miss is not a hot path (shaping may allocate).
- No premature optimization either. Code outside the hot-path definition favors readability.

## 8. unsafe / syscall / purego rules

These may be written only in `platform/win32`, `platform/x11`, `platform/wayland`, `platform/cocoa`, `gpu/d3d11`, `gpu/vulkan` and `gpu/metal`. `depguard` in `.golangci.yml` stops imports in other packages.

- **Every use of unsafe has a comment** saying why it is needed and how long the pointer lives:
  ```go
  // pData must stay alive until Unmap; it is pinned by the pinner below.
  ```
- **Go pointers passed to C** are assumed valid only for the duration of the call. If C keeps one across calls, pin it with `runtime.Pinner` and make the `Unpin` site explicit. Put `runtime.KeepAlive` right after the call.
- **ABI structs** (`D3D11_TEXTURE2D_DESC`, `VkSwapchainCreateInfoKHR`, `XEvent` and so on) have one test per struct that compares `unsafe.Sizeof` with the C size. Also check `Offsetof` for fields that need care.
- **Handles are typed**: `type HWND uintptr`, `type VkDevice uintptr`. Raw `uintptr` does not appear in function signatures. Only the `NativeHandle` interface is passed above `platform`.
- **COM**: vtable indices are constants, with the interface and method name in a comment:
  ```go
  const (
      iDXGISwapChain_Present       = 8  // IDXGISwapChain::Present
      iDXGISwapChain_GetBuffer     = 9  // IDXGISwapChain::GetBuffer
  )
  ```
  `AddRef`/`Release` pairs are closed within each method. Structs that keep a reference have a `Release()` method, and forgetting to call it is detected with the `gowakudebug` tag.
- **purego**: `purego.Dlopen` once per library, with `sync.Once`. Symbols are resolved together at startup, and missing ones are returned as `error` (do not repeat go-vk's "crash on a nil call").
- OS structs and flag constants use the names from the official headers as is (`WM_IME_COMPOSITION`, `VK_IMAGE_LAYOUT_PRESENT_SRC_KHR`). Do not rename them Go-style. Being searchable comes first.

## 9. Concurrency

The UI belongs to the main goroutine only (the thread model in [ARCHITECTURE.md](ARCHITECTURE.md)).

- **Do not start goroutines** inside `core` / `layout` / `paint` / `widgets` / `motion`. Do not use `sync` there either.
- Only the `app.Post` queue and `gpu` texture uploads cross goroutines. Only these hold a `sync.Mutex` / `chan`.
- **State goroutine safety** in the doc comment of exported types. If nothing is written, the default is "UI goroutine only":
  ```go
  // Post schedules fn to run on the UI goroutine. It is safe to call from any goroutine.
  ```
- `-tags gowakudebug` checks which goroutine calls `SetState`. The check does not use the `runtime` goroutine ID; it compares a `goroutineToken`, held only by the UI goroutine, with `sync/atomic`.
- Do not call `time.Now()` directly in `core` / `motion`. Inject the `motion.Clock` interface, and use a fixed time in tests.

## 10. Tests

- `go test ./...` **passes with no GPU and no window**. Tests that need a GPU have `//go:build gpu` and live under `gpu/`.
- Table-driven tests are the default. Case names may be in Japanese (`t.Run("行頭禁則: 句点", ...)`, meaning "line-start kinsoku: full stop"; kinsoku is the set of JLReq line-break rules).
- Names are `Test<subject>_<situation>`: `TestReconcile_KeyedReorder`, `TestJLReq_LineStartProhibition`.
- **golden**: compare the text form of the DisplayList returned by `internal/testutil.Render(widget, size)` with `testdata/<name>.golden`. Update with `go test -update`. When a diff appears, explain in the PR whether it is intended.
- For Japanese typesetting, the golden is a table of "string + width → line breaks".
- Do not use `time.Sleep`. Inject a `Clock` for time.
- Helpers call `t.Helper()`. No assertion libraries. `if got != want { t.Errorf("got %v, want %v", got, want) }` is enough.
- Benchmarks are `Benchmark<subject>_<scale>`: `BenchmarkReconcile_10kNodes`. `b.ReportAllocs()` is required.
- No numeric coverage target. Instead, four areas cover their boundary values thoroughly: reconcile, Layout, each jlreq rule, and HCT.

## 11. Comments and documentation

- **Doc comments are in English**, because godoc is read for a library published on GitHub. The first sentence starts with the identifier name: `// Padding insets its child by the given Insets.`
- Comments inside the implementation are also in English. Design background that is better written in Japanese goes in `docs/ADR/`, referenced from code as `// See docs/ADR/0003-stencil-clip.md`.
- Comments say **why**, not what. Do not write what the code already says.
- TODOs carry an issue number, like `// TODO(#123): ruby annotation`. No owner names.
- Every exported identifier has a doc comment, no exceptions. The `revive` `exported` rule enforces it.
- Main public APIs (`Run`, `StatefulWidget`, `AnimatedContainer`, `Text`) have `Example*` tests. They appear in godoc.

## 12. File layout

- One concept per file. A widget is `widgets/control/button.go` + `widgets/control/button_test.go`. A RenderObject is `layout/padding.go`.
- Order within a file: package comment (omitted if it is in `doc.go`) → imports → constants → types → constructors → methods (exported → unexported) → helper functions.
- Consider splitting past 500 lines. Huge files like `command.go` are allowed only for generated code.
- Platform-specific files are split by **file name suffix**, not build tags: `window_windows.go`, `window_linux.go`. Tags are needed only for `//go:build gpu` on GPU tests and for `gowakudebug`.
- Shaders live in `gpu/<backend>/shaders/` with names that show role and language, like `sdf.frag.glsl` / `sdf.ps.hlsl`, and the compiled binary sits next to them with the same name + `.spv` / `.dxbc`. `go:embed` is in one place (`shaders.go`).

## 13. Git

- Branches: names that describe the content, like `fix-ime-caret` or `table-sort`. Only working code goes on main.
- Commit messages follow the Go project's style: `package: summary starting in lowercase`
  ```
  core: add keyed child reconciliation

  Match the children from both ends first, then look up the
  middle by key. See docs/ADR/0002-reconcile.md.
  ```
  For several packages, `core, layout: ...`; for everything, `all: ...`.
- Design decisions go in `docs/ADR/NNNN-<slug>.md`. Format: "Background / Options / Decision / Consequences". One decision per file. Include the date of the decision.
- One commit, one intent. Formatting-only changes go in a separate commit.

## 14. Forbidden (summary)

| Forbidden | Instead |
|------|----------|
| Side effects in `init()` | Explicit initialization from `Run` |
| Mutable package-level variables | Struct fields. Exceptions in §3.2 |
| `any` arguments and return values (other than `Key`) | Concrete types or generics |
| reflect that walks structs | Explicit code |
| `context.Context` | `Ticker` / `Dispose` |
| Functional options, method chains | Struct literals |
| Goroutines or `sync` in `core` / `layout` etc. | `app.Post` |
| `time.Now()` (`core` / `motion`) | `motion.Clock` |
| The `log` package, logging on hot paths | `slog.Debug` (initialization only) |
| `recover` inside the library | Let it propagate |
| `//nolint` without a reason, file-level nolint | Per line + reason |
| `unsafe` / `syscall` / `purego` outside `platform` / `gpu` | Keep them at the boundary |
| Raw `uintptr` handles passed to upper layers | `NativeHandle` |
| Unit suffixes like `WidthPx` | Types and context |
| Getters with a `Get` prefix, negative booleans | `X()`, `Enabled` |

## 15. Code example: a widget that follows the rules

```go
// widgets/basic/padding.go

package basic

import (
    "github.com/bankai-tensei/gowaku/core"
    "github.com/bankai-tensei/gowaku/layout"
)

// Padding insets its child by the given Insets.
// The zero value draws the child without any inset.
type Padding struct {
    Insets layout.Insets
    Child  core.Widget
}

// Key implements core.Widget. Padding is never keyed directly; wrap it with Keyed.
func (Padding) Key() core.Key { return nil }

// CreateRenderObject implements core.RenderWidget.
func (p Padding) CreateRenderObject() core.RenderObject {
    return &layout.RenderPadding{Insets: p.Insets}
}

// UpdateRenderObject implements core.RenderWidget.
func (p Padding) UpdateRenderObject(ro core.RenderObject) {
    rp := ro.(*layout.RenderPadding)
    if rp.Insets != p.Insets {
        rp.Insets = p.Insets
        rp.MarkNeedsLayout()
    }
}
```

```go
// layout/padding.go

package layout

import (
    "github.com/bankai-tensei/gowaku/core"
    "github.com/bankai-tensei/gowaku/geom"
    "github.com/bankai-tensei/gowaku/paint"
)

// RenderPadding lays out a single child inset by Insets.
type RenderPadding struct {
    core.RenderBase
    Insets Insets
    child  core.RenderObject
}

// Layout implements core.RenderObject.
func (r *RenderPadding) Layout(c Constraints) geom.Size {
    if r.child == nil {
        return c.Constrain(r.Insets.Size())
    }
    inner := c.Deflate(r.Insets)
    sz := r.child.Layout(inner)
    r.child.SetOffset(geom.Offset{X: r.Insets.Left, Y: r.Insets.Top})
    return c.Constrain(sz.Add(r.Insets.Size()))
}

// Paint implements core.RenderObject.
func (r *RenderPadding) Paint(cv *paint.Canvas, off geom.Offset) {
    if r.child != nil {
        r.child.Paint(cv, off.Add(r.child.Offset()))
    }
}
```

Key points: the widget is a value type and its zero value works; the RenderObject has the `Render` prefix and embeds `RenderBase`; on update, `MarkNeedsLayout` is called only when something changed; `Paint` does not allocate; every exported identifier has a doc comment.
