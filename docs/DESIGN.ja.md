# gowaku デザイン仕様

[English](DESIGN.md)

`widgets` と `theme` はこの仕様に沿って実装している（ADR 0011）。見本は `examples/gallery` と[ウィジェットカタログ](catalog/ja/README.md)で確認できる。未実装なのは連続曲率の角（§4）だけである。

---

## 1. 立ち位置

gowaku は独自の既定デザインを備えている。名前はまだない。

ひとことで言えば、**和文のための静かなデスクトップツール**である。Apple の美学からは「引き算」と「質感の作り方」を借り、文字組は日本語を起点に組み立てる。

### Apple から借りるもの

| 借りるもの | gowaku での形 |
|---|---|
| 色を使わない勇気 | 面は中立色にする。色はアクセントの 1 色だけで、操作できる要素と現在位置にしか使わない |
| 髪の毛のように細い線 | 区切りには影ではなく、1px の半透明の線を使う |
| インセットのグループ | 設定やフォームは角丸のカードの中に行を並べ、区切り線は左端まで伸ばさない |
| 2 層の影 | 接地を表す細い影と、広く淡い影を重ねる。1 枚の濃いぼかしは使わない |
| 物の手触り | 押すと 0.97 倍に沈む。スイッチのつまみは影の付いた白い玉にする。動きはスプリングで表す |
| 太さで階層を作る | サイズより先に、ウェイトと色の濃さで差をつける |
| フォーカスリング | キーボードフォーカスの位置だけは、外側の柔らかいリングではっきり示す |

### 借りないもの

- San Francisco（SF）フォント。ライセンスの面でも使えない。
- 信号機のボタン、macOS のタイトルバー、アイコン、Liquid Glass 風の演出など、Apple 製に見せるための要素。既定のタイトルバーは OS 標準である（gowaku が描くタイトルバーは opt-in、ADR 0048）。
- ブラーを前提にした質感。既定のデザインは不透明な面だけで成り立つようにしている。ブラーは opt-in で使える（`BackdropFilter`、`Dialog{Glass: true}`。背景を σ 20 でぼかし、その上に `Glass` の面を重ねる。透け具合は控えめにし、文字の読みやすさを優先する。ADR 0044）。

### gowaku 独自のもの

- **色のない面**: 地の色は、無彩色に見える `f5f5f7` にする。ベージュやクリーム色には決してしない。AI が作った画面の典型に見えてしまうからである。
- **和文基準の文字組**: サイズと行送りは、和文の読みやすさから決める（§3）。
- **藍のアクセント**: 既定の色は青みの強い藍で、任意の色に差し替えられる。

## 2. 色

HCT はそのまま使うが、Material の 36 色のロールは採用せず、用途で名付けた 15 色ほどに絞る。開発者が選ぶのはアクセントの 1 色だけで、残りの色はそこから導かれる。

```go
Theme: theme.FromAccent(geom.Hex(0x2f5fd0))   // 省略すると藍
```

| トークン | ライト | ダーク | 用途 |
|---|---|---|---|
| `Canvas` | N 96.5 | N 10 | ウィンドウの地 |
| `Sidebar` | N 93 | N 14 | サイドバー |
| `Card` | 白 | N 15 | グループ、カード |
| `Raised` | 白 | N 20 | ダイアログ、メニュー |
| `Glass` | 白 85% | N 20 の 78% | ガラス風のダイアログ（`Dialog{Glass: true}`）。スクリムの下にどの面があっても Ink2 が 4.5:1 を保つ（ADR 0044） |
| `Field` | 白 | N 19 | 入力欄 |
| `Control` | 白 | 白 14% | 通常のボタン |
| `Ink` | N 13 | N 95 | 本文 |
| `Ink2` | N 42 | N 72 | 補足。どの面の上でも 4.5:1 以上（ADR 0041） |
| `Ink3` | N 62 | N 50 | プレースホルダー、無効、装飾。あえて 4.5:1 未満にしているので、時刻や件数のように情報を伝える文字には使わず、`Ink2` を使う |
| `Hair` | 黒 9% | 白 10% | 線 |
| `Fill` | 黒 5% | 白 8% | 控えめな塗り、セグメントの地 |
| `FillStrong` | 黒 9% | 白 14% | オフのスイッチ、トラック |
| `Accent` | A 45 | A 45 | 塗り。上に白い文字を載せる。ホバー中も 4.5:1 を保つ（ADR 0123） |
| `AccentInk` | A 41 | A 74 | 文字、線、フォーカスリング |
| `AccentTint` | A 45 の 12% | A 62 の 22% | 選択中の行。`Ink` はこの上で読めるが、`Ink2`、`AccentInk`、`Danger`、`Success` は 4.5:1 を下回るので、この上に置くものは `Colors.OnTint` の色を使う。それぞれを、読める最小の量だけ `Ink` に寄せた色である（ADR 0138） |
| `Danger` | 赤 41 | 赤 72 | 破壊的な操作、エラー |
| `Success` | 緑 41 | 緑 72 | 完了や、進行中の休憩など、前向きな状態 |
| `Warning` | 琥珀 70 | 琥珀 76 | 問題になる前に注意を促すもの。`InfoBar` の `SeverityWarning` のアイコンと枠など。アイコン、点、枠線、薄い塗りに使い、文字には使わない（ADR 0124） |

N は中立色のパレット（色相 235、彩度 3.5）、赤・緑・琥珀は色相 25・145・60 のパレット、A はアクセントの色相で彩度を max(seed, 40) にしたパレットを表す。数字はトーンである。

### 色を決めた理由

- **中立色の彩度を 0 に近づけてはいけない**。HCT の無彩色は色相 209・彩度 2.8 付近にあり、彩度を 0.8 にするとかえってピンクに振れる。
- **地の色は 4 つの候補を描き比べて決めた**。暖かみのある `f6f5f4` はベージュに見えるので却下した。完全なグレーの `f5f5f5` は白いカードと並べると少し濁って見え、`f4f5f9` まで青くすると SaaS の管理画面のようになる。色相 265 は紫に寄る。`f5f5f7` なら色を感じさせない。
- **アクセントは 1 色では足りない**。ダークで文字として読める明るさの色を塗りに使うと、上に載せた白い文字が読めなくなる。そこで塗り用と文字用に分けた。
- シードを緑や橙に替えても破綻しない。面が中立色なので、シードの影響が及ぶのは操作部品だけだからである。

## 3. 文字

既定の本文は 13px である。Windows の Yu Gothic はウェイト 400 では細すぎるので、ラベルには 500 を使う。行の高さはピクセル単位で決め、すべて偶数にしている。下に積み重ねる要素がグリッドからずれないようにするためである。

| 役割 | サイズ | ウェイト | 行送り |
|---|---|---|---|
| `LargeTitle` | 24 | 600 | 32 |
| `Title` | 16 | 600 | 24 |
| `Headline` | 13 | 600 | 20 |
| `Body` | 13 | 400 | 20 |
| `Control` | 13 | 500 | 20 |
| `Caption` | 12 | 400 | 18 |
| `Section` | 12 | 500 | 18 |
| `Reading` | 15 | 400 | 26 |
| `Code` | 13 | 400 | 20 |

行送りは和文を基準にした固定値とし、文字サイズは 9 つの役割に絞る。

書体を持つ役割は `Code` だけである。ソースコード、ログ、コピーして使う値のための等幅の書体で、`editor.Editor` と markdown のコードの既定になる。書体は各 OS が先頭から順に探して最初に見つかったものを使う一覧であり、Windows では Cascadia Mono と Consolas、macOS では SF Mono と Menlo、Linux では DejaVu Sans Mono、Noto Sans Mono、Liberation Mono が当たる（`theme.MonoFamilies`）。コードの中の日本語は和文の書体に落ちる。

## 4. 形と寸法

寸法には偶数だけからなるスケールを使う。偶数なら、100%、150%、200% のどの倍率でも物理ピクセルが整数になる。値は `theme.Space2` 〜 `theme.Space28` として定義しており、コードに数値を直接書かない。

| | 値 |
|---|---|
| 角丸 | 小 4（チェック）/ 標準 8（ボタン、入力欄、行）/ 大 12（グループ）/ 特大 16（ダイアログ） |
| 操作部品の高さ | 小 24 / **標準 30**（ボタン、入力欄、セグメント、サイドバーの行）/ 大 38 |
| グループの行の高さ | 44 以上 |
| `Detail` のあるサイドバーの行の高さ | 46。2 行（20 と 18）と上下の 4 |
| 余白 | 2, 4, 6, 8, 10, 12, 16, 20, 24, 28 |
| 余白の使い分け | ページ 28、セクション間 24、カード内の左右 16、部品間 8、見出しと本文の間 6 |
| サイドバーの幅 | 208。区切り線を含む（`Sidebar.Width`） |

### 物理ピクセルへのスナップ

`render` は角丸矩形を物理ピクセルに揃える。同じ長さは位置によらず同じ物理長になるので、線の太さが揃う。2 物理ピクセル未満の端数は切り捨てる（150% での 1px は 1 物理ピクセルになる）。

スナップしないのは、拡大縮小中の図形（1 ピクセル未満の単位で動く必要がある）と、円（つまみが階段状に動かないようにするため）である。ただし枠線の太さだけは、拡大縮小中でも揃える。

**連続曲率の角**（Apple の角丸の要）はまだ実装していない。現在の SDF は円弧であり、半径 8 程度なら差は小さい。シェーダーの `roundedBoxDistance` の角を p ノルムに変えれば、`Instance` の形式を変えずに導入できると見込んでいるが、検証はしていない。第 2 段階で試す予定である。

## 5. 部品

**ボタン** は 3 段階に破壊的操作用を加えた 4 種類である。`Button{Label, Style}` の 1 つにまとめており、ゼロ値が通常のボタンになる。

| `Style` | 見た目 | 使いどころ |
|---|---|---|
| `ButtonNormal`（ゼロ値） | 白地 + 線 + 接地の影 | 既定 |
| `ButtonPrimary` | アクセントの塗り | 1 画面に 1 つだけ |
| `ButtonQuiet` | 地なし、アクセントの文字 | 補助的な操作 |
| `ButtonDanger` | 地なし、赤の文字 | 削除 |

地のないボタンは左右の余白を 8 にする。16 のままだと、隣の要素との間隔が広く見えるからである。

**入力欄**: ラベルは上（`field.Input.Label`）か行の左（`GroupRow`）に置き、フローティングラベルは使わない。フォーカスすると線がアクセント色になり、外側に 3px の淡いリングが表示される。リングは `layout.RenderRing` が線として描くので、内側の塗りには影響しない。

**スイッチ**: 38×22 で、18 の白い玉に 2 層の影を付ける。押すと玉が横に伸びる。**スライダー**: トラックは 4、白い玉は 18 で、ポインタが乗ると少し膨らむ。**チェック**: 16、角丸 4.5。

**新しく加えた部品**

- `SegmentedControl`: 外観の切り替えのような 2〜4 択に使う。選択中を示す板がスプリングで滑る。
- `Group` と `GroupRow`: インセットのリスト。左に名前、右に操作を置く。
- `Sidebar` と `SidebarItem`: 選択中の項目は `AccentTint` の面で示し、その中身は `Colors.OnTint` の色で描く。`Detail` は `Caption` と `Ink2` の 2 行目で、1 行に切る。
- `Steps`: 手順の流れの現在地。直径 24 の丸と名前を太さ 2 の線でつなぐ。済んだ手順と現在の手順は `Accent` の丸、先の手順は `Fill` の丸と `Ink2` の名前で、現在の手順の名前だけを太字にする。

**ダイアログ**: 幅 340、余白 24、角丸 16、面は `Raised` で、左揃え、影は 2 層。スクリムは黒 25%。`Glass: true` のときは面が `Glass` になり、背後を σ 20 でぼかす。

### 状態の表現はどの部品でも共通

| 状態 | 表し方 |
|---|---|
| hover | 地か線が 80ms で変化する。Switch、Checkbox、Segmented、Sidebar、Slider、Input、Button のすべてが対象 |
| press | スプリングで沈む、伸びる、濃くなる。Input 以外のすべてが対象 |
| focus | 3px の淡いリング。`Pressable` で作る独自の部品も、`PressState.Focused` のときに同じリングを表示する |
| disabled | `Fill`、`Ink3` のトークンで描画する。全体を半透明にはしない |

この約束は `widgets` のテスト（`TestHover_MovesEveryControl`、`TestPress_MovesEveryControl`、`TestDisabled_UsesTokensNotOpacity`、`TestControls_ShareOneHeight`、`TestStacking_StaysOnTheGrid`）で守っている。

## 6. 影

光源は真上にあるものとし、接地の影と広い影の 2 層で表す。

| 段 | 近い影 | 遠い影 | 使いどころ |
|---|---|---|---|
| 1 | y 0.5 / blur 1 / 5% | なし | 通常のボタン |
| 2 | y 0.5 / blur 1 / 8% | y 1 / blur 2–3 / 16% | セグメントの板、スイッチの玉 |
| 3 | y 2 / blur 4 / 8% | y 24 / blur 48 / 16% | ダイアログ |

ダークでは影が目立ちにくいので、面の明るさ（`Card` → `Raised`）で段差を表し、線を加える。

## 7. 動き

リップルは使わず、**スプリングで手触りを表現する**ことを gowaku の特徴とする。`motion.SpringSimulation` がすでにあるので、追加の仕組みはほとんど要らない。

| 動き | 値 |
|---|---|
| hover | 80ms。線形 |
| 押す | **背景だけ**が 0.97 倍に沈み、塗りが変わる。スプリング（素早く、跳ね返らない） |
| 離す | 同じスプリングで戻る。速度を引き継ぐので、連打しても飛ばない |
| スイッチ、セグメント | スプリング（わずかに跳ね返る） |
| ダイアログ | 0.96 → 1 の拡大とフェード。280ms の `motion.SpringOut`。閉じるときは 120ms で素早く |
| 色の切り替え | 150ms |

押したときの動きは、`Decoration.Sink` で背景だけに適用する。文字ごと縮めると、グリフのピクセルサイズが量子化されるため、0.97 倍付近で文字の大きさが飛ぶおそれがある。文字はその場にとどめる。

## 8. API への影響

- 「簡単におしゃれ」とは、**何も指定しなくても見た目が整う**ことを指す。`Button{Label: "保存"}` と書くだけで完成した見た目になるようにする。
- `theme` は `Colors`、8 役割の `TextTheme`、`Radii`、`Lift` からなり、HCT、`TonalPalette`、`Set`、`ThemeMode`、OS への追従を備える。
- ボタンは `Button`、入力欄は `field.Input` の 1 種類ずつにまとめる。
