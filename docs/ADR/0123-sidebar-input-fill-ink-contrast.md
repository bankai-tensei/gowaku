# 0123: Sidebar の幅・スクロール・Header/Footer、ラベル付き複数行 Input の伸び方、文字色のコントラストの不足

決定日: 2026-11-16

状態: 採用

## 背景

初めて使う人に gowaku を試してもらったところ、次の 4 つが見つかった。

1. **`collection.Sidebar`：** 幅 208 で固定、高さいっぱいの背景と区切り線を自分で描き、スクロールしない。項目が多いか窓が低いと、下の項目が切れて見えなくなる。godoc にはどれも書いていなかった。上に検索欄、下にボタンを置きたい人は、`SidebarItem` から作り直していた。
2. **`field.Input`：** `Multiline` で `Label` 付きの欄は、`Expanded` に入れても高さを埋めない。ラベルと欄を `Column{Size: MainMin}` で包んでいたため、欄には高さの制約が届かず、文字の高さのままだった。ラベルが無ければ埋まる。
3. **文字色：** `ButtonDanger` の赤い文字が、Sidebar の面の上で gowakutest の警告に掛かった。計算上は 4.501:1 だが、画素から測ると 4.5 をわずかに下回り、警告は「4.50:1 … below 4.5:1」と矛盾して見える文で出ていた。README のカウンターも、ダークでポインターが主要ボタンの上にあると、白い文字が 4.42:1 になって警告に掛かった（ホバーで Accent に白を 5% 混ぜるため）。ライブラリの既定が、自分の検査に落ちていた。
4. **列挙型の godoc：** `go doc .../widgets/control` は `const ButtonNormal ButtonStyle = iota ...` としか見せず、値の名前が分からない。`ButtonDestructive` と書いた人がいた。

ADR 0041 は、Canvas、Sidebar、Card、Raised、Field と、それぞれにホバーの `Fill` を重ねた面の上で `Ink` と `Ink2` が 4.5:1 を満たすことを決め、テストで固定した。しかし `AccentInk`、`Danger`、`Success` と、Accent の上の `OnAccent` は、その対象に入っていなかった。

## 選択肢

### Sidebar

- (a) Sidebar はそのままにして、godoc に制限を書く。検索欄やボタンが欲しい人は、相変わらず作り直すことになる。
- (b) `Width`、行のスクロール、`Header` と `Footer` を足す。

### ラベル付きの複数行 Input

- (a) 制約を見て、高さが有限なら必ず埋める。`Center` や `Stack` の中でも窓いっぱいに伸びてしまい、ラベルの無い欄（最小の高さだけを守る）とも振る舞いが変わる。
- (b) 与えられた最小の高さから、ラベルとすき間の分を引いて欄に渡す。`Expanded` や `SizedBox` は高さをきっちり決めるので、欄はそれを埋める。`Column` の中のように高さが決まらなければ、これまでどおり文字に合わせて伸びる。ラベルの無い欄とまったく同じ振る舞いになる。

### 文字色

- (a) gowakutest の判定に余裕を持たせる。既定の色はそのまま。利用者の色の判定まで甘くなる。
- (b) 色の濃さを変えて、すべての面で 4.5:1 を満たすようにする。

## 決定

Sidebar は (b)、Input は (b)、文字色は (b) を採る。

### 1. Sidebar

- **`Width float32`：** ゼロなら設計どおりの 208。右端の区切り線（1）を含む幅にした（以前は 208 + 1 だった）。外側を `SizedBox{Width}` にしたので、`control.SplitPane` のペインのように親が幅を決めると、そちらが勝ち、パネルはその幅を埋める。
- **スクロール：** 行だけを `basic.Scroll` に入れた。スクロールバーは、Scroll と同じく、はみ出したときだけ出る。タイトル、Header、Footer は動かない。
  - 行のフォーカスリング（外側 3px）がスクロールの切り抜きで欠けないよう、左右の余白（10）と上の 4 をスクロールの内側に入れた。タイトルの下の余白を 8 から 6 にして、タイトルから最初の行までの距離（10）は変えていない。
- **`Header core.Widget`：** タイトルの下、行の上。検索欄などを置く。
- **`Footer core.Widget`：** 下端に固定する。ボタンなどを置く。
- **アクセシビリティ：** リストは行だけを持つ。名前はタイトルで、タイトルの文字は読ませない（ADR 0065 と同じく、一度だけ読まれる）。Header と Footer はリストの外にある。
- **godoc：** 背景と区切り線を自分で描くこと、`CrossStretch` の `Row` の先頭に置くこと、高さが有限でなければならないこと、幅、スクロール、Header と Footer を書いた。

### 2. ラベル付きの複数行 Input

- 複数行でラベルがある欄は、`Column` の代わりに小さなレイアウト（`labeledLayout`）で並べる。ラベルを上に置き、残りの最小と最大の高さを欄に渡す。1 行の欄は、高さを与えられても 1 行の高さのままでよいので、これまでどおり `Column` を使う。
- godoc に、高さが決まらなければ伸び、決まれば埋めることと、`editor.Editor` との使い分けを書いた。Input はフォームの欄や短いメモ、Editor は行番号、装飾、検索バーがあり、見えている行だけを組む長い文書向け。Editor の godoc にも逆向きの一文を足した。
- 縦書きの欄では、ラベル付きでも、与えられた高さを使うようになった（以前はラベルがあると既定の長さ 240 だった）。ラベルの無い縦書きの欄と同じになる。

### 3. 文字色

濃さ（トーン）を次のように変えた。濃さは L* なので、コントラストは色相にほとんどよらない。

| 色 | ライト | ダーク |
|---|---|---|
| `Accent` | 45（変更なし） | 48 → **45** |
| `AccentInk` | 42 → **41** | 74（変更なし） |
| `Danger` | 45 → **41** | 68 → **72** |
| `Success` | 45 → **41** | 72（変更なし） |

- 対象の面は ADR 0041 と同じ。Canvas、Sidebar、Card、Raised、Field と、それぞれに `Fill` を重ねたもの。`FillStrong` は押下中やトラックの色で、その上に文字を長く置かないので含めない。
- いちばん厳しいのは、ライトでは Fill を重ねた Sidebar（Danger 45 は 4.04:1）、ダークでは Fill を重ねた Raised（Danger 68 は 4.16:1）。ライトの 41 は 9 つのアクセントの最悪で 4.68:1、ダークの 72 は 4.71:1 になる。画素で測ると 0.01〜0.02 ほど下がるので、ぎりぎりの値は選ばなかった。
- `AccentInk` のライトの 42 は、Fill を重ねた Sidebar の上で 4.496〜4.499:1 だった。`Ink2`（42、4.53:1）より 0.03 ほど低い。41 にした。
- ダークの `Accent` 48 は、白い文字が静止時 4.80:1、ホバー中（白 5%）4.37:1 だった。45 にすると 5.34:1 と 4.87:1 になり、ライトと同じ濃さになる。押下中（白 11%）は 4.31:1 で、一瞬なので対象にしない。暗い面の上での塗りの見え方は、48 と 45 でほとんど変わらない。
- **テスト：** `TestColors_InkReadsOnEverySurface` を広げた。9 つのアクセント、ライトとダークで、`Ink`、`Ink2`、`AccentInk`、`Danger`、`Success` がすべての面で 4.5:1 以上、`OnAccent` が Accent の上と、ホバーの白を混ぜた Accent の上で 4.5:1 以上、ライトの `Success` が白い文字を載せられることを確かめる。`Ink3` は薄いままであることも確かめる。gowakutest には、4 つのアクセント、ライトとダーク、5 つの面に全部の文字色と 4 種類のボタンを置いて警告が出ないこと、README のカウンターを 9 回押してポインターを載せたままでも警告が出ないことを確かめるテストを足した。
- **警告の文：** 比を小数 2 桁に切り捨てて表示する。4.499 は 4.49:1 と出て、「4.50:1 … below 4.5:1」とは出ない。`Amount` には切り捨てない値が入る。

### 4. 列挙型の godoc

`widgets/*` の公開の列挙型すべて（`ButtonStyle`、`ButtonSize`、`InfoSeverity`、`SkeletonShape`、`SparklineKind`、`SplitCollapse`、`SortOrder`、`TableSelectMode`、`CellKind`、`CellTone`、`TreeDrop`、`Underline`、`HourCycle`、`ViewerBoundary`、`DockZone`、`SheetEdge`）の型の doc に、「It is ButtonNormal (the zero value), ButtonPrimary, ButtonQuiet or ButtonDanger.」のように値の名前を並べた。`go doc control.ButtonStyle` で名前が見える。

## 結果

- gallery のサイドバーは、窓が低いと行がスクロールするようになった。幅が 1 狭くなり、右側の内容が 1 左に寄る。
- ピクセルの golden は、色の変更（ライトの AccentInk・Danger・Success、ダークの Accent・Danger）、サイドバーの 1 の移動、縦書きのルビの欄の高さで更新した。差分の画像は確かめた。
- カタログの Sidebar の図に Header（検索欄）と Footer（ボタン）を、Input の図に `Expanded` で高さを埋める複数行の欄を加えた。
