# 0044: 描画拡張（13a: 任意 Affine、グラデーション、ブレンドモード、ブラー）

決定日: 2026-11-09

状態: 採用

## 背景

描画の拡張（Phase 13）。検討して次を決めた。

- **13a と 13b に分け、2 回レビューする。** 13a は任意 Affine、グラデーションの拡張、ブレンドモード、ブラー（このADR）。13b はカスタムシェーダーと `gowaku-shader`、SVG、動画像、ミップマップ。
- **ガラス風 Dialog の 120fps：** 完了条件は RTX 3050 Ti で、D3D11 と Vulkan の両方。Iris Xe でも測って記録するが、完了条件にはしない。
- **ガラスは opt-in にする。** `BackdropFilter` と `Dialog{Glass: true}` を用意する。既定の見た目は変えない（当初の計画の互換方針）。
- **ブレンドモードは当初の計画どおり全部。** Porter-Duff の 12 種、分離可能なもの、分離不可能なもの。同じ式を `gpu/soft` にも入れ、golden で比べる。
- **Affine は、描画・当たり判定・文字まで対応する。** 回した文字は、アトラスのグリフをバイリニアで描く。Semantics の矩形は外接矩形にする。

## 決定

### 1. 任意 Affine

- `geom.Affine` を足す。2×3 の行列（`A, B, C, D, E, F`、`x' = A·x + C·y + E`、`y' = B·x + D·y + F`）。ゼロ値は恒等変換とみなす（`IsIdentity`）。
- `paint.Canvas` に `Transform(geom.Affine)` を足す。`Save` / `Restore` で戻る。平行移動と拡大だけの変換は、今までの `Origin` と `Scale` の速い道を使う。回転や歪みを含むときだけ、`Op.Transform` に積む。
- `gpu.Instance` に `Transform [6]float32` を足す。頂点シェーダーが、局所座標の四角形を画面座標に移す。ピクセルシェーダーは局所座標のまま SDF を評価する。縁の幅は `fwidth` で 1 物理ピクセルにする。恒等変換のときは今までと同じ式を通り、同じ絵になる。
- **文字：** 回転や歪みがあるとき、グリフをアトラスから `Load` ではなくバイリニアのサンプラーで読む。グリフは今までどおり、画面の倍率でラスタライズしたものを使う。
- **パス：** CPU でフラット化した頂点に変換を掛けて、ステンシルに描く。覆いの四角形は、変換後の外接矩形にする。
- **クリップ：** 回った矩形のクリップは、パスのクリップ（ステンシル）にする。
- **レイヤー：** 回ったレイヤーは、軸に沿って描いた画像を変換して描く。
- **当たり判定：** core に `Transformer` を足す（`ParentToLocal`、`LocalToParent`）。`core.GlobalToLocal` と `core.LocalToGlobal` は、そこで変換をたどる。ポインターの局所座標、IME のキャレットの矩形、Semantics の矩形（外接矩形）がこれを通る。
- **ウィジェット：** `Transform{Transform, Origin, Child}`。`Rotate`、`Skew` などの補助関数も用意する。今の `Scale` と `Translate` は、そのまま速い道として残す。

段 1 を実装したときに決めた細部（2026-11-09）：

- **`Transformer` はメソッド 1 つ：** `ChildTransform() geom.Affine`（子の座標を自分の座標へ移す変換）。`ParentToLocal` と `LocalToParent` の 2 つにすると、片方だけ直して食い違う心配がある。逆向きは `Invert` で作る。変換の無い木では、`GlobalToLocal` と `LocalToGlobal` は今までの `GlobalOffset` の足し算をそのまま使い、結果はビットまで同じ。
- **ゼロ値の `Affine`：** `IsIdentity` は真を返し、`Canvas.Transform` と `Transform` ウィジェットは何もしない。`Mul` や `Apply` はただの計算のままにする（ゼロ値を恒等とみなすと、合成の式が壊れる）。`gpu.Instance.Transform` も全部 0 を「無し」とする。
- **`Op.Transform` の意味：** 今までの `Origin` と `Scale` で置いた座標を、画面へ移す変換。`Scale` を残すので、拡大してから回した文字も、拡大した大きさでラスタライズされる。
- **縁の幅は `fwidth` でなく変換から出す：** 距離の勾配（SDF の法線）と逆行列から、1 物理ピクセルあたりの距離を計算する。`fwidth` と同じ量だが、2×2 のピクセルの組み方に依らないので、D3D11、Vulkan、`gpu/soft` が同じ値になる。
- **回した文字のバイリニアはサンプラーを使わない：** アトラスのグリフの間に隙間が無く、追い出したグリフのピクセルも残るので、サンプラーだと隣が滲む。`Load` で 4 テクセルを読み、グリフの外は 0 として自前で補間する。四角形はグリフの外に 1 テクセル広げる。
- **回した画像とレイヤー：** 四角形を 1 物理ピクセル広げ、矩形の SDF で縁を滑らかにする。広げた分は端のテクセルを繰り返す。
- **回したパスの覆い：** 外接矩形ではなく、局所座標の四角形に変換を付けて描く。覆いの中でグラデーションを局所座標で評価できる。
- **残した穴：** ステンシルが要るためにページに載らない（inline の）レイヤーを回すと、レイヤーの中の矩形のクリップ（シザー）は、回した矩形の外接矩形になる。カラー絵文字は回すとサンプラーで読むので、端に隣のグリフが少し滲みうる。スクロールの量は回さずに渡す。

### 2. グラデーション

- ~~`MaxGradientStops` を 16 にする。~~ 実装で変えた（下の細部を参照）。`MaxGradientStops` は 4 のまま、5 ストップ以上は `Gradient.MoreStops` で渡す。
- 4 ストップまでは、今までどおりインスタンスで運ぶ。5 ストップ以上は、256 テクセル幅の色の帯（ランプ）を 1 行ずつ詰めたテクスチャで渡す。内容が同じランプは使い回す。
- `GradientSweep` を足す。`Start` を中心に、`End` の向きを 0 として時計回りに一周する。
- `Gradient.Transform`（`geom.Affine`）を足す。楕円の放射状のグラデーションなどに使う。

段 2 を実装したときに決めた細部（2026-11-09）：

- **`MaxGradientStops` は 4 のまま、`MoreStops` を足す：** 最初は配列を 16 にしたが、`Op` が `Gradient` を値で持つので `Op` が 240 バイト大きくなり、記録のホットパス（`BenchmarkCanvas_10kRects`）が約 0.77ms から約 1.15ms に遅くなった。グラデーションを使わない描画にもかかる費用なので、やめた。代わりに `Gradient.MoreStops *[]GradientStop` を足す。中身があれば全部のストップ（長さは自由）で、`Stops` / `StopCount` / `StartColor` / `EndColor` は見ない。
  - **ポインターにした理由：** スライスを持つと `Gradient` が比較できなくなる。v1 は `==` で比べられることを約束していて（ADR 0032、`layout.Decoration.Equal`）、利用者のコードが壊れる。ポインターなら比較はでき、指す先が違えば別物とみなす（中身が同じでも再描画が 1 回増えるだけ）。
  - **`Canvas` が写す：** 不透明度をかけ、オフセットを前に揃えるには、利用者のスライスを書き換えずに済む写しが要る。`Canvas` が自前の領域（`Reset` で使い回す）に写し、`Op` はその写しを指す。だから利用者は描いた後にスライスを変えてよい（`Op.Glyphs` のような寿命の決まりは要らない）。領域が伸びても、前の写しは古い配列に残るので、指す先は壊れない。アロケーションは領域が伸びきれば 0。
  - `Op` は HEAD の 328 バイトから、段 1 の `Transform`（24）、`Gradient.Transform`（24）、`MoreStops`（8）で 384 バイト。

- **ランプのテクスチャ：** RGBA8（premultiplied）で 256×256。1 行が 1 つのランプで、テクセル i は i/255 の位置の色。焼く式は `gpu.FillRamp` にまとめ、シェーダーの `ramp` と同じ順の `lerp` を使う。だから 4 ストップを焼いた行は、インスタンスで運んだときとテクセルの上で一致する。
- **行の持ち方：** `render.Resources` が持つ。ストップのビット列の FNV ハッシュで行を引き（float のまま map の鍵にすると 1 つずつハッシュされて遅い）、行ごとに持つストップの写しと比べて衝突を見分ける。直前に渡した行とはハッシュの前に比べる。行が足りなくなったら、今のフレームで使っていない行のうち一番古いものを追い出す（グリフのアトラスと同じ）。1 フレームで 256 を超えたら、その先は最初と最後と間の 2 つ、計 4 ストップに落とす。`Resources` 無しで `Encode` したときも同じ。
- **インスタンス：** `GradientMode` に `GradientRamp`（16）を足して印にする。行の番号は `StopOffsets[0]` に入れる。ランプのときは色とほかのオフセットを使わないので、新しいフィールドは要らない。テクスチャは `DrawCall` ではなく `Batch.Ramps` に持たせる。1 つの `Resources` に 1 枚しかなく、描画コールの束ね方を変えずに済む。D3D11 は t2、Vulkan は set 3（set 1・2 と同じレイアウト）。
- **ランプは `Load` で読む：** 隣の 2 テクセルを読み、自前で `lerp` する。サンプラーの重みは 8 ビットに丸められることがあり、バックエンドごとに違いうる。行の外を読むことも無い。端より先は端の色が続く。
- **差：** ストップがテクセルの上にある 4 ストップは、インスタンスで運んだ場合とシェーダーの出力が 1 以内（`gpu/soft` のテスト）。テクセルの間にあるストップは、そこで折れ線が 1 テクセル分丸まる。硬い境目も 1/255 の幅に広がる（4 ストップまでの硬い境目は今までどおり鋭い）。
- **`GradientSweep`：** `t = atan2(axis × p, axis · p) / 2π`、負なら 1 を足す。y が下向きなので時計回り。0 と 1 の継ぎ目は、ほかの硬い境目と同じく滑らかにしない。オフセットの扱いは線形と同じ。
- **`Gradient.Transform`：** SVG の `gradientTransform` と同じく、グラデーションの座標を図形の座標へ移す。`Canvas` は `Start` / `End` と同じく配置（P）で包み、`P·T·P⁻¹` にする。インスタンスには逆行列の線形部分を `GradientMatrix [4]float32` として持たせ（16 バイト増えて 200 バイト）、`GradientStart` には変換後の始点、`GradientEnd - GradientStart` にはグラデーションの座標での軸を入れる。これなら平行移動だけのレイヤーの合成（`appendMoved`）は今までどおり `GradientStart` / `GradientEnd` をずらすだけで済む。図形の `Transform` とは独立で、グラデーションは図形の局所座標で評価される。潰れた（逆行列の無い）変換は無視する。
- **文字のグラデーション：** 今もグリフはグラデーションを塗らないので、対象外にした。
- **費用：** このマシンで、HEAD（段 1 の前）と比べて `BenchmarkCanvas_10kRects` は約 0.77ms から約 0.83ms（`Op` が 56 バイト増えた分）。`Encode` はインスタンスが 160 から 200 バイトになったが、インスタンスを `b.Instances` の中で直接組むようにして値のコピーを 2 回減らしたので、`BenchmarkEncode_10kRects` は約 0.72ms から約 0.60ms になった。16 ストップの `Encode`（1 万個、同じランプ）は約 1.0ms。どれもアロケーション 0。

### 3. ブレンドモード

`paint.BlendMode` に全部を足す。実装は 3 段に分ける。

1. **固定機能のブレンドで書けるもの：** Clear、Src、Dst、SrcOver、DstOver、SrcIn、DstIn、SrcOut、DstOut、SrcAtop、DstAtop、Xor、Plus、Screen、Modulate。パイプラインのブレンド状態を変えるだけで済む。premultiplied のまま、カバレッジは src に掛ける。この結果、形の外側は変えない（「形に限るブレンド」）。
2. **下地を読むもの**（分離可能な Multiply、Overlay、Darken、Lighten、ColorDodge、ColorBurn、HardLight、SoftLight、Difference、Exclusion と、分離不可能な Hue、Saturation、Color、Luminosity）：その描画の外接矩形だけ、今の描画先をスクラッチのテクスチャに写す。写した下地と描くものから、シェーダーが式で色を出す。式は W3C の Compositing and Blending Level 1 に合わせる。
3. **部分木ごとのブレンド：** `Blend{Mode, Child}` ウィジェット。子をオフスクリーンに描いてから、上の 2 で合成する。

`DrawCall.Blend` を足し、バックエンドはブレンド状態ごとにパイプラインを持つ。2 の道は `DrawKind` の `DrawBlendRead` として、レンダーパスを一度区切って写す。

段 3 を実装したときに決めた細部（2026-11-09）：

- **モードの並び：** `paint.BlendMode` は SrcOver（ゼロ値）、Porter-Duff の Clear から Modulate、分離可能な Multiply から Exclusion、分離不可能な Hue から Luminosity の 29 個。`gpu.BlendMode` は同じ値の写しで、render はそのまま渡す（数が違えばコンパイルが止まる）。名前は CSS の書き方（`color-dodge`）。ルートにも `BlendMode` と `BlendMultiply` などを置いた。
- **`Op` は大きくしない：** `Op.Blend` は `Kind` の隣の詰め物の 1 バイトに入る。`unsafe.Sizeof(paint.Op{})` は段 2 のあとと同じ 384 バイト（HEAD は 328）。`Canvas` の状態にも 1 バイト足した（`PushBlend`、詰め物に入る）。
- **形に限る、の作り方：** ピクセルシェーダーは図形ごとに、縁のカバレッジを掛けた色と、カバレッジそのものを分けて出す（`shade`）。固定機能のモードは出力の形を変える。Clear は `(0,0,0,cov)` を ZERO / INV_SRC_ALPHA で、DstIn と Modulate は `cov - c` を ZERO / INV_SRC_ALPHA・INV_SRC_COLOR で合成する。こうすると縁ではカバレッジの割合で下地と結果の間をとり、形の外は変わらない。DstOver、DstOut、SrcAtop、Xor、Plus、Screen は色をそのまま出せば足りる。モードの番号は `Instance.Kind` の 8 ビット目から上に入れる（render が描画コールのモードを入れる）。インスタンスも定数バッファも増やさずに済み、シェーダーは 1 本のまま。
- **ADR の §3 の 1 から外したもの：** Src、SrcIn、SrcOut、DstAtop は、下地を置き換える式に `(1 - cov)·D` の項が要り、出力 1 つでは色とカバレッジを両方運べない。デュアルソースのブレンドなら書けるが、Vulkan では `dualSrcBlend` の機能と別のシェーダーが要る。この 4 つは下地を読む道に回し、ONE / ZERO で書き込む（Skia も、デュアルソースが無いときは同じことをする）。Dst は何も描かないので、render が落とす。
- **固定機能のブレンド状態：** `gpu.BlendMode.Factors` に表を 1 つ持ち、バックエンドはそれを引く。係数の同じモードは 1 つの状態を共有する（`State`：下地を読む W3C のモードは SrcOver と、置き換えの 4 つは Src と同じ）。D3D11 は `ID3D11BlendState`、Vulkan は色を書く 2 段（quad と cover）のパイプラインを、パスごとに初めて使うときに作る。アルファの係数は色の係数の alpha 版にする（D3D11 は `_COLOR` を許さない）。
- **`DrawBlendRead` は作らなかった：** ADR は `DrawKind` を足すとしたが、パスの塗り（`DrawFill`）も下地を読むので、種類とは別の性質にした。`DrawCall.Blend` が `ReadsBackdrop` なら、バックエンドはその描画の前に `DrawCall.Bounds`（render が出す、インスタンスの四角形の和）を物理ピクセルにし、クリップと描画先で切って（`gpu.BackdropRect`）写す。
  - **D3D11：** フレームは `CopySubresourceRegion` で back buffer から写す。マルチサンプルのときは、D3D11 に部分 resolve が無いので、面と同じ大きさのテクスチャに全体を `ResolveSubresource` する。ターゲットは RGBA の共有スクラッチへ写す。下地は t3。
  - **Vulkan：** レンダーパスを終え、マルチサンプルなら終わりの resolve で swapchain の画像がそろうので、そこから `vkCmdCopyImage` で写して、互換の「再開」パス（全部 LOAD、初めのレイアウトは attachment）で続ける。互換のため依存は変えず、イメージバリアで同期する。続けるために、フレームのパスは深度・ステンシルとマルチサンプルの色も STORE にした。ターゲットは今のターゲット用パス（色は LOAD）でそのまま再開できる。下地は set 4（set 1〜3 と同じレイアウト）。swapchain が `TRANSFER_SRC` を持たない環境では、下地を読む描画を捨てる（デスクトップの GPU には無い）。
  - **gpu/soft：** 描画コールの前に同じ範囲を、マルチサンプルなら resolve と同じ丸めで平均して写す。
  - 写した下地は同じ座標に置くので、シェーダーは `SV_Position` でそのまま `Load` する。
- **W3C の式の当て方：** 下地を読むモードは、`Cs = c.rgb / c.a`、`Cb = d.rgb / d.a` に戻し、`Cs' = (1 - αb)·Cs + αb·B(Cb, Cs)` を `(Cs'·c.a, c.a)` として出して、GPU の source-over で重ねる。`c.a` はカバレッジ込みなので、縁ではカバレッジの割合で重なる。分離不可能なモードは仕様の `SetLum` / `SetSat` / `ClipColor` をそのまま書いた（`SetSat` は最大を s、最小を 0 にする等価な式）。
- **1 回の写しで済ませる範囲：** 1 つの描画コールのインスタンスは、全部コールの前の下地を読む。1 つの命令のインスタンス（文字列のグリフなど）は 1 コールにまとめる。続く同じモードの命令は、それまでのコールの外接矩形と重ならなければ同じコールに入る（`beginBackdrop`）。重なれば新しいコールにして写し直す。グリッドのように外接矩形が広がる並びでは、命令ごとに写すことになる。
- **測った写しの費用（RTX 3050 Ti、1200×900、PresentImmediately、半透明の 12×40 の矩形 720 個、Multiply）：** まとめた 12 回の写しは src-over と差がほぼ無い（D3D11 1.14ms 対 1.19ms、Vulkan 0.73ms 対 0.72ms）。矩形ごとに 720 回写すと、D3D11 5.2ms、Vulkan 6.7ms。マルチサンプルのフレームでは 1 回が重く（D3D11 は全体の resolve、Vulkan はパスの区切りと resolve）、720 回で D3D11 22ms、Vulkan 25ms、12 回なら D3D11 0.68ms、Vulkan 1.05ms。まとめる手間に見合うので入れた。
- **部分木：** `widgets.Blend{Mode, Child}` は `core.RenderRepaintBoundary` に `SetBlend` を足したもので作った（レイヤーの記録と使い回しは境界がすでに持つので、layout に別の RenderObject は作らなかった）。`Canvas.DrawLayerBlended` が `OpLayer` に `Blend` と、レイヤー全体の不透明度（`Op.Color.A`、0 は 1）を入れる。`Opacity` の下でも、まとめて薄めてから混ぜるので、CSS の `opacity` と `mix-blend-mode` と同じ結果になる（`CanBlendLayer` は拡大とレイヤーの入れ子だけを拒む）。モードの変更は親の絵の変更として扱う。
  - レイヤーはページの画像として、固定機能か下地を読む道で描く。混ぜるレイヤーは「落ち着くまでインライン」を待たない（インラインでは 1 枚の絵にならない）。
  - 拡大の下やレイヤーの中では、`Canvas.PushBlend` で子の命令をひとつずつ混ぜる。ステンシルが要るためにページに載らないレイヤーも、同じく命令ごとのモードと不透明度に落とす（ランプのグラデーションは薄まらない）。重なりでは結果が違う。
  - 形に限るモード（SrcIn など）でレイヤーが形とみなすのは、描いたものの外接矩形（ページの範囲）。
- **golden：** `blends`（29 モードの格子。虹のグラデーションと文字の上に、半透明のグラデーションの円。マルチサンプル無しなので写しは直接）、`blends2`（`Blend` の部分木と、命令ごとの比較、`Opacity` の下の Hue、`RepaintBoundary` のレイヤーの中の Difference と DstOut、パスの Overlay と Screen と Clear。パスでフレームがマルチサンプルになり、写しが resolve を通る）。D3D11 と Vulkan は既存の閾値で soft に合う（`blends` は最大 4〜5、閾値 2 を超える画素 9〜40）。シーンは 1 つの Renderer を共有するので、新しいシーンは最後に置く（前に置くと、後ろのシーンのアトラスやページの状態が変わり、`list-scrolled` が 1 画素 1 だけ変わった）。
- **残した穴：** 1 つのコールの中で重なるインスタンス（文字の縁のにじみ程度）は、互いの結果を下地として読まない。置き換えの 4 モードでは、重なりで後のインスタンスが前のものを消す。マルチサンプルのフレームでは、下地は resolve した 1 サンプルの値で、サンプルごとの下地ではない。swapchain がコピーできない環境では下地を読む描画が消える。

### 4. ブラー

- **`BackdropFilter{Sigma, Child}`（背景のぼかし）：** 描画は `OpBackdrop`（形は角丸矩形、または上に積まれたクリップ）。バックエンドの手順は次のとおり。
  1. レンダーパスを区切る。
  2. 形の外接矩形に 3σ を足した範囲を、スクラッチに写す。マルチサンプルのときは resolve する。
  3. σ に応じて 1/2 か 1/4 に縮小する。
  4. 横と縦に分けて Gauss のぼかしを掛ける。
  5. 元の倍率で形の中に描き戻す。
- **`ImageFiltered{Sigma, Child}`（子のぼかし）：** 子をレイヤーとして記録し、`OpLayer` に `Blur` を付ける。render はレイヤーをターゲットに描き、`BlurTarget` でぼかしたテクスチャを画像として描く。
- **レイヤーとの関係：** 背景のぼかしは画面の下地を読むので、`OpBackdrop` を含むレイヤーはページに載せず、`inline` の道（ADR 0019）で毎回フレームに描く。
- **`Dialog{Glass: true}`：** 半透明の地と背景のぼかし（σ = 20 論理ピクセル）。既定は false のまま。
- **ReduceTransparency** のような OS 設定への追従は、Phase 14 の OS 設定と一緒に扱う。

段 4 を実装したときに決めた細部（2026-11-09）：

- **`Op` は大きくしない：** `OpBackdrop` を種類に足し、形は `RRect`、σ（面の上の論理ピクセル）は `Blur`、不透明度は `Color.A` に入れた。`ImageFiltered` は `OpLayer` の `Blur` に σ を入れる（`OpLayer` は `Blur` を使っていなかった）。`unsafe.Sizeof(paint.Op{})` は段 3 と同じ 384 バイト。`Canvas` には `DrawBackdrop(rr, sigma)` と `DrawLayerFiltered(l, off, mode, sigma)` を足した。
- **描画コール：** `gpu.DrawCall.Blur`（σ、論理ピクセル）を足した。ぼかすコールはインスタンスを 1 つだけ持つ。インスタンスの種類は、背景を形に描き戻す `InstanceBackdrop`（角丸の SDF で縁を滑らかにする）と、ぼかしたレイヤーを画像として描く `InstanceFiltered`。ADR の「`BlurTarget`」は作らなかった。ぼかしのパスもバックエンドが描画コールの中で走らせるので、render は 1 つのコールを出すだけで済む。
- **パスは SDF のパイプラインのまま：** 縮小、横、縦の 3 パスを、`InstanceBlurDown`、`InstanceBlurX`、`InstanceBlurY` というインスタンスの種類として、同じピクセルシェーダーに書いた。パイプラインもシェーダーの本数も増えない。パスのインスタンスはバックエンドが `gpu.PlanBlur` と `Blur.Passes` で作り、バッチのインスタンスの後ろに足して同じ頂点バッファで描く（ぼかし 1 つにつき 3 個）。書き込みは `BlendSrc` の固定機能のブレンドで、下地を読まずに置き換える。
- **定数を変えずにスクラッチへ描く：** スクラッチのターゲットは描画先より小さいが、ビューポートとフレームの定数は描画先のままにする。インスタンスの矩形を「テクセル ÷ scale」で渡すと、頂点シェーダーの出力が描画先の物理ピクセル＝スクラッチのテクセルになる。定数バッファもプッシュ定数も増えない。シザーで書く範囲を切る。
- **縮小の段階：** 物理ピクセルの σ が 8 未満は 1/2、32 未満は 1/4、それ以上は 1/8（ADR は 1/2 か 1/4 としたが、σ が大きいとタップが増えるので 1/8 を足した）。縮小後の σ は 1〜16 テクセルで、片側 `ceil(3σ)` テクセル、最大 48 を読む。σ は物理 128 ピクセルで頭打ち。小さい σ でも縮小は 1/2 から始める（等倍の道を作ると、スクラッチが描画先と同じ大きさになり、Vulkan の 2048 の深度にも当たる）。ガラスの σ = 20 は、倍率 1 で 1/4・σ 5・片側 15 タップ、1.5 で 1/4・σ 7.5・23 タップ。
- **読む範囲：** 背景のぼかしは、形の外接矩形に 3σ を足し、クリップと描画先で切った範囲を写す（`Blur.Source`）。範囲の外は端のピクセルを繰り返す。クリップの外（スクロールの上の見出しなど）は混ざらない。パスが書くのは `Source` を縮小した範囲の周りに 1 テクセル足した範囲（`Blur.Out`）で、描き戻すときのバイリニアがはみ出しても書いたテクセルに当たる。
- **計算の決まり：** 縮小は f×f の平均、ぼかしは `exp(-k²/2σ²)` を正規化した重み。どちらも `Load` で読み、描き戻しのバイリニアも `Load` の 4 テクセルを自前で混ぜる（サンプラーの重みの丸めは GPU ごとに違う）。各パスは RGBA8 に書くので、途中で 8 ビットに丸まる。`gpu/soft` は同じ式、同じ丸めで書いた。
- **D3D11：** ぼかすコールの前に、段 3 の写し（`copyBackdrop`。マルチサンプルなら全体を resolve）で下地を t3 に置き、深度なしでスクラッチの RTV に 3 回描いて、フレームの RTV と DSV に戻す。ぼかした絵は新しいスロット t4 で読む。
- **Vulkan：** レンダーパスを終え、写し、スクラッチごとにターゲット用のパス（平のパスと互換）を 3 回開いて閉じ、段 3 と同じ再開のパスで戻る。マルチサンプルのフレームでも、パスは平のパスのパイプラインを使う。ぼかした絵は set 5 で読むので、パイプラインのレイアウトは 6 組になった（デスクトップのドライバは 8 組以上を許す）。
- **スクラッチの使い回し：** スクラッチはデバイスに 2 枚、足りなくなったときだけ大きくする。フレームとターゲットで共有する。D3D11 と Vulkan のテストで、ぼかしのあるマルチサンプルのフレームも allocs/op = 0、2 フレーム目以降に作り直さないことを確かめた。
- **レイヤー：** ぼかすコールを含むレイヤーは、ページに載せずインラインにする（ADR 0019 の表に 1 行増える）。`ImageFiltered` は `RenderRepaintBoundary.SetBlur` で作り、レイヤーを「1 枚の絵」として描く（段 3 の `Blend` と同じ道）。ページには周りに `ceil(3σ·scale)+1` ピクセルの透明な余白を付けて描くので、ぼかしが端で切れない。`InstanceFiltered` は `InstanceImage` と同じく回転（段 1）、不透明度、ブレンド（段 3）を受ける。
- **`Dialog{Glass: true}`：** テーマに `Glass` の色を足した（ライトは白の 85%、ダークは N 20 の 78%）。スクリムの下のテーマのどの面（アクセントの塗りを含む）の上でも Ink と Ink2 が 4.5:1 を保つ最小の不透明度を切り上げた値で、`theme` のテストで固定した。黒や白の上では Ink は 4.5:1、Ink2 は 4.25:1。もっと透かすと、ライトのアクセントの塗りの上で Ink2 が 4.5:1 を割る（0.78 で 4.03:1）。カードは `BackdropFilter{Sigma: 20, Radius: 角丸, Child: Container{Color: Glass, ...}}` で、線と影は今までのまま。既定の `Glass: false` は今までの絵とビットまで同じ（`dialog` の golden は変わらない）。`ReduceMotion` は今までどおり、フェードだけ残る。
- **golden：** `blurs`（虹のグラデーション、図形、文字の上に σ 3、14、40 のガラスのカード、`RepaintBoundary` の中のカード、`ImageFiltered` の文字と、回して薄めた図形）、`glass-dialog`（ライト、倍率 1）、`glass-dialog-dark`（ダーク、倍率 1.5）。D3D11（Iris Xe）と Vulkan（RTX 3050 Ti）は、既存の閾値のまま soft に合った（どれも最大 2、閾値 2 を超える画素 0）ので、閾値は広げなかった。`gpu` のパリティのテストに足した 3 場面（背景のぼかし 3 種、ステンシルのクリップと不透明度の下のぼかし、回して Multiply したレイヤーのぼかし、各倍率 1 と 1.5）でも、両 GPU で D3D11 と Vulkan の差は最大 1、soft との差は最大 3（閾値 2 を超える画素 1）。既存の golden はビットまで同じ。
- **計測の道具：** 両バックエンドに `EnableGPUTiming` と `GPUFrameTimes`（タイムスタンプのクエリ）を足した。D3D11 は最初の `DrawToTarget` か `BeginFrame` から `Present` の前まで、Vulkan はコマンドバッファの最初から最後まで。有効にしなければ、フレームの経路にあるのはポインターの nil の比較だけ。Windows の `time.Now` は約 0.5 ms 刻みで 1 フレームの CPU 時間を測れないので、`platform/win32.PreciseTime`（QueryPerformanceCounter）を足した。どちらも gowaku 自身は使わない。計測は `examples/glass -bench`。
- **120fps の計測（2026-11-09）：** `examples/glass -bench 10s`。1920×1080 物理（1280×720 論理、倍率 150%）、垂直同期なし（`PresentImmediately`）。幅 560 のガラスのダイアログの後ろで、グラデーションの行（各行が `RepaintBoundary`）の一覧が毎フレーム動く。CPU は木からバッチまで（Tick、Build、Layout、Paint、Encode、Finish）と `Draw` の記録。`BeginFrame` と `EndFrame` はスワップチェーンと GPU を待つので外した。GPU はタイムスタンプ。各 10 秒、約 4400〜5000 フレーム。

  | GPU | API | CPU p50 / p95（ms） | GPU p50 / p95（ms） | CPU + GPU の p95（ms） | 不透明のダイアログの GPU p50 |
  |---|---|---:|---:|---:|---:|
  | RTX 3050 Ti | D3D11 | 0.19 / 0.33 | 0.29 / 0.30 | 0.63 | 0.12 |
  | RTX 3050 Ti | Vulkan | 0.23 / 0.42 | 0.54 / 0.54 | 0.96 | 0.33 |
  | Iris Xe（記録のみ） | D3D11 | 0.22 / 0.43 | 2.04 / 3.17 | 3.60 | 1.22 |
  | Iris Xe（記録のみ） | Vulkan | 0.34 / 0.62 | 1.50 / 2.39 | 3.01 | 0.75 |

  完了条件の RTX 3050 Ti では、D3D11 と Vulkan のどちらも、CPU と GPU を足して直列に並べても 1 ms 未満で、8.33 ms に 8 倍以上の余裕がある。最適化はしていない。ガラスの GPU の費用は RTX で 0.17〜0.21 ms、Iris Xe で 0.75〜0.82 ms。垂直同期なしのフレームの間隔は p50 で 1.6〜2.1 ms（450〜500 fps）で、残りは `Present` の経路が占める（ADR 0015 と同じ）。この PC は 4K を出せないので、4K では測っていない。
- **記録とエンコードの費用：** 段 4 がホットパスに足したのは、`addDraw` と `beginBackdrop` の `Blur == 0` の比較と、`encodeOps` の分岐 1 つ。HEAD（段 1 の前）と一時的な worktree で交互に 6 回ずつ測った（`-benchtime 2s`、中央値）。`BenchmarkCanvas_10kRects` は 0.69 ms から 0.76 ms（+11%、`Op` が 328 から 384 バイトになった段 1〜2 の分）、`BenchmarkEncode_10kRects` は 0.65 ms から 0.53 ms、`BenchmarkEncode_10kGlyphs` は 1.22 ms から 1.29 ms。どれもアロケーション 0。この PC は時間帯で 2〜3 倍揺れるので、交互に測った値だけを比べている。
- **残した穴：** インラインでしか描けないレイヤー（パスや形のクリップでマルチサンプルが要る、2048 を超える、`Blend` などのレイヤーの中、拡大の下）を `ImageFiltered` にすると、ぼかさずに描く。`Blend` の中の `ImageFiltered` もそうなる（レイヤーは入れ子にならない）。背景のぼかしの σ は面の上の値で、回転や歪みの変換では回らない（円いまま）。マルチサンプルのフレームでは、段 3 と同じく下地は resolve した 1 サンプルの値。swapchain がコピーできない環境では背景のぼかしが消える。σ が物理 128 ピクセルを超える分は 128 として描く。

### 5. `gpu/soft` と golden

Affine、ランプ、全ブレンドモード、ぼかしの式を `gpu/soft` にも入れる。D3D11 と Vulkan は、golden（閾値つき）で `gpu/soft` と比べる。ぼかしは縮小の仕方が GPU ごとに違ってよいので、閾値を広めにする。

### 6. Metal（Phase 17）に写せるか

ブレンド状態、テクスチャのコピー（blit）、フラグメントシェーダーでのぼかしは、すべて Metal にそのまま写せる。レンダーパスを区切る点も、`MTLRenderCommandEncoder` を作り直すだけで同じになる。

## 進め方

共通のファイル（`Instance`、シェーダー、両バックエンド、`gpu/soft`）を全段で触るので、段を分けて順に進める。

1. Affine
2. グラデーション
3. ブレンドモード
4. ブラーとガラス、120fps の計測

## 却下した案

- **Affine のときは常にレイヤーに描いてから変換する：** 文字や細い線がぼける。SDF を局所座標で評価するほうが、きれいで速い。
- **ブレンドモードは全部、下地を写す道で描く：** 固定機能で書ける 15 種まで、毎回コピーすることになる。
- **ぼかしにコンピュートシェーダーを使う：** D3D11 と Vulkan と soft で道が増える。フラグメントの 2 パスで、120fps の目標に足りる見込み。
