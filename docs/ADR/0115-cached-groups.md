# 0115: キャッシュするグループ、既存ウィジェットのグループ化

決定日: 2026-11-14

状態: 採用

## 背景

[ADR 0114](0114-gpu-layers-masks-filters.md) で、キャンバスのグループ（`PushGroup`）を GPU のジョブとして描くようにした。残った穴が 2 つあった。

- **既存のウィジェット：** `Blend`、`ImageFiltered`、`RepaintBoundary.SetOpacity` は 13a のページ（ADR 0044）で 1 枚の絵として合成し、ページが使えないところ（拡大の下、ほかのレイヤーの中、マルチサンプルの要るレイヤー）では命令ごとの合成やぼかし無しに落ちていた。`Opacity` は形ごとに薄めていた。
- **毎フレームの費用：** グループは描くフレームごとにジョブが走る（ページに載ったものを除く）。CPU で合成していたころの SVG は、合成した絵をキャッシュしていた。オーナーの選択は「案 A」：合成の結果を GPU のテクスチャとして持ち、次のフレームからはそれを描く。

## 決定

### 1. 既存のウィジェットをグループに載せ替える

- **`RepaintBoundary`：** 混ぜる、ぼかす、薄めるのどれかがあると、`Translate(off)` → `PushOpacity` → `PushGroup{Blend, Filter, Cache}` → 子（`DrawLayer` か、レイヤーが使えなければ子をそのまま）→ `PopGroup`。グループの中は不透明度 1、source-over なので、レイヤーはそこでも使える。ぼかしは `FilterBlur`（sRGB、標準偏差は論理ピクセル）。領域は箱とレイヤーの外接矩形を 3σ+1 広げたもの（`Layer.Bounds` を足した）。
- **`RenderOpacity`（`Opacity`、`AnimatedOpacity`）：** 0 と 1 の間では子をグループで描く。重なった形の下が透けなくなる（CSS の `opacity`）。
- **1 つの形のグループは絵を作らない：** フィルターもマスクも無く、source-over のグループの中身が、インスタンス 1 つの描画コール 1 つ（パスの頂点、下地の読み、カスタムシェーダー、ランプのグラデーションを除く）なら、そのインスタンスを薄めてそのまま描く。結果は同じで、アイコンや 1 枚の箱にかかる `Opacity` がジョブを増やさない。
- **消した 13a のコード：** `Canvas.DrawLayerBlended`、`DrawLayerFiltered`、`CanBlendLayer`、render の混ぜる／ぼかすページ（`grouped`、`layerOpacity`、`blurPad`、ページの余白、`blendEach`、`InstanceFiltered` の描画コール）。`OpLayer` は `Blend`、`Color.A`、`Blur` を使わなくなった。`CanDrawLayer` は `PushBlend` の下でも false を返す（`PushBlend` は命令ごとに混ぜる約束で、ページの絵では守れない）。
- **残したもの：** `gpu.InstanceFiltered` と各バックエンドの「画像をぼかす」道（`PlanBlur` の `fromImage`、シェーダーの `KIND_FILTERED`）。render からは使われなくなったが、消すとインスタンスの種類の番号が変わり、D3D11（fxc）、Vulkan、Metal のシェーダーを作り直すことになる。gpu の単体テストだけが使っている（「決めてほしいこと」）。

### 2. キャッシュするグループ

- **API（paint）：** `GroupStyle.Cache *GroupCache`。`GroupCache` はゼロ値で使え、`Invalidate()` と `Version()` だけを持つ。描く場所ごとに 1 つ持ち、中身・マスク・フィルターが変わったら `Invalidate` する。不透明度、`Blend`、クリップは描くときに掛かるので数えない。
  - **動かすのは平行移動で：** キャッシュの絵は `PushGroup` の時の平行移動に付いて動く。同じ平行移動のまま中身の座標を変えるのは「変わった」になる。だから使う側は `Translate` してから `PushGroup` し、原点から描く（`RepaintBoundary` と `SVG.DrawCached` はそうした）。
  - **クリップを外して記録する：** キャッシュするグループの中身は、その時のクリップ（シザー）を外して記録する（`BeginMask` の後も同じ）。絵はどこに描かれても中身を全部持ち、クリップは合成するときに掛かる。スクロールで半分隠れても、隠れ方が変わってもキャッシュは当たる。
  - **版は描くときに読む：** render は `Encode` の時に `Cache.Version()` を読む。レイヤーだけが描き直されてフレームのリストが残る場合（`Tree.Repaint` が false）でも、レイヤーと一緒に `Invalidate` すれば次の絵になる（`RepaintBoundary.flush` がそうする）。
- **SVG：** `SVG.DrawCached(cv, dst, current, *SVGCache)` と `SVGCache`。グループのある図は、外側にキャッシュするグループを 1 つ置き、その中で今までどおり描く。`SVGCache` は図、`SetText` の回数、`dst` の大きさ、`currentColor` が変わると `Invalidate` する。位置だけの変化は保つ。グループの無い図（アイコン）は `Draw` と同じ道で、キャッシュは使わない。`layout.RenderSVG` は `SVGCache` を持ち、`DrawCached` で描く。
- **render：**
  - 鍵は `*GroupCache`。項目は版、面の倍率、キャンバスの倍率（`Op.Scale`）、作った時の原点、絵の矩形、絵のテクスチャ。版と倍率が合えば、絵だけを `InstanceImage` として描く（不透明度、`Blend`、クリップはそのとき）。ジョブは 1 つも走らない。
  - **素のグループは 2 回目から：** フィルターもマスクも無く、不透明度 1、source-over のグループ（SVG の外側のグループがそう）は、その版を初めて描くときはグループを作らずに中身をフレームに入れる（クリップはそこで掛ける）。同じ版の 2 回目に絵を作って保つ。中身が毎フレーム変わる図（アニメーション）は、キャッシュの無いときと同じ費用で、余計なパスは増えない。絵が要るグループ（不透明度、混ぜる、フィルター、マスク）は、どうせ最後の絵があるので、初回からそれを保つ（追加の費用は無い）。
  - **絵の持ち方：** 最後のパスが書いたプールのターゲット（ADR 0114）を、プールから外してキャッシュのものにする。描き直すときと捨てるときは、古い絵をすぐにはプールへ返さず、次のフレームの初めに返す（そのフレームでまだ描くかもしれないので）。
  - **予算と追い出し：** 絵のバイト数の合計は 128 MB（2048 四方 8 枚分）まで。超えるときは、このフレームで描いていないものを古い順に追い出す。それでも入らなければ保たない（その回はキャッシュの無いグループと同じ）。120 フレーム描かれなかった項目は捨てる（グループのターゲットの寿命と同じ）。`Resources.Destroy`（装置を失ったときも含む）ですべて捨てる。
  - **画素の格子（端数の位置）：** 作り直すのは版と倍率が変わったときだけで、位置の端数では作り直さない。初回の絵は今までと同じ位置にビットまで同じに描き、後のフレームは原点の移動を物理ピクセルに丸めた分だけ絵をずらす（レイヤーの `snapOrigin` と同じ丸め）。端数で動くアニメーション（ページの横滑り）でも毎フレーム当たり、ずれは最大 0.5 ピクセル。グリフをずらして描き直すとぼけるので、作り直す時に端数に合わせることもしない。
  - **キャッシュしない場合：** ページに載せるレイヤーのラスタライズ中（ページが絵を持つので二重に持たない）、回転や歪みの下（`Op.Transform`）、クリップを外した範囲が 2048 を超えるとき（そのときはクリップで切った、キャッシュの無いグループとして描く）。
  - 定常状態のアロケーションは 0（当たり、毎フレーム変わる素のグループ、どちらも `TestCachedGroup_EncodeDoesNotAllocate`）。`map` への追加は初めて見る `GroupCache` だけ。
- **一般のプリミティブにした理由：** SVG 専用の鍵（図と大きさと色）にすると、`RepaintBoundary` のぼかしや薄めの絵（13a ではページが持っていた）に同じ仕組みを使えない。`GroupCache` は版 1 つなので小さく、鍵の意味は使う側が決める。

## 結果

- **golden（タスク 1）：** `blends2`（「faded」の格子：`Opacity` の下の `Blend` Hue が、外側のグループで孤立する。CSS で opacity が重ね合わせの文脈を作るのと同じで、円はそれぞれの色を 0.6 で見せる）、`blurs`（`ImageFiltered` が縮めてからのぼかしでなく、グループのガウス／箱のぼかしになった。最大 8）、`coverage-misc(-dark)`（`AnimatedOpacity` 0.4 の箱の上の文字が箱を透かさなくなり、白く見える）、`controls-dark`（無効な入力欄のラベルが同じ理由で少し明るい）。ほかの 14 枚は最大 1〜2（グループの絵を 8 ビットで通る丸め）。D3D11 と Vulkan はどれも最大 2、2 を超える画素 0。
- **golden（タスク 2）：** `svg-features`（最大 2）と `navigator-push-dark`（最大 1）。何フレームか描く場面で、2 回目からキャッシュの絵を描くための丸め。
- **catalog：** `basic.Opacity`、`basic.AnimatedOpacity`（文字が箱を透かさない）、`basic.ImageFiltered`（ぼかしが領域いっぱいに広がり、絵が 2〜5 ピクセル大きい）を作り直した。

## 残した穴

- **`Opacity` は毎フレーム絵を作る：** 中身の版が分からないので、`RenderOpacity` はキャッシュしない（1 つの形のときは絵を作らない）。`Opacity{RepaintBoundary{…}}` でも外側のグループは毎フレーム走る。変わらない子をフェードさせて保ちたいときは、`RepaintBoundary` 自身の不透明度（`SetOpacity`、ナビゲーターのページがそう）を使う。
- 回転や歪みの下のグループはキャッシュしない。
- キャッシュの絵は端数の移動を物理ピクセルに丸めるので、止まった位置が初回の位置と端数で違うと、最大 0.5 ピクセルずれたまま（レイヤーと同じ）。
- `GroupCache` を渡したまま中身を変えて `Invalidate` を忘れると、古い絵が出る（使う側の約束）。

## 却下した案

- **端数が変わるたびに作り直す：** ビットまで正確だが、ページの横滑りのように端数で動くものが毎フレーム外れる。13a のページは丸めていたので、それに合わせた。
- **作るときに中身を整数の位置へずらす：** グリフのインスタンスが端数の位置に落ちてぼける。
- **SVG 専用のキャッシュ（render の資源を図と大きさと色で引く）：** `RepaintBoundary` が使えない。
- **素のグループも初回から絵を保つ：** 毎フレーム変わる図で、パスが 1 つ増える。
