# 0098: DockLayout（IDE 風のパネルのドッキング）

決定日: 2026-11-13

状態: 採用

## 背景

当初の計画の `DockLayout`。表には「規模が大きい。配置の保存と復元まで含めるか」とだけあり、範囲が決まっていなかった。今あるのは `SplitPane`（2 つのペインと区切り）と、`TabBar` の並べ替え・帯の間の移動・引き剥がし（ADR 0060）。範囲の判断はオーナーから任された。

## 選択肢

1. **SplitPane と TabBar の組み合わせ例をサンプルに置くだけ。** 部品は増えない。しかし群をまたぐ移動、端に落として分割、空になった群の片付けは、利用者が毎回木の操作を書くことになる。
2. **配置の木と操作を持つ部品にし、保存は利用者に任せる。** 保存の形式が利用者ごとに違い、後で浮動パネルを足すときに互換を守れない。
3. **配置の木、操作、保存できる値までを部品が持つ。** ファイルの読み書きだけは利用者がする。
4. 3 に加えて、浮動パネル（別ウィンドウ）、自動で隠れる横の帯、入れ子のドックまで。

## 決定

3 を選ぶ。4 の三つは範囲の外にする（§6）。

### 1. 置き場所

`widgets/nav`（ADR 0081 の 5 段）。`TabBar` と同じパッケージに置くと、帯のドラッグの仕組みに非公開の口を 1 つ足すだけで済む（§3）。`control` の `SplitPane` は使わず、`kit.SplitHandle` と寸法を直接使う（§4）。

### 2. モデル

- **木。** 節は分割（`Axis` と子と `Weights`）か、葉のタブの群（`Panels` と `Active`）。パネルは利用者が付ける安定した文字列の ID で表す。
- **API。**
  - `DockLayout{Panels []DockPanel, Controller, Default, Label, OnChange, OnClose}`。
  - `DockPanel{ID, Title, Icon, Build func(ctx) Widget, Closable}`。
  - `DockController`（ゼロ値で使える。State に置く）は `Arrangement`、`SetArrangement`、`Reset`、`Activate`、`Close`、`Move(id, target, zone)`、`Maximize` を持つ。
  - `Controller` が nil なら部品が自分で持つ。
- **ゼロ値。** `Default` が空なら、全パネルを 1 つの群に並べる。`Default` を渡せばそこから始まり、`Reset` もそこへ戻る。
- **木の片付け。** 変更のたびに次を行う。木の形の規則がここ 1 箇所に集まり、どの操作の後も同じ形になる。
  - 空の群を除く（根だけは空の群として残る）。
  - 子が 1 つの分割をその子に置き換える。
  - 同じ向きの分割の中の分割を親に展開し、重みを掛け合わせる。
- **群の同一性。** 群は実行中だけの番号を持ち、タブの帯と区切りのキーにする。保存の形式には入れない。
- **パネルの並びが変わったとき。**
  - `Panels` から消えたパネルは木から消える。
  - 新しいパネルは「今の群」（最後にフォーカスがあった群、無ければ最初の群）に入る。
  - ユーザーが閉じたパネルは `Closed` に記録し、新しいパネル扱いで戻ってこないようにする。`Activate` で開き直せる。

### 3. TabBar の再利用

タブの帯を二つ目は書かない。各群は普通の `TabBar` で、全部の帯が 1 つの `TabGroup` を共有する。

- 帯の中の並べ替え、別の群の帯への移動、差し込み位置の半透明のタブ、Escape での取り消し、Ctrl+Tab と Ctrl+W は、TabBar がそのままする。
  - 別の帯へ落とすと、TabBar は相手の `OnReceive` の後に元の `OnDetach` を呼ぶ。部品は `OnReceive` で移動を済ませ、`OnDetach` では何もしない。
- 帯の外（パネルの中身の上）へのドラッグを部品が知るために、`TabGroup` に非公開の `dropper` を足した。
  - TabBar は、帯から離れたタブの位置を `tabDragged` で伝える。
  - どの帯の上でもない所で放すと `tabDropped` を呼び、受け取られたら `OnTearOff` は呼ばない。
  - 終わりは `tabDragEnded` で伝える。
  - 公開 API は変わらない。`dropper` が nil の帯の動きも変わらない。
- 閉じられないパネルのために、`TabItem` に `Permanent`（× を出さず、中クリックと Ctrl+W でも閉じない）を足した。
  - ゼロ値の TabItem が閉じられないと困るので、肯定形の `Closable` ではなくこの名前にした（CODING_STYLE §4.1 の `Disabled` と同じ理由）。
- **キーの順番。** TabBar の Ctrl+Tab と Ctrl+W は窓のどこからでも効き、フォーカスが外にあると最後に描いた帯が取る。
  - 部品のキーは、最後の子（大きさ 0）と、全体を包むものの二箇所で受ける。
  - こうして、フォーカスがパネルの中でも外でも、「今の群」に効くようにした。
  - フォーカスがある帯の中では、その帯の TabBar が先に取る。どちらも同じ群なので、結果は変わらない。

### 4. 操作

- **区切り。**
  - `kit.SplitHandle` をそのまま使う。見た目、9px の帯、カーソル、ダブルクリック、矢印と Home / End、`RoleSeparator` の Range（最初の側の割合）は SplitPane と同じ。
  - 動かすのは隣り合う 2 つの子の重みだけで、どちらも最小の大きさ（幅 96、高さは帯 + 40。入れ子では軸に沿って足し合わせる）より小さくならない。
  - ドラッグ中は Build をせず、重みを書き換えてレイアウトだけをやり直す（§7）。`OnChange` はドラッグの終わりに 1 回。
- **落とす場所。**
  - 全体の端から 24px 以内なら、全体のその端に 1/4 の幅で置く。
  - 群の中身の上では、近い辺までの距離が大きさの 1/4 未満ならその辺に半分で分割し、それ以外は群に加える。帯の上は加えるだけ。
  - 変化が無い場所（自分の群の中央、1 枚だけの群の自分の辺など）にはプレビューを出さない。
  - プレビューはアクセント色の薄い角丸の四角で、描くだけの変更で動く。そのため、ドラッグ元の帯が Build 中に消えても安全に片付く。
- **最大化。** 入れる。帯の空いた所をダブルクリックするか Ctrl+Alt+Enter で、その群が全体を占め、ほかを隠す（状態を保ったまま）。もう一度で戻る。保存の値にも入る。
  - 入れた理由: 小さな画面で 1 つの群に集中する操作は IDE で毎日使う。部品の外からは作れない。
- **キーボード。**
  - Ctrl+Alt+矢印: 隣の群へフォーカスを移す。
  - Ctrl+Alt+Shift+矢印: 選択中のパネルを隣の群へ移す。隣が無ければ、自分の群のその辺に分割して置く。
  - 隣は、前回のレイアウトの位置で、その方向にあって横に重なる一番近い群とする。
  - Ctrl+Alt は AltGr と重なる配列があるが、矢印と Enter は文字を出さないので衝突しない。
- **閉じる。** × 、中クリック、Ctrl+W。選択は右隣に移る（ブラウザと同じ）。最後の 1 枚なら群が消え、隣が場所を引き取る。

### 5. 保存と復元

- `DockArrangement{Root DockNode, Maximized, Closed}` は普通の値で、encoding/json で読み書きする（新しい依存は無い）。部品はファイルを読み書きしない。
- 形式:

  ```json
  {"version":1,
   "root":{"split":"horizontal","weights":[0.2,0.6,0.2],"children":[
     {"panels":["files"],"active":"files"}, …]},
   "maximized":"main.go","closed":["props"]}
  ```

- 版は 1。`version` が無いか 1 以外なら `ErrDockVersion` を包んだエラーを返し、値は変えない。知らない `split` もエラー。
- **復元の寛容さ。**
  - 知らないパネル ID は捨てる。重複は最初の 1 つだけを残す。
  - 保存に無い新しいパネルは今の群に入れる。`Closed` にあるものは閉じたままにする。
  - 長さの合わない重みや正でない重みは等分にする。
- **後から引き剥がしを足すとき。** 知らないキー（たとえば将来の `"windows"`）は読むときに無視する。版 1 の読み手は浮動パネルの入った保存を壊さずに読め、浮動パネルは新しいパネル扱いで今の群に入る。新しい読み手は、`windows` が無ければ浮動パネルが無いとみなせる。版を上げるのは、意味が変わって古い読み手が誤読するときだけにする。

### 6. 範囲の外

- **浮動パネル（引き剥がしで別の OS ウィンドウ）。** 今も範囲の外。
  - TabBar の引き剥がしは使えるが、ドックの木を窓をまたいで持つには、閉じたときにどこへ戻すか、窓の位置の保存、Wayland で位置が分からない場合（ADR 0060 §3）を決める必要がある。
  - 帯の外で放したタブは、ドックの外なら何もせず元に戻る。
- **自動で隠れる横の帯**（VS Code のアクティビティバー、JetBrains のツールウィンドウの帯）。2026-11-13 にオーナーの依頼で入れた。ADR 0102 を見る。
- **入れ子のドック**（パネルの中の DockLayout）。同じく ADR 0102 で入れた。
  - キーは内側から外側へ流れ、ドラッグはドックの中に閉じる。
  - 外と中の間でタブは移らない。core にグローバルキーが無く、移すと State を保てないため（ADR 0102 §8）。

### 7. 状態の保持とホットパス

- **パネルの中身は、群ではなく部品自身の子として置く。** パネル ID をキーにした子で、群の場所にレイアウトする。
  - core にはグローバルキー（親をまたぐ要素の付け替え）が無い。中身を群の帯の下に置くと、群を移るたびに State が作り直しになる。
  - 1 つの親の下のキー付きの子なら、今の reconcile のままで要素が残る。そのため、エディタの文字やスクロール位置は、群を移っても、最大化しても、選択されていない間も保たれる。core には手を入れていない。
- **中身は初めて表示されたときに作り、閉じるまで木に残す。** 選択されていない間は `core.Hider` で隠し、ポインタ、Tab、スクリーンリーダーから外す。一度も開かないパネルは作らない。
- **レイアウトと描画はアロケーションしない。**
  - 木の配置は再帰のメソッドで、群の地は木を直接たどって描く（クロージャを作らない）。プレビューの線は render object のフィールドを指す。
  - `BenchmarkDockLayout_DragDivider_5Panels`（区切りの帯へのポインタの移動、全群のレイアウト、描画）は 0 allocs/op。
  - `Tree.DispatchPointer` を通すと 1 allocs/op になる。これは core の `Tree.deliver` が各ターゲットに渡すイベントの写しで、どの部品でも同じ。

### 8. Semantics

- 群の帯は TabBar のまま `RoleTabList`（名前は `Label`）、タブは `RoleTab`。
- 表示中のパネルは、題名を名前にした `RoleGroup`。
- 区切りは SplitPane と同じ調整できる `RoleSeparator`（名前は「ペインの区切り」）。

## 結果

- 追加だけで、既存の公開 API と既定の動きは変わらない。共有ファイルへの変更は次の二つ。
  - `TabItem.Permanent` と `TabBar` の閉じる処理の判定（tabbar.go）。
  - `TabGroup.dropper` と、ドラッグ中・放したとき・取り消しのときの呼び出し（tabbar_drag.go）。
- テストは GPU 無しで通る（docklayout_test.go、docklayout_model_test.go、docklayout_bench_test.go）。
  - 対象: すべての落とす場所、最後の 1 枚の移動による分割の畳み、閉じる、区切りの最小値、JSON の往復（知らない ID、新しいパネル、版の誤り）、ドラッグ中のパネルの増減、Escape、キーボード、ゼロ値、1 枚だけ。
- カタログの頁は `examples/gallery/pages_dock.go`（まだ登録していない）。保存・復元・初期配置のボタンを置き、JSON はメモリに持つ。
- 残り:
  - ドラッグ中のタブの影（TabBar と同じく、帯を離れると見えなくなる）。
  - 帯の外へ出たタブのカーソル。
  - 実機でのスクリーンリーダーでの確認。
  - 区切りをドラッグしている間、スクリーンリーダーに渡す値は重みから計算するので即座に変わる。ただし Step の分母は前回のレイアウトの長さになる。
