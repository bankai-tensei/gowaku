# 0155: 開いているファイルが外で変わったときに気づき、保存で壊さず、追記を追いかける

決定日: 2026-11-18

状態: ADR 0157 で置き換え（ファイルの変化の扱いはアプリの側に移した）

## 背景

`Controller.OpenFile`（ADR 0153）は、ファイルをディスクに置いたまま、見える行だけを読む。そのため、開いている間に外でファイルが変わると、次のことが起きていた。

- 追記（ログを書き込み中のプログラム）: 開いた後の行は見えない。
- 書き換え（ほかのエディタの保存、ログのローテーション）: 古い索引のまま読むので、ずれた行を黙って表示する。
- 切り詰め: 読めない行は空行になる。
- **保存: 変わったファイルから範囲を写すので、壊れたファイルを黙って書くおそれがある。**

持ち主と話して、まず「気づく」「保存で壊さない」「追記を追いかける」をやることにした。書き換えのときに編集を残して読み直す仕組みと、Windows の共有モード（下の「残り」）は後に回した。

## 選択肢

### 気づき方

- **A. ファイル自身（`os.SameFile`）、大きさ、更新時刻、末尾 4 KB を開いたときに覚え、比べる。** 大きさだけが増え、元の末尾 4 KB が同じなら追記。小さくなった、時刻だけが変わった、末尾が違うなら書き換え。パスが別のファイルを指すか、ファイルが無ければ置き換え。
- **B. 内容のハッシュを取る。** 数 GB を読み直すことになり、開いてすぐ見せるという目的に合わない。
- **C. OS の変更通知（ReadDirectoryChangesW、inotify、FSEvents）。** 3 つの OS の実装が要り、ネットワークドライブでは届かないこともある。

### 見張り方

- 見張らない。`CheckFile` と保存のときだけ見る。
- タイマーで 1 秒ごとに `os.Stat` する goroutine。変わったときだけ UI の goroutine を起こす。待機中の CPU 0 % を保つため、アプリが頼んだとき（`OnChange` か `Follow`）だけ走らせる。

行を読みに行くたびに確かめる案も考えたが、気づいてもアプリに伝える手段が無ければ使い道が無いので、見張りの goroutine に任せた。

## 決定

気づき方は案 A。見張りは、頼まれたときだけ goroutine で行う。

### API

- `OpenFile(path, FileOptions)` に変えた。`FileOptions{OnLoad, OnChange, Follow}`。`OnLoad` はこれまでの第 2 引数。未公開なので互換の層は作らない。
- `FileChange`（`FileUnchanged`、`FileAppended`、`FileRewritten`、`FileReplaced`）。
- `CheckFile() FileChange`: 今のファイルを見て、変わり方を返し、`OnChange` に伝える。同じ変わり方は、次に変わるまで 1 度だけ伝える。読み込み中は `FileUnchanged`。
- `Reload()`: 同じオプションで開き直す。編集と履歴は消える。
- `ErrChangedOnDisk`: 保存を断ったときのエラー。
- `WatchPeriod`（既定 1 秒）: 見張りの間隔。

### 保存で壊さない

- `Save`（と、自分のファイルへの `SaveAs`）は、開いた後にファイルが少しでも変わっていれば書かずに `ErrChangedOnDisk` を返す。書けば、ほかのプログラムが書いたものを消すことになるので、どうするかはアプリに任せる（`Reload`、別のパスへの `SaveAs` など）。
- 別のパスへの `SaveAs` は、追記と置き換えのときは書ける。追記なら元の部分はそのままで、置き換えならこちらが開いているファイルを OS が残しているからである。書き換えのときは、編集していない行がもう元のとおりに読めないので、どのパスにも書かずに `ErrChangedOnDisk` を返す。
- `SaveAs` の後は、書いたファイルを新しく覚え直し、見張りもそのファイルに移す。

### 追記を追いかける（`Follow`）

- 追記に気づいたら、ファイルの最後の行（改行が無いので、追記で続きができることがある）の頭から索引をやり直し、新しい末尾まで別の goroutine で読む。文書から見ると、最後の行が置き換わり、その後に行が増える変更なので、読み込み中に行が増えるのと同じ仕組みがそのまま使える。
- 検索中なら、やり直す最後の行の一致を消し、検索の goroutine がまだ持っているその行の結果も捨てる（編集の記録に足す）。新しい行は検索の列に足す（ADR 0154）。
- 文書が編集されていても追いかける。最後のピースがファイルの末尾でなければ（最後の行を編集した後など）、新しい行はその後ろに足す。

## 結果

- テスト（`widgets/editor/editor_file_change_test.go`、race 検出器あり）: 変わらない、追記、同じ大きさでの書き換え、長くなる書き換え、切り詰めを見分ける。追記と書き換えのときに `Save` が断り、ファイルに何も書かない。追記のときは別のパスへ `SaveAs` でき、書き換えのときはできない。`OnChange` は変わり方ごとに 1 度。`Reload` で今の中身になる。`Follow` で、改行の後への追記、最後の行の続きへの追記、`\r\n`、空のファイルへの追記を読む。編集と検索を持ったまま 5 回追記されても、文書と一致が正しく、最後に保存できる。Editor に表示したまま、見張りの goroutine が追記に気づき、Poster を通って行が増える。
- **Windows では、こちらが開いている間、ほかのプログラムがファイルを置き換えられない**ことを確かめた（置き換えのテストで `Access is denied`）。Go の `os.Open` が `FILE_SHARE_DELETE` を付けないためで、ほかのエディタの「一時ファイルに書いて差し替える」保存が失敗する。置き換えのテストは Windows では飛ばしている。
- 残り:
  - `FILE_SHARE_DELETE` を付けて開く（Windows）。付ければ、ほかのプログラムの保存を邪魔せず、置き換えにも気づける。
  - 書き換えのときに、編集した行を残して読み直す仕組み（今は `Reload` で編集が消える）。
  - 見張りは `os.Stat` の比較なので、大きさも時刻も変えずに中身だけを変える書き換えには気づかない。
