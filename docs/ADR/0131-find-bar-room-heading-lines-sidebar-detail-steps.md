# 0131: 検索バーの分の余白、見出しのソース上の位置、Sidebar の 2 行目、手順の表示

決定日: 2026-11-16

状態: 採用

## 背景

初めて使う人に gowaku を試してもらったところ、次の 4 つが見つかった。

1. **検索バーが一致を隠す：** `editor.Editor` の検索バー（Ctrl+F / Ctrl+H）は、エディタの右上に重ねて置く `Positioned` である。テキストはバーの存在を知らないので、1〜3 行目にある一致はバーの下に隠れたまま「選択」された。スクロールして一致を見せる処理（`revealCaret`）も、ビューの上端までしか見ていなかった。
2. **見出しのソース上の位置が無い：** `markdown.Headings` は `Level`、`Text`、`Slug` だけを返す。プレビューの目次はスクロールできるが、隣のソースのエディタを目次から動かせない。パーサーはブロックごとに `startLine` を持っているのに、外に出していなかった。
3. **Sidebar の行に 2 行目が無い：** `collection.SidebarItem` は `Label`、`Icon`、`Count` しかなく、チャットの一覧の「名前と最後のメッセージ」を作れなかった。`collection.GroupRow` には既に `Detail` がある。
4. **手順の表示が無い：** ウィザードの「① ― ② ― ③」を、利用者がそれぞれ自前で組んでいた。しかも「stepper」で探すと `control.Stepper`（数値を増減するもの。NSStepper にあたる）が見つかり、Material の Stepper や Ant Design の Steps のような手順の表示を探す人を迷わせた。

## 選択肢

### 検索バーと一致

- **A. バーを開いている間、テキストの上端にバーの分の余白を取る。** VS Code の `editor.find.addExtraSpaceOnTop` と同じ考え方。先頭の行もバーの下から出せる。一致を見せる処理は、上の余白（パディング＋バーの分）を見て、一致をバーの下に置く。
- **B. 余白は取らず、一致がバーの下に来たらスクロールするだけにする。** 1〜3 行目は上にスクロールする余地が無いので、隠れたままになる。
- **C. バーをテキストの外（上）に置き、テキストを押し下げる。** 開閉のたびにテキスト全体が動く。スクロールした位置でも動く。

バーの高さは、バーをレイアウトする前に要る（`Stack` はテキストのビューを先にレイアウトする）。測ってから直すと 1 フレームずれるので、バーの行の数（検索だけか、置換もあるか）と定数（`theme.ControlHeight`、余白 6）から計算する。テストで、計算した高さと実際のバーの下端が一致することを確かめる。

### 見出しの位置

- **A. 行（1 から）を返す。** パーサーが既に持っている。CRLF や不正な UTF-8 を正規化しても行の数は変わらない。
- **B. バイトの位置を返す。** 正規化（CRLF→LF、不正な UTF-8 の置き換え、NUL の置き換え）の後の位置では、元のソースとずれる。
- **C. 両方を返す。** バイトの位置は、行の番号から元のソースをたどって求めれば、正規化の影響を受けない。

### Sidebar の 2 行目の読み上げ

- **A. 行の Value に入れる。** Value は既に `Count`（件数）が使っている。両方あると「3, 明日の件ですが…」のように混ざる。
- **B. 行の説明（Hint。UIA の HelpText、AT-SPI の description、NSAccessibility の help）に入れる。** 名前、値（件数）、説明の順に、それぞれ 1 度だけ読まれる。ARIA の aria-describedby にあたる。
- **C. 2 行目の文字をそのまま子のノードとして読ませる。** 行の名前と別に読まれ、`Count` を 1 度だけ読ませるようにした ADR 0127 と食い違う。

### 手順の表示の名前

- **A. `nav.Steps` を新しく作り、`control.Stepper` を `control.NumberStepper` に改名する。** 「stepper」で探すと両方が見つかり、名前を見ればどちらか分かる。未公開なので互換の層は作らない（ADR 0081 以降の方針）。
- **B. `control.Stepper` はそのままにし、両方の godoc から互いを参照する。** 変更は少ないが、名前だけでは区別が付かないまま残る。
- **C. 手順の表示を `nav.StepIndicator` とする。** 意味ははっきりするが長い。Ant Design の Steps、Mantine の Stepper のどちらで探しても、godoc の文（「stepper」「step indicator」を含める）で見つかるので、短い Steps でよい。

`semantics.RoleStepper` は改名しない。各プラットフォームでは spin button（UIA の Spinner、AT-SPI の SPIN_BUTTON、NSAccessibility の incrementor）であり、`field.NumberField` も使う役割の名前で、ウィジェットの名前とは別である。godoc にその旨を書く。

### 手順の読み上げ

- 一覧（`RoleList`、名前は既定で「手順」）の中に、手順ごとの項目（`RoleListItem`）を置く。位置は `PosInSet` / `SetSize` で渡し、「3 件中 2 番目」はプラットフォームの言葉で読ませる（UIA の PositionInSet / SizeOfSet、AT-SPI の posinset / setsize）。そのために `interact.Semantics` に `PosInSet` と `SetSize` を足す。
- 現在の手順と済んだ手順は、説明（Hint）に「現在の手順」「完了」を入れる。`Selected` は「選択」と読まれ、手順の意味と違うので使わない。丸の中の番号は位置と重なるので読ませない。
- 済んだ手順は `OnStepPress` があれば押せる（Tab で移動し、Enter か Space で押す）。先の手順は押せない。入力の済んでいない手順を飛ばせないのが、ウィザードの普通の作りだからである。押せない項目に `Disabled` は付けない（一覧の項目として普通の状態である）。

## 決定

- `editor.Editor` は、検索バーを開いている間、テキストの上の余白をバーの下端まで広げる（`padTop` = 4 + バーの分）。スクロールの位置、カーソルの位置からの逆算、描画、アクセシビリティの行の矩形、ページ送りの上限は、すべてこの余白を使う。スクロールしている途中で開閉したときは、その分スクロールの位置をずらし、画面上のテキストを動かさない。先頭にいるときはテキストが下がり、1 行目がバーの下から出る。一致を見せる処理は、一致の行をバーの下に置く。
- `markdown.Heading` に `Line`（1 から）と `Offset`（元のソースでのその行の先頭のバイト位置）を足す（案 C）。行の区切りは `\n`、`\r\n`、`\r` で、`editor.Editor` と同じ数え方である。setext の見出しはテキストの 1 行目（`===` や `---` の上）、HTML の見出しは `<h1>`〜`<h6>` のタグの行とする。段落の先頭のリンク参照定義を取り除いた setext の見出しは、定義の後の行から始まる。
- `collection.SidebarItem.Detail string` を足す。`Caption` の大きさ、`Ink2` で、`MaxLines: 1` で 1 行に切る。`Detail` があるときはラベルも 1 行に切る。行の高さは 46（20 と 18 の 2 行、上下 4）で、DESIGN.md の表に加える。スクリーンリーダーには説明（Hint）として全文を 1 度だけ伝え、文字そのものは読ませない（案 B）。
- 手順の表示は `nav.Steps{Labels, Current, OnStepPress, Label}` とし、`control.Stepper` を `control.NumberStepper` に改名する（案 A）。呼び出し元、カタログ、gallery、golden の場面、ドキュメントをすべて直し、古い名前は残さない。両方の godoc とカタログの説明から互いを参照する。見た目は直径 24 の丸と名前、太さ 2 の線。済んだ手順は `Accent` の丸に白いチェック、現在の手順は `Accent` の丸に白い番号と太字の名前、先の手順は `Fill` の丸と `Ink2` の名前。線は済んだ区間が `Accent`、先が `FillStrong`。高さは 30 で、与えられた幅いっぱいに広がり、線が残りを分け合う。`Current` が `len(Labels)` 以上なら全部済んだ表示になる。
- `basic.Strings` に `Steps`、`StepCompleted`、`CurrentStep` を足す（英語と日本語）。

## 結果

- 検索の一致はどの行でもバーに隠れない。テストは、現在の一致の矩形がバーの下端より下にあること（1〜3 行目と、スクロールでバーの下に来た行。置換の行がある場合も）、計算したバーの高さが実際の下端と一致すること、スクロール中に開いてもテキストが動かないことを確かめる。代償として、先頭にいるときはバーを開くとテキストが下がる。バーはエディタの右上にしか無いが、余白は幅いっぱいに取る（VS Code と同じ）。エディタの幅がバーより狭いとき、バーが左にはみ出すのは以前のままである。
- 目次から隣のエディタのカーソルを `editor.TextPosition{Line: h.Line - 1}` で動かせる。`Offset` は元のソースの位置なので、CRLF や不正な UTF-8 があってもずれない。テストは ATX、setext、フェンスの中と後、閉じないフェンス、引用と箇条書き、HTML、details、CRLF と CR を確かめる。
- Sidebar の行にチャットの「名前と最後のメッセージ」を置ける。カタログの Sidebar の例に `Detail` の行を加えた。`Count` と並べても、件数は値、2 行目は説明として別々に 1 度ずつ読まれる。NVDA、Narrator、Orca、VoiceOver が一覧の項目の説明をどの順で読むかは、実機では確かめていない。
- 手順の表示を自作する必要がなくなった。カタログに `nav.Steps` を加え、ガイドの「よく使う形」に購入手続きの例を足した。`control.NumberStepper` への改名でカタログの絵のファイル名も変わった。
