# 0102: DockLayout の自動で隠れる横の帯と入れ子のドック

決定日: 2026-11-13

状態: 採用

## 背景

ADR 0098 で `DockLayout` は分割、タブの群、ドラッグでのドッキング、閉じる、最大化、キーボード、JSON の保存と復元までを持った。範囲の外にした三つ（浮動パネル、自動で隠れる横の帯、入れ子のドック）のうち、オーナーから次の二つを頼まれた。

- **自動で隠れる横の帯。** パネルや群を端の細い帯に畳み、押すとレイアウトの上に滑り出る（VS の Auto Hide、JetBrains のツールウィンドウの帯）。
- **入れ子のドック。** パネルの中身が別の `DockLayout` のとき、どちらも正しく動くこと。

別の OS ウィンドウへの引き剥がしは引き続き範囲の外とする。

## 選択肢

### 帯から出たパネル（以下フライアウト）をどこに描くか

1. `widgets/overlay` の上に出す。`nav` は `overlay` を import してよい（ADR 0081 の 5 段は 4 段の上）。ただし、入れ子の内側のドックのフライアウトが外側のドックや窓全体を覆ってしまう。中身の State を保つには、パネルの中身をドックの外（オーバーレイ）に置き換えることになり、0098 §7 の「中身は部品自身のキー付きの子」が崩れる。
2. ドック自身の render object の子として、群の上に重ねて描く。

### 隠れたパネルの State

1. 帯に移ったら中身を作り直す。
2. 0098 §7 と同じく、パネル ID をキーにした部品自身の子のまま、置く場所（矩形）だけを変える。

### 入れ子の間のタブの移動

1. 内側と外側が同じ群（例: `DockLayout.Group`）を共有したら、タブを行き来させる。
2. 移動はドックの中に閉じる。入れ子は置けるが、タブはドックをまたがない。

## 決定

フライアウトは選択肢 2、State は選択肢 2、入れ子の移動は選択肢 2。

### 1. API（追加だけ）

- `DockLayout.AutoHide bool`。
  - 真なら各群の帯の右端にピンのボタンが付き、Ctrl+Alt+PageDown が効く。
  - ゼロ値は偽。今ある DockLayout の見た目とキーは変わらない（カタログの絵も変わらない）。
  - 偽でも、コントローラーの `Unpin` や保存から戻した配置で隠れたパネルは帯に出る。利用者はそれを開き、ピンで戻せる。
- `DockController` に次を足した。どれもゼロ値で呼んでよく、表示前は何もしない。
  - `Unpin(id string, side DockZone)`: パネルを `side` の端に隠す。`DockCenter`（端でない値）なら群に一番近い端。隠れているパネルなら帯を移る。
  - `UnpinGroup(id string, side DockZone)`: `id` を含む群を丸ごと隠す。
  - `Pin(id string)`: 元の群に戻す（§3）。
  - `Show(id string)`: フライアウトを出し、キーボードを渡す。隠れたパネルへの `Activate` も同じ。
  - `HideFlyout()`、`Flyout() string`。
- `DockArrangement.Hidden []DockHidden`。`DockHidden{ID, Side DockZone, Size float32, Origin []string, Share float32}`。
  - `Origin` は隠したときの群のパネル（自分を含む、並び順）。
  - `Share` は群が端に沿って占めていた割合。
- 文言 `Strings.AutoHide`（Auto-hide / 自動的に隠す）と `Strings.HiddenPanels`（Hidden panels / 隠したパネル）を構造体の末尾に足した。

### 2. 見た目と操作

- **帯。**
  - 隠れたパネルがある辺にだけ、幅 28 の帯が出る。左右は全高、上下は左右の帯の間。
  - 群の木は帯の内側に置き直す。帯が出る、消えるときだけ分割が詰め直る。フライアウトの出し入れでは詰め直らない。
  - 内側の辺にヘアラインを引く。
- **帯のタブ。**
  - 左右の帯では文字を 90° 回す。左は下から上、右は上から下（JetBrains と同じ）。
    - `layout.RenderTransform` はレイアウトを変えないので、`nav` に 4 分の 1 回転の render object（`renderDockTurn`）を足した。子を縦横を入れ替えた制約で置き、回した大きさを自分の大きさにする。
    - `core.Transformer` を実装するので、ポインタとスクリーンリーダーの矩形は回った絵に従う。文字は ADR 0044 のとおり鋭いまま。
  - 上下の帯は横書きのまま。アイコンがあれば題の前に出す。
  - 開いているタブは `FillStrong`、ポインタの下は `Fill` の地。
- **開く。**
  - タブを押して離す（または Enter / Space）と滑り出る。もう一度で隠れる。
  - **ホバーでは開かない。** フライアウトは中身を覆うので、帯の近くを通っただけで開くのは邪魔になる。遅延を付けても、タブのドラッグや帯の上の移動と区別しにくい。開く道は押す、キー、`Show` の三つにした。
- **動き。**
  - 出るときは 200ms の `motion.Standard` で端から滑る。`ReduceMotion` では即座に出る。
  - 隠れるときは即座に消す。閉じかけのパネルにフォーカスやポインタが入らないようにするため。
  - 滑る間も、矩形の大きさは変えずに位置だけを動かす。中身のレイアウトはやり直さず、Build もしない。
- **大きさ。**
  - 内側の辺に `kit.SplitHandle` の取っ手がある（区切りと同じ 9px、矢印キー、ダブルクリックで既定に戻る）。名前は「ペインの区切り」の `RoleSeparator`。
  - 大きさは `DockHidden.Size` に覚え、保存にも入る。
  - 範囲は最小が群の最小（幅 96、高さは帯 + 40）、最大は群の場所から 48 を残すまで。ゼロは群の場所の 30%。
  - 群から隠したときは、その群の幅（上下なら高さ）が最初の大きさになる。
- **隠れる。** Escape（タブにフォーカスを戻す）、外を押す、フォーカスが出る、タブをもう一度押す。
  - 外の押下は、ドックの render object がパスの先頭に入って見る（`Tooltip` と同じ手）。フライアウト、取っ手、帯の上は外に数えない。
  - フライアウトの中の何も取らない所を押しても、フォーカスは外れない（スロットが押下を取る）。
  - フォーカスの移動は、移った先が同じドックのフライアウトか帯なら隠さない。そのため、開いているタブを押すと閉じ、別のタブを押すと切り替わる。
- **ヘッダー。** 題、`Closable` なら ×、ピン。
- **ピンの意味。** チェックボックス（ツールバーのトグルと同じ形）で、名前は「自動的に隠す」。隠れている間はチェックされ、横倒しのピンの絵になる。群の帯では外れていて、立ったピンの絵。
- **キー。** 0098 の Ctrl+Alt+… にそろえた。
  - Ctrl+Alt+PageDown: 今の群の選択中のパネルを隠す。フライアウトの中なら、それを片付ける。
  - Ctrl+Alt+Shift+PageDown: 今の群を丸ごと隠す。
  - Ctrl+Alt+PageUp: 出ているパネルを元に戻す。
  - Home / End は RDP クライアントの Ctrl+Alt+End（リモートの Ctrl+Alt+Del）と Ctrl+Alt+Home に取られるので避けた。PageUp / PageDown は文字を出さず、AltGr の配列とも衝突しない。
  - フライアウトの中では、Ctrl+W / Ctrl+F4 がそのパネルを閉じる。Ctrl+Tab などは移る先が無いので何もしない（下の帯の TabBar に流れないように取る）。
- **ドラッグ。** 0098 の `dropper` の口だけで足りた。TabBar に手は入れていない。
  - 群のタブを既にある帯の上で放すと、そこに隠れる。プレビューは帯を覆う。
  - 帯のタブはそれ自体がドラッグを持つ（4px の遊びの後）。群の上なら加える、群の辺なら分割、ドックの端なら端に置く。プレビューと判定は群のタブと同じ `dropAt` を使い、Escape で取り消す。
  - 帯の無い辺へ落として新しく帯を作ることはできない。ボタン、キー、`Unpin` を使う。
- **Semantics。**
  - 帯は「隠したパネル」の `RoleTabList`、タブは `RoleTab`（開いていれば Selected）。
  - フライアウトの中身は、群と同じく題を名前にした `RoleGroup`。

### 3. 元に戻す規則（Pin）

- 一緒に隠したパネル（`Origin` が等しいもの）は一緒に戻る。`UnpinGroup` で隠した群は、どれか 1 枚を戻すと群ごと戻る（VS と同じ）。
- 戻り先は、`Origin` のパネルのうち木に残っている最初のものの群。並びは `Origin` の順を保つ位置に差し込む。
- 元の群が残っていなければ、隠れていた辺に沿って全体の端に置く。割合は `Share` を 0.1〜0.6 に収めたもの（無ければ 1/4）。
- 木が空（全部隠れた）なら、根の空の群に入る。
- 戻すと最大化は解け、そのパネルが選ばれて今の群になる。キーボードもそこへ移る。

### 4. State の保持

0098 §7 を広げた。隠れたパネルの中身も、パネル ID をキーにしたドック自身の子のままにする。

- 群にあるときは群の矩形へ、隠れたときはフライアウトの矩形へ置く。子の並びの中で場所が変わるだけで、キーが同じなので要素は残る。
- 出ていない間は `core.Hider` で隠し、ポインタ、Tab、スクリーンリーダーから外す。
- 一度も出していない隠れたパネルは作らない。群で表示済みなら作ったまま。
- 出ていない隠れたパネルは、自分が出るときの矩形に置いておく。出るときに中身のレイアウトをやり直さない。
- テストで、隠す、出す、戻す、帯からドラッグで群へ移す、の各操作の後も同じ State であることを確かめた。

### 5. フライアウトの重なり

- フライアウトの部品（地とヘッダー、中身、取っ手）は、子の並びの最後（キーの子の前）に置く。そのため群、帯、区切りより上に描かれ、先に当たる。
- 描くときは、群の場所（帯の内側）で切る。滑り出る途中も帯の上には出ない。影は内側にだけ落ちる。
- 入れ子の内側のドックのフライアウトは、内側のドックの中に描かれ、そこで切られる。外側のドックやほかのパネルを覆わない。内側のドックのパネルが外側の場所を使えないのと同じ。

### 6. 保存の形式

```json
{"version":1,
 "root":{…},
 "hidden":{"right":[{"id":"outline","size":240,"origin":["outline"],"share":0.2}],
           "bottom":[{"id":"a","origin":["a","b"]},{"id":"b","origin":["a","b"]}]}}
```

- **版は 1 のまま。** 0098 §5 の方針どおり、知らないキーは読むときに無視する。
  - 古い読み手は `hidden` を読み飛ばし、隠れたパネルを新しいパネルとして今の群に入れる。配置は失うが、パネルは失わず、誤読もしない。
  - 新しい読み手は、`hidden` が無ければ隠れたパネルが無いとみなす。今ある版 1 の保存はそのまま読める。
  - 版を 2 にすると、古い読み手は `ErrDockVersion` で保存全体を捨てることになり、かえって悪い。
- 辺は `left` / `right` / `top` / `bottom` の名前で、その中の順が帯の上の順。知らない辺は無視する。
  - JSON のマップには順が無いので、読むと辺の順（左、右、上、下）に並べ直す。2 度目の往復で文字列は変わらない。
- 復元は 0098 と同じく寛容にした。
  - 知らない ID は捨てる。木と帯の両方にある ID は木を優先する。帯で重複したものは最初の 1 つ。
  - 端でない `Side` は左とみなす。
- フライアウトが出ているかどうかは保存しない（その場の状態）。

### 7. 入れ子のドック

- **独立。** 各 `DockLayout` は自分の `DockController`、`TabGroup`、配置を持つ。
  - 外側の保存は内側を含まない（内側は外側にとって 1 枚のパネルの中身）。
  - アプリはそれぞれを保存する。ギャラリーは `{"outer":…, "console":…}` にまとめた。
- **キー。**
  - 各ドックのキーは、全体を包む `ShortcutTarget` と、大きさ 0 の最後の子の二箇所で受ける（0098 §3）。これを次のように絞った。
    - 包む側は `FocusWithinListener` を兼ね、フォーカスが中にあるかを知る。
    - 他の DockLayout の中にあるドック（render object の祖先に `renderDock` があるもの）は、フォーカスが中にあるときだけ包む側で受ける。最後の子では受けない。
    - 一番外のドックは今までどおり両方で受ける。
  - core は、フォーカスの上の `ShortcutTarget` に近い順で聞き、取られなければ残りに描いた順の逆で聞く。そのため次のようになる。
    - **フォーカスが内側にある**: 内側が先に聞かれる。内側が使わないキーは外側の包む側へ流れる。
    - **フォーカスが外側（内側の外）にある**: 外側だけが受ける。外側が使わないキーが内側へ流れることはない。
    - **どちらの外**: 一番外のドックの最後の子が受ける。内側は受けない。
  - 一つの押下で二つのドックが動くことは無い。最初に true を返した方で止まる。
  - **流れるキー**（内側では何も起きないとき、外側へ）:
    - Ctrl+Alt+矢印で、内側にその方向の群が無い（内側が最大化中も含む）。外側が内側のパネルを持つ群から隣へ移す。
    - Ctrl+Alt+Enter で、内側の群が 1 つだけで最大化するものが無い。外側の最大化になる（単独のドックでも、何もしないときは false を返すようにした）。
    - Ctrl+Alt+PageDown で、内側の `AutoHide` が偽。Ctrl+Alt+PageUp で、内側にフライアウトが無い。
    - Escape で、内側にフライアウトもドラッグも無い。
    - 内側の今の群が空。
  - **流れないキー**（内側で取る）:
    - Ctrl+Tab、Ctrl+PageUp / PageDown（と Shift）、Ctrl+W / Ctrl+F4。閉じられないパネルの Ctrl+W も取る。外側のパネルを閉じるのは驚きになる。
    - Ctrl+Alt+Shift+矢印。パネルはドックをまたげないので、外側のパネルを代わりに動かすのは驚きになる。
- **ポインタ。**
  - タブのドラッグは、始まったドックの中に閉じる。
    - TabBar の `barAt` は同じ `TabGroup` の帯しか見ない。
    - `dropper` はそのドックの `dropAt` しか聞かない。
  - そのため、落とす場所の優先は自然に決まる。
    - 内側のタブには内側の端と群の場所だけがある。外側の場所は見えない。
    - 外側のタブには外側の場所だけがある。内側のドックの上は「内側を持つ外側の群」の中央や辺になる。
  - 内側のドックが外側の端に接していても、24px の端の帯は各ドック自身の端として働く。
    - 内側のタブは内側の端、外側のタブは外側の端。
    - 二つが同じドラッグで競うことは無い。
- **最大化。** 内側の群の最大化は内側の中で起きる。帯のダブルクリックも内側の帯が取るので、外側には届かない。
- **見た目。** 内側のドックは自分の帯の地を `Canvas` で塗る。外側の群の地（Card）の上でも、選ばれたタブが浮いて見えるようにするため。一番外のドックの描き方は変わらない。
- **ドラッグ中に内側が消える。** 内側の TabBar の `Dispose` がドラッグを取り消し、`tabDragEnded` は描くだけなので安全に片付く。帯のタブも `Dispose` で自分のドラッグを終える。テストした。

### 8. 入れ子の間のタブの移動はしない

内側と外側の間でタブを移す機能は入れない。値型の Widget のままでは健全に作れない。

- パネルの中身の State は、そのドックの render object の下のキー付きの子として残っている（0098 §7）。
- core にはグローバルキー（親をまたいだ要素の付け替え）が無い。別のドックへ移すと、中身の State は必ず作り直しになる。エディタの文字やスクロール位置が消える。
- これは 0098 の「群を移っても State を保つ」という約束を破る。
- 加えて、パネルの持ち主（`Panels` の並び）は利用者だ。移動は「片方から消し、片方に足す」をアプリに頼むコールバックになる。その間の 1 フレームは、どちらのドックにも無い、または両方にある状態が生まれる。
- 最小の契約でも、State を失う移動を「動く」とは言えない。

必要なら、アプリが `OnClose` と `Activate` で、片方を閉じてもう片方で開く操作を自分で組める（State は作り直し）。core にグローバルキーが入ったら見直す。

### 9. ホットパス

- **フライアウトの取っ手のドラッグ。** 区切りと同じく Build をせず、`DockHidden.Size` を書き換えてレイアウトだけをやり直す。
- **題の文字。** ヘッダーの題は、幅が変わるたびに整形し直すとアロケーションする。そのため、自分の幅で一度だけ置いて切る `renderDockLine` に入れた。
- **滑る動き。** `AnimationController` の `OnChange` は `MarkNeedsLayout` だけ。
- **確認。**
  - `TestDockLayout_ResizingAFlyoutDoesNotAllocate`（1000 フレームで 0 回）。
  - `BenchmarkDockLayout_ResizeFlyout_5Panels` を足した。
  - 既存の区切りのテストも 0 回のまま。

## 結果

- 追加だけ。既存の公開 API、JSON、`AutoHide` が偽のときの見た目と動きは変わらない。
  - 既存のドックのテストは変えずに通る。ハーネスに `autoHide` と `motion` の欄を足しただけ。
  - カタログの DockLayout の絵は変わらない（`AutoHide` も入れ子も使っていない）。
- 共有ファイルへの変更は、`widgets/basic/strings.go` と `strings_tables.go` の末尾に足した 2 語だけ。TabBar には手を入れていない。
- テストは GPU 無しで通る（docklayout_autohide_test.go、docklayout_nested_test.go、docklayout_bench_test.go）。
  - 対象: 隠すと戻すの往復、群ごとの往復、フライアウトの開閉の全経路、大きさの記憶と範囲、State の保持、フライアウト中のパネルの増減、JSON（新しいキーの有無、古い版 1、知らない辺）、帯へのドラッグと帯からのドラッグ、キーボード、ゼロ値。
  - 入れ子: フォーカスが内側、外側、どちらの外のときのキーの行き先、ドラッグの閉じ込め、端の優先、内側での最大化、別々の保存、ドラッグ中に内側が消える場合。
- ギャラリーのドックの頁に、右の帯に隠れたアウトラインと、ドックを持つコンソールのパネルを置いた。保存、復元、初期配置は両方のドックに効く。
- 残り:
  - 帯の無い辺へドラッグで新しく帯を作ること。
  - ホバーで開くこと（入れるなら、遅延と、ドラッグ中は開かない規則と一緒に）。
  - 隠れるときの動き。
  - 実機のスクリーンリーダーでの確認。
  - 0098 の残りはそのまま。
