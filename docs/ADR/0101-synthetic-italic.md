# 0101: 合成の斜体（斜体の書体が無いフォントを傾けて描く）

決定日: 2026-11-13

状態: 採用

## 背景

ADR 0099 の「残したこと」の 1 行目。入れ子のモジュール `markdown/` は `*強調*` を `text.Style.Italic` で表すが、既定の日本語フォント（Yu Gothic / Noto Sans CJK JP / Hiragino Sans / Meiryo）には斜体の書体が無く、和文のフォールバックフォントにも普通は無い。fontscan は斜体を求められても立体の書体を返すので、強調が地の文と同じ見た目になっていた。

調べたこと:

- `Style.Italic` は `Shaper.selectFacesFor` で fontscan の `Aspect.Style` に渡るだけ。合成の斜体も合成の太字も、テキスト層には無かった。
- グリフの画像はすべて `text.Atlas` が CPU で作る（輪郭は `rasterize`、カラーは `rasterizeColor`）。`render.encodeRun` が `text.GlyphKey{Face, ID, Size, Subpixel, Sideways}` でアトラスを引き、gpu/soft・D3D11・Vulkan・Metal はその画像を貼るだけ。バックエンドごとの字形の処理は無い。
- `FaceID` は `Shaper.faceID` が `*font.Face` ごとに配る番号で、アトラスのキャッシュは `GlyphKey` 全体で引く。

## 決定

### 1. 傾けるのはアトラスの輪郭。合成の斜体は別の `FaceID`

- 斜体を求められた run の書体が斜体でなければ、その書体に**もう 1 つの `FaceID`（合成の斜体）**を配る。`Shaper.faces` には同じ `*font.Face` が入り、並行する `Shaper.slanted` がその ID に印を付ける。書体ごとの答えは `Shaper.obliqueIDs` に覚える（`Shaper.italicFaceID`）。
- `Atlas.rasterize` は印の付いた ID の輪郭を、ベースラインを軸に `x' = x + 0.2126·y`（フォント単位、y は上向き）でずらしてから画素に移す。`Sideways` の回転はその後。
- `GlyphKey` の `Face` が違うので、同じ書体の立体と合成の斜体の画像がキャッシュで混ざることは無い。`GlyphKey`・`paint.GlyphRun`・`render`・`gpu` のどれにもフィールドを足していない。どのバックエンドもアトラスの同じ画像を貼るので、soft・D3D11・Vulkan・Metal で同じに傾く。シェーダーにも、`paint` の変換にも手を入れない。
- グリフごとのアフィン（`paint` で run に変換を掛ける）は採らなかった。アトラスの画像は軸に揃った矩形として貼られるので、変換を掛けると全部のグリフがサブピクセルの段とは別の経路（変換付きのインスタンス）を通り、立体の文字と画素の作り方が変わる。輪郭の段階で傾ければ、ヒンティングを持たない今の経路（被覆の計算、4 段のサブピクセル）がそのまま使える。
- 判断は**解決した書体ごと**。fontscan が run ごと・クラスタごとに選んだフォールバックの書体（和文の書体、欧文の書体、記号の書体など）を `out.Face` で見て、それぞれ決める。斜体かどうかは OS/2 の `fsSelection`（italic / oblique のビット）を `font.Font.Describe` で読む。本物の斜体の書体があれば、今までどおりそれを使い、傾けない。

### 2. 傾きは tan 12° = 0.2126

FreeType の `FT_GlyphSlot_Oblique` と同じ値（0x0366A / 0x10000）。Skia の合成斜体は 0.25（約 14°）だが、和文の字は em の箱いっぱいに広がるので、14° だと上端のはみ出しが大きく、漢字が倒れて見える。欧文の本物の斜体の多くは 9°〜12° で、12° なら欧文と和文が混ざった強調も揃って見える。定数は `text` の非公開の `obliqueShear`。

### 3. 傾けないもの

| 場合 | 決定 | 理由 |
|---|---|---|
| 縦書き（`Orientation: Vertical`） | 傾けない（横倒しの欧文も含む） | 縦組の強調は傍点や書体の切り替えで表すのが慣習で、字を傾ける組み方は一般的でない。行の向きに合わせて縦に傾ける（CSS の synthesized oblique が縦書きで行う形）には、立てた字と横倒しの字で軸を変える必要があり、今回の範囲を超える。縦書きでも本物の斜体の書体があれば、横倒しの欧文はそれで描かれる（今までどおり） |
| カラー絵文字（COLR / sbix / CBDT） | 傾けない | 絵文字は絵で、傾けると形が崩れる。絵文字のクラスタ（`isEmojiCluster`）は合成の ID を受けない。ほかのクラスタがカラーの字形に当たっても、カラーの経路（`rasterizeColor`）は傾けないので立ったまま |
| 右から左の run（アラビア文字、ヘブライ文字など） | 傾けない | アラビア文字の斜体は左へ傾ける流儀や傾けない流儀があり、右へ傾けるのは誤り。ヘブライ文字も斜体を使う習慣が薄い。shaping の run の向きが RTL なら合成しない。同じ段落の中の欧文（LTR の run）は傾く |
| ルビ | 親文字に従う | ルビは親文字のスタイル（`Italic` を含む）を受け継ぐので、横書きでは一緒に傾く。ルビ自身はルビのベースラインを軸に傾くので、そのままだと傾いた親文字の上端より左に寄る。親文字が合成の斜体なら、ルビの原点を `0.2126 × rubyLift × 親文字の大きさ` だけ右へずらし、傾きの線の上に置く。本物の斜体の親文字のルビは今までどおり |

### 4. 計量、キャレット、選択、線

- **送り（advance）は変えない。** 行分割、両端揃え、ヒットテスト、`Layout.Size` は立体と同じ。
- **キャレットと選択の矩形は立てたまま。** 字の送りの境に縦の線と矩形を置く。傾けたキャレットは本物の斜体でもプラットフォームによって違い（macOS は立てる）、合成の斜体だけ傾ける理由が無い。
- **下線と取り消し線は水平のまま。** テキスト層は線を描かず、描く側（markdown の `richText` など）は行の矩形から水平な線を引く。
- **はみ出し**: 上端は最大で約 0.2em 右へ、ディセンダーは約 0.05em 左へ出る。`GlyphRun.Bounds` は送りの両側に 1em ずつの余白を持つので、カリングで切られない。レイヤーの範囲は render がエンコードしたインスタンスから測るので、傾いた画像の幅がそのまま入る。`Text` / `RichText` はクリップしない。スクロールでクリップする入力欄などで最後の字の右上が切れうるのは、本物の斜体のフォントでも同じ。

### 5. 決定性とホットパス

- 傾ける式は `p.X + float32(obliqueShear*p.Y)`。積を明示的に丸め、arm64 で FMA に融合されないようにした（ADR 0086）。ヒンティングは無く、サブピクセルの段は今までどおり `render.encodeRun` が決める。
- 斜体でない文字: shaping で run ごとに bool を 1 つ見るだけ。`FaceID` の配り方、`GlyphKey`、ラスタライズの式は 1 ビットも変わらない（`gx = p.X` のときの `gx * unit` は元の `p.X * unit`）。アトラスのヒットの経路は変えていない。
- 斜体の文字: 書体ごとの初回に `Describe`（名前の表を読むので割り当てあり）とマップへの登録が 1 回。描画はアトラスにある限り割り当てない。

## 含めなかったもの

- **合成の太字。** テキスト層に無く、今回も足さない。太さを持たないフォントの `Weight` は、今までどおり fontscan が近い書体を選ぶだけ。
- 縦書きでの合成の斜体（上の表）。
- 可変フォントの `slnt` / `ital` 軸を `Italic` から動かすこと。今は軸を持つ書体でも、`fsSelection` が立体なら合成する。
- 傾きの角度を利用者が変える口。

## 互換

- 公開 API は増やしていない（`Style.Italic` の意味が「見える」ようになっただけ）。
- `Italic` を指定しない文字、本物の斜体の書体を持つフォントの `Italic` の文字は、画素が変わらない。既存の golden は再生成せずに全部通る。
- 斜体の書体を持たないフォントの `Italic` の文字だけが傾く。本体（examples、ギャラリー、カタログ）で `Italic` を指定している箇所は無かった。

## 結果

- `text/italic_test.go`: Go Regular（斜体なし）の「Hill」が傾く（上 4 分の 1 のインクが下 4 分の 1 より 3 画素以上右へ出る。立体は 1 画素以内）、インクの上下の行と送り・キャレット・選択の矩形が立体と同じ。Go Regular と Go Italic を並べると Go Italic がそのまま使われる。縦書きは傾かない。ルビが傾きに沿って動く。斜体の描画のアトラスのヒットが 0 アロケーション。システムのフォントで「日本語 abc」の漢字・かな・欧文がすべて傾き、絵文字と RTL（ヘブライ文字・アラビア文字）は傾かず、隣の欧文は傾く。
- golden に新しい場面 `italic` / `italic-dark` を最後に足した（立体と斜体の文、折り返す斜体の段落、斜体のルビ、40px の「Hill」、斜体の入力欄の選択とキャレット）。既存の PNG は変えていない。
- `markdown/` の `TestMarkdown_EmphasisIsVisible`: 既定のフォントで `*強調された日本語*` などが地の文と違う画素になり、大きさは同じ。
