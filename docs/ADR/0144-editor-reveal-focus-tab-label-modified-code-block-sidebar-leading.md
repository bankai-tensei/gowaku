# 0144: 表示前のエディターの選択とフォーカス、タブの名前と未保存の印、コードブロックの差し替えとコピー、サイドバーの行頭

決定日: 2026-11-17

状態: 採用

## 背景

初めて使う人に、IDE、チャット、メールのクライアントを作ってもらったところ、次の 4 つが見つかった。

1. **表示前の View の選択がスクロールしない：** `editor.View.SetSelection` の godoc は、キャレットが見える所までスクロールすると書いている。しかし、まだどの `Editor` も表示していない View に呼ぶと、選択は残るが、表示された最初のレイアウトでキャレットの所へスクロールしなかった。「ファイルを開いて 34 行目へ飛ぶ」が、ファイルの先頭を表示した。View が前に表示されたことがあると、そのときの位置（`keepPlace`）に戻り、やはりキャレットは見えなかった。`Controller.SetSelection` を、どのエディターも表示していない間に呼んだときも同じだった。また、エディターにコードからフォーカスを渡す公開の手段が無かった（`field.InputController.Focus` に当たるものが無い）。
2. **タブの名前の付け方が揃っていない：** `nav.TabItem.Title` と `control.TabPage.Label` は、どちらもタブに表示し、スクリーンリーダーに名前として渡す文字列なのに、名前が違った。保存していない文書の印も無く、メモのアプリは題名の前に「• 」を足していたので、スクリーンリーダーはそれを題名の一部として読んだ。
3. **Markdown のコードブロックに手を入れられない：** チャットの UI がコードブロックに Copy ボタンを付けようとしたが、描き方を差し替える口も、公開の構文木も無かった。返事を流しながら表示するときは、閉じのフェンスがまだ来ていないコードブロックが書きかけだと分かる手段も要る。
4. **サイドバーの行頭に色の点を置けない：** メールのクライアントで、ラベルの色の点を `collection.SidebarItem` の行頭に置けず、行を自分で作り、選択中の見た目（ADR 0138 の `OnTint`）も写す必要があった。

## 選択肢

### 表示前の選択

- **A. View に「次に表示されたときにキャレットを見せる」印を持たせる。** 表示されていない View の `SetSelection` が印を立て、エディターが View を表示する最初のレイアウトで、今あるキャレットへのスクロール（`reveal`）に渡す。前に表示されたときの位置は、その後の `SetSelection` に負ける。`SetScroll` は、表示中の View と同じく、キャレットより優先する。`Controller.SetSelection` も、どのエディターも表示していない間は、最初に選択を受け取る View に同じ印を渡す。
- **B. `SetSelection` の中で行の高さから位置を計算し、`SetScroll` として保存する。** 折り返しや行の高さは表示するエディターが決めるので、表示前には計算できない。

ファイルを読み込んだ直後（表示中のエディターで `SetText` の後に `SetSelection`）は、`SetText` が行の表を作り直した後のレイアウトでキャレットを見せるので、今のままで動く。テストで確かめる。

### コードからのフォーカス

- **A. `View.Focus()` と `View.Focused()`。** フォーカスはエディター 1 つに付くもので、エディターごとに View が 1 つある。`Controller` は複数のエディターに共有されるので、どれにフォーカスを渡すかが決まらない。`field.InputController.Focus` と同じく、レイアウトの後なら今すぐ、前なら次のレイアウトで渡す。
- **B. `Editor.Autofocus`。** 最初の表示のときにしか使えず、「検索を閉じたら本文へ戻す」ような後からの移動ができない。

### タブの名前

- **A. 両方を `Label` にする。** gowaku では、操作する部品の名前（スクリーンリーダーに渡る名前を兼ねる文字列）は `Label`（`Button`、`SidebarItem`、`Action`、`Pressable` など）で、`Title` は見出しを描く物（`Dialog`、`Group`、表の列、ウィンドウ）である。タブは操作する部品なので `Label` に揃える。`nav.DockPanel.Title` はパネルの見出しなので、そのままにする。
- **B. 両方を `Title` にする。** `Label` の方が広く使われていて、変える所も多い。

### 未保存の印

- **A. `TabItem.Modified bool`。** よくあるエディターと同じく、閉じるボタンの場所に点を描き、ポインターがタブの上に来ると閉じるボタンに戻す。選択中のタブでも点を描き、その点は閉じるボタンとして押せる。`Permanent` のタブは点だけを描く。スクリーンリーダーには、タブの値として `Strings.Modified`（「Modified」、「未保存」）を渡す。
- **B. semantics に新しい状態（Modified）を足す。** プラットフォームの側に対応する状態が無く（UIA にも AT-SPI にも共通の物が無い）、値の方がどの読み上げでも聞こえる。

### コードブロックの口

- **A. `Markdown.CodeBlock func(c CodeBlock) core.Widget`。** `CodeBlock` は `Lang`、`Info`、`Code`（Source の通り、タブを含む）、`Open`（閉じのフェンスが無い）、`Default`（Markdown が描く物）を持つ。nil を返すと `Default` を使う。`ImageProvider` と同じ形で、引数が 2 つを超えるので構造体にした（CODING_STYLE §5.1）。
- **B. `func(lang, code string, def core.Widget) core.Widget`。** `Open` や `Info` を足すと引数が増え続ける。
- **C. 構文木を公開する。** 公開する型が大きく増え、内部の作りを変えられなくなる。

### Copy ボタン

- **A. `Markdown.CopyButton bool`。** 小さく、チャットでは最もよく要る物なので、組み込む。各コードブロックの上の行（言語名の行）の右端に、`control.Button`（Quiet、Small、`icons.Copy`、`Strings.Copy`）を置き、押すとコードを Source の通りに（タブを含めて）クリップボードへ書く。書く経路は ADR 0137 の通り、窓の `Host` の `SetClipboardText` で、`gowakutest` の Tester ではそのクリップボードに入る。
- **B. 口だけを用意し、ボタンはアプリに作らせる。** よく要る物を毎回書かせることになる。

### 書きかけのフェンス

CommonMark では、閉じのフェンスの無いフェンス付きコードブロックは、文書（または入れ物）の終わりまで続く。今の解析もそうなっていて、Source の終わりまでがコードとして描かれる。足りなかったのは、それが書きかけだと分かる手段だけなので、解析で閉じのフェンスを見つけたかどうかを持ち、`CodeBlock.Open` で渡す。

### サイドバーの行頭

- **A. `SidebarItem.Leading core.Widget`。** `Icon` の代わりに行頭に置く。選択中の行では `basic.Theme{Data: th.OnTint()}` の下で作るので、テーマの色を使う部分は色合いの上で読め、点のように自分で決めた色はそのまま残る。点のほか、アバターなども置ける。
- **B. `IconColor geom.Color`。** 色の付いたアイコンは描けるが、点の形のアイコンが無く、点を描くにはアイコンを足す必要がある。点以外の物も置けない。

## 決定

- 案 A。`editor.View` に表示前の選択の印を持たせ、表示する最初のレイアウトでキャレットを見せる。前に表示されたときの位置はその後の `SetSelection` に負け、`SetScroll` はキャレットに勝つ。`Controller.SetSelection` も、どのエディターも表示していない間は同じにする。godoc に書く。
- 案 A。`editor.View.Focus()` と `View.Focused()` を足す。表示前に呼ぶと、表示されてレイアウトされたときに渡す。
- 案 A。`nav.TabItem.Title` を `Label` にする。中の使い手（`DockLayout`、例、カタログ、golden の場面、テスト）を直す。`control.TabPage.Label` に godoc を付ける。
- 案 A。`nav.TabItem.Modified` と `basic.Strings.Modified` を足す。メモのアプリはタブの「• 」をやめて `Modified` を使う（ウィンドウの題名には今まで通り「• 」を付ける）。カタログの TabBar の絵に未保存のタブを入れて描き直した。
- 案 A。`markdown.Markdown.CodeBlock`、`markdown.CodeBlock`、`Markdown.CopyButton` を足し、`Markdown` の godoc に流しながら表示するときの書きかけのコードブロックのことを書く。
- 案 A。`collection.SidebarItem.Leading` を足し、カタログの説明に書く。

## 結果

- 「ファイルを開いて 34 行目へ飛ぶ」が、表示前に `View.SetSelection` を呼ぶだけで動く。テストは、表示前の `View.SetSelection` と `Controller.SetSelection` の後の最初のレイアウトで、その行とキャレットが見えること、タブを切り替えて隠れている間の選択が前の位置に勝つこと、その後の `SetScroll` は選択に勝つこと、表示中のエディターで `SetText` の後に `SetSelection` するとその行が見えることを確かめる。修正を外すとこれらが失敗することも確かめた。
- `View.Focus` のテストは、表示前に呼ぶと表示されたときにフォーカスが付き、別のエディターに移った後に呼ぶとすぐに戻り、その View が主の View になることを確かめる。
- `TabItem.Title` は無くなった。gowaku はまだ公開していないので、互換のための別名は置かない。
- `Modified` のテストは、選択中、選択していない、`Permanent` のタブの 3 つに点が描かれ、値が「Modified」になること、ポインターを載せると点が閉じるボタンに変わって押すと閉じること、選択中のタブの点が閉じるボタンとして働くこと、印の無いタブには値も点も無いことを確かめる。
- Markdown のテストは、Copy ボタンがコードブロックごとに 1 つあり、押すとタブを含むコードがクリップボードに入ること、`CopyButton` が無ければボタンが無いこと、`CodeBlock` で `Default` を包んでアプリのボタンを足せること、nil を返すと元の描き方になること、フェンスだけ、言語名まで、行の途中、リストの中など、書きかけの 5 つの形が `Open` でコードとして描かれ、閉じたものと字下げのコードブロックは `Open` でないことを確かめる。
- `Leading` のテストは、選択中の行でも点の色が変わらず、テーマの色を読む行頭は選択中の行で `OnTint` の色を受け取ること、点の行の高さがアイコンの行と同じで、点が読み上げの項目を増やさないことを確かめる。
- `Strings.Modified` を設定しない言葉の表は、ほかの言葉と同じく英語の「Modified」を使う。
