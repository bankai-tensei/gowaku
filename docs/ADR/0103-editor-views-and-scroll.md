# 0103: エディターのビュー、スクロール位置の読み書き、横のスクロールバー、斜体の飾り

決定日: 2026-11-13

状態: 採用

## 背景

読み取り専用のコードビューアーと差分ビューアーを作っているアプリから、`widgets/editor` に 4 つの要望が来た。

1. **一つの文書を複数の Editor で同時に見せたい（要望 5）。** 今の `Controller` は `view *renderEditor` を 1 つだけ持ち、2 つ目の Editor を付けると 1 つ目が通知を受けなくなる。選択も Controller に 1 つしか無い。
2. **スクロール位置を読み書きし、変わったら知りたい（要望 2）。** 差分の左右のペインを同期する、タブを切り替えたときに位置を戻す、に使う。今は `ScrollState` が Editor の State の中にあり、外から触れない。
3. **折り返さないときの横のスクロールバー（要望 1）。** ADR 0061 の「残り」の 1 つ。横へはキャレットとホイールでしか動かなかった。
4. **飾りに斜体（要望 7 の残り）。** `Decoration` には `Bold` しか無い。合成の斜体は ADR 0101 でテキスト層に入った。

## 1. ビュー: 文書は Controller、選択とスクロールは View

### 選択肢

| | 内容 | 判断 |
|---|---|---|
| A. Controller を Editor ごとに複製し、編集を互いに流す | 履歴と検索が二重になり、Undo がどちらの履歴か分からない | 採らない |
| B. Controller に選択の配列を持たせ、Editor 側の番号で引く | 番号の寿命（Editor が消えたら詰めるのか）が利用者に漏れる | 採らない |
| C. 選択とスクロールを持つ値 `View` を作り、Editor に渡す | `Controller` と同じ「State に置く、ゼロ値で使える」型が 1 つ増えるだけ | **採る** |

### 決定

- 新しい型 `editor.View`（ゼロ値で使える。State に置く）。持つものは選択（anchor と caret）、スクロール位置、`OnScroll`。`Editor.View *View` で渡す。nil なら Editor の State が自分の View を持つので、1 つの Editor だけのアプリは何も変えなくてよい。nil の Editor を 2 つ並べても、それぞれ自分の選択を持つ。
- Controller が持つのは文字、履歴、検索、飾りの世代（`decoGen`）と、付いている View の並び（`views`）。今まで `c.view.xxx()` だった通知はすべて、付いている全部の View の描画オブジェクトに送る（行の変更、`SetText`、検索、`Redecorate`）。
- **Controller の選択のメソッドは「主の View」に効く。** `Selection` / `SetSelection` / `SelectedText` / `Insert` / `Replace` / `Undo` / `Redo` / `FindNext` / `FindPrevious` / `ReplaceMatch` / `ReplaceAll` / `CurrentMatch`。主は、利用者が最後にフォーカスした、押した、打った、スクリーンリーダーで操作した View で、それより前は最初に付いた View。1 つの Editor なら今までと同じ意味になる。特定の View を選ぶには `View.SetSelection` を使う（主を変えない）。
  - 案として「Controller の選択は全部の View に効く」も考えたが、差分ビューアーで左を選ぶと右の選択まで動いてしまう。
- **編集は、主でない View の選択をずらす。** `splice` で、編集の前の位置はそのまま、後ろの位置は既存の `shiftPos` でずらし、編集に飲まれた位置は新しい文字の後ろへ。主の View は、今までどおり呼んだ側（`replace` / `Replace` / `Undo` など）が置く。
- **編集はほかの View のスクロールを同じ文字に留める。** 描画オブジェクトは `linesChanged` で、行の数を変える前の行表から今の位置（行とその中のずれ）を取り、編集がその行より上なら行番号を足し引きして覚え（`anchorPos`）、次のレイアウトでそこへ跳ぶ。上の行が消えて先頭の行も消えた場合は、編集の最初の行の頭に置く。これは主の View にも効く（下の「互換」）。キャレットを追うのは主の View だけで、ほかの View は `OnChange` を受けて描き直すだけ。
- **View は同時に 1 つの Editor にしか出ない。** 2 つの Editor に同じ View を渡すと、後から付いた方が View を取り、取られた方が次のレイアウトか描画で `panic("gowaku: an editor.View shows in two Editors at once; ...")` する。付けた時点で panic しないのは、reconcile がキー付きの古い子を新しい子の後で外すことがあり（`updateChildren` の最後）、同じ View を新しい Editor へ移すだけの正しい使い方まで止めてしまうため。
- **View は見えない間も選択と位置を覚える。** 描画オブジェクトが外れるとき（Editor が消える、別の View に替わる）に位置を `pending` に移し、同じ Controller に付き直したらそこへ戻る。タブごとに View を 1 つ持てば、タブの位置が戻る。別の Controller に付いたら、その文書の選択と先頭から始める（位置は文書に属するため）。一度も付いていない View に `SetSelection` / `SetScroll` したものは、最初に付いたときにそのまま使う。最初に付く View が選択を持っていなければ、文書がすでに持っていた選択（Editor が無い間に `SetSelection` されたもの）を引き継ぐ。最後の View が外れると、その選択が文書に戻る。
- **検索は文書に 1 つ。** 一致は全部の View で塗る。「今の一致」の枠は View ごとに、その View の選択と同じ一致に引く。検索バーは Editor ごとにあり、検索バーのボタンやキーは、まずその Editor の View を主にしてから `FindNext` などを呼ぶので、一致が選ばれてスクロールするのは検索バーを操作した方の Editor。ある Editor の検索バーで検索すると、ほかの Editor の検索も置き換わる（検索は 1 つ）。どれかの検索バーを閉じると、検索は終わる。
- アクセシビリティ（`editor_semantics.go`）は View ごと。選択の位置、窓（キャレットの周り）、`SetSelection` / `SetValue` は、その Editor の View に対して働く。操作の前にその View を主にする。

## 2. スクロール位置: 行とそのずれ

### 選択肢

| | 内容 | 判断 |
|---|---|---|
| A. 文書の先頭からのピクセル | 上の行の見積もりが正確になるたびに値が変わり、折り返しの幅が変わると別の文字を指す。左右の行の高さが違う差分では使えない | 採らない |
| B. 先頭に見えている論理行と、その行の上端からのピクセル、横のピクセル | ADR 0061 の「錨」と同じ表し方。見積もりが変わっても、リサイズで折り返しが変わっても同じ文字を指す | **採る** |

### 決定

```go
type ScrollPosition struct {
	Line   int     // 先頭に見えている論理行（折り返した行も 1 つ）
	Offset float32 // その行の上端からビューの上端までのピクセル。折り返しでは 1 段より大きくなりうる
	X      float32 // 横のスクロール。Wrap のときは 0
}

func (v *View) Scroll() ScrollPosition
func (v *View) SetScroll(p ScrollPosition)
OnScroll func(ScrollPosition) // View のフィールド
```

- 最初の行は内容の上端（上の余白を含む）から始まるとしたので、一番上は `{0, 0, x}` で、`Offset` は負にならない。引っ張りすぎ（オーバースクロール）の間は端にいるとして数える。
- `SetScroll` はその場では動かさず、次のレイアウトで行の表（見積もりを含む）から位置を求めて跳ぶ。行が文書を越えれば最後の行に、位置が内容を越えれば端に収める。同じレイアウトでキャレットを見せる動きがあっても `SetScroll` が勝つ。
- **`OnScroll` が呼ばれる時:** ホイール、スクロールバー、PageUp/PageDown、キャレットを追う動き、リサイズ（端で収まったなど先頭の行が変わったとき）、上の編集で行番号が変わったとき。値が前に知らせた値と違うときだけ呼ぶ。
- **ループさせない決まり: `SetScroll` は `OnScroll` を呼ばない。** 収めるために値が変わっても呼ばない（それを知らせると、行の数が違う左右の文書で、互いに収め合う往復が終わらない場合がある。浮動小数の誤差でも起こりうる）。実際の値は `Scroll()` で読める。だから `left.OnScroll = func(p) { right.SetScroll(p) }` と逆向きを両方書いてよい。テストで、短い文書の端を越えて回しても、相手は 1 回も知らせないことを確かめた。
- **レイアウト中に起きた変化は、次のフレームの頭で知らせる。** `OnScroll` の中で別の Editor の `SetScroll` を呼ぶと、その Editor をレイアウト済みに印を付け直すことになる。レイアウトの途中に祖先がまだレイアウト中の兄弟へ印を付けると、`MarkNeedsLayout` は祖先の `needsLayout` を見て止まり、祖先のレイアウトが終わると印が消えて、兄弟が二度とレイアウトされない（core の `Tree.Layout` も、ループ中に足された境界を見ない）。core を直すより、知らせる時を選ぶ方が狭い。そこで、
  - ホイールやスクロールバーなど、Ticker や入力から来る動き（`ScrollState.OnMove`）は、その場で知らせる（レイアウトの前なので安全）。差分の左右は同じフレームで揃う。
  - キャレットを追う、リサイズ、編集で留める、といったレイアウトの中で決まる変化は、描画オブジェクトの Ticker で次のフレームの頭に知らせる。相手のペインは 1 フレーム（16ms）遅れて追う。
  - `SetText` や Controller の付け替えは、build の中で起きるので `ScrollState.Jump` ではなく `Scroller.Jump` で動かし、知らせはレイアウトの後に回す（build の中で `OnScroll` が `SetState` を呼ぶと panic するため）。
- View が付いていなければ、`Scroll()` は覚えている値（`pending` か、最後に知らせた値）を返す。

## 3. 横のスクロールバー

- Editor の State に 2 つ目の `basic.ScrollState`（`horz`）を足し、`ScrollFrame{Vertical, ScrollFrame{Horizontal, view}}` と入れ子にした。`DataTable` と同じ作りで、縦のバーと同じ細いオーバーレイのバーが、動いている間とポインターが近い間だけ下端に出る。つまみのドラッグとバーの上のホイールも同じ。
- 入れ子は `Wrap` でも常に置く。`Wrap` を切り替えても木の形が変わらず、描画オブジェクトと整形した行のキャッシュが残る。`Wrap` のときは `Content == View` なのでバーは出ず、当たり判定も無い。
- 横の量は `hscroll` のフィールドをやめて `horz.Offset` にした。範囲は今までどおり「整形した中で一番広い行 + キャレットの幅 − 文字の欄の幅」。
- ホイール: 横のホイールとタッチパッドの横の動き、Shift + ホイール（`DataTable` やブラウザと同じ）。今までは 1 刻み 60px でその場で動いたが、ほかのスクロールと同じ `ScrollState.Wheel` にしたので、刻みのあるホイールは 100px を滑らかに動き（端で少し引っ張れて戻る）、タッチパッドはその場で動く。
- 横の位置は `ScrollPosition.X` に入る。キャレットを追う動き（`revealCaret`）も `horz` を動かす。
- バーは Editor の幅いっぱい（行番号の欄の下も）に出る。文字の欄だけに出すには `ScrollFrame` に手を入れる必要があり、`DataTable` の固定列と同じく今回はそのままにした。
- 横のバーの分だけ下に余白を足すことはしなかった。バーは動いている間だけ出る重ね描きで、縦のバーも折り返さない文字の右端に重なる。下の余白を足すと、1 つの Editor の縦のスクロールの範囲が変わってしまう。

## 4. 斜体の飾り（要望 7 の残り）

- `Decoration.Italic bool` を足した。`shapeLine` で、その範囲の `text.Span` の `Style.Italic` を立てるだけ。斜体の書体があればそれを、無ければ ADR 0101 の合成の斜体を使う。重なった飾りでは `Bold` と同じく「どれかが立てれば立つ」（`text.Style` の合成が OR）。ドキュメントの「後の飾りが勝つ」は `Color` だけの話に直した。
- 送り（advance）は ADR 0101 どおり変わらないので、キャレット、ヒットテスト、選択の矩形、行の折り返しは立体と同じ。テスト（`TestDecoration_ItalicSlantsWithoutMovingTheCaret`）で全部の列のキャレットの矩形が一致し、斜体の run だけ `FaceID` が違う（合成の斜体の ID）ことを確かめた。

## 互換

- 公開 API は足しただけ（`View`、`ScrollPosition`、`Editor.View`、`Decoration.Italic`）。既存のテストは、非公開のフィールドを指していたところ（`ctl.view`、`ctl.caret`、`r.hscroll`）を書き換えただけで、期待値は変えずに全部通る。golden も再生成せずに通る。
- 1 つの Editor で変わること:
  - 横のスクロールバーが出る。横のホイールが滑らかになり、端で少し引っ張れる（上の 3）。
  - 見えている範囲より上を、コードから `Replace` などで変えたとき、今までは内容が行の数だけずれて見えた。今は同じ文字に留まる（そのあとキャレットが見えるように動くのは今までどおり）。
  - `SetText` のあと、`ScrollState.OnUser` が呼ばれなくなった（Editor は `OnUser` を使っていない）。

## 結果

- テスト（`widgets/editor/editor_view_test.go`）:
  - 2 つの Editor で、打った方の選択だけが動き、もう片方は編集に合わせてずれる。Controller の選択は主の View に効き、Undo は共有。
  - Semantics の選択が Editor ごとで、スクリーンリーダーの `SetSelection` はその Editor にだけ効く。
  - 上に 3 行足すと、もう片方の View は `Line` が 3 増え、同じ「line 100」を先頭に見せ続ける（折り返しの有無の両方）。消すと戻る。
  - `SetScroll` → `Scroll` の往復（折り返しの有無）、先頭は `{0,0}`、越えたら端。`SetScroll` で `OnScroll` は呼ばれない。
  - タッチパッドはその場で知らせ、キャレットを追う動きとリサイズは次のフレームで知らせる。先頭の行が変わらないリサイズは知らせない。
  - 行の数が違う 2 つの文書の同期で、往復が起きない。
  - タブを模した切り替えで、View が位置と選択を戻す。同じ View を 2 つの Editor に出すと panic。
  - 検索の一致は両方で塗られ、F3 は検索バーを操作した Editor で選ぶ。
  - 横: Shift + ホイール、タッチパッド、バーのドラッグ、`Wrap` では動かない。
  - 2 つの View を付け、横にスクロールし、片方がもう片方を `OnScroll` で追う状態で、スクロール + レイアウト + 描画が 0 アロケーション（`testing.AllocsPerRun`、折り返しの有無）。
- ベンチ `BenchmarkTextEditor_ScrollPaintTwoViews100k` を足した（並行して別の作業が走っていたので、ここでは計っていない）。
- gallery に「エディターのビュー」のページ（`-state editors`）を足した。同じ Controller を左（折り返しなし、横に 90px スクロール）と右（折り返し）に出し、スイッチで縦のスクロールを同期する。コメントは斜体、キーワードは太字の飾り。

## 残したこと

- 主でない View で IME の変換中に、別の View から同じ行を編集したときの変換の位置合わせ（今までも Controller からの編集で同じ）。
- 横のバーを文字の欄だけに出すこと。
- 差分ビューアー向けの「行の対応表で左右を同期する」仕組みは作っていない。アプリが `OnScroll` の中で行番号を写せば作れる。
