# 0158: 保存の後もソースを差し替えるだけにし、Rebase で位置を残し、ソースが縮むのを止める

決定日: 2026-11-18

状態: 採用

## 背景

Nople が `LineSource`（ADR 0157）の上にファイルの読み書きを作り直したところで、gowaku に次の要望が届いた。

1. **保存の後に、元に戻す履歴とキャレットが消える。** 保存の後に新しいファイルを読ませる手段が `SetSource` か `Rebase` しか無く、どちらも履歴を捨ててキャレットを先頭に戻す。Nople は、大きなファイルの自動保存を止めることで逃げていた。
2. **`Rebase` でもキャレットが先頭に戻る。** 外での変化で読み直すたびに戻る。
3. 4,096 行を超える編集は、置き場所を決められない（困るほどではない）。
4. **ソースの `Len` が縮むと、Editor が範囲外を読む。** Nople は追記の追いかけで、元の行数に届くまで行を渡さないようにしていた。

持ち主の判断で 1、2、4 を入れ、3 は見送った。3 を入れるには、古いファイルがまだ読めることを Editor が確かめる必要があり、その手段が無い。

## 決定

### 1. `Controller.ReplaceSource(src) error`

- 文書と同じ中身を持つソースに差し替える。保存の後、書いたファイルを読むソースに替えるときに使う。
- 中身が同じかは、行の数と全体の長さ（`Offset(Len())`）が文書と一致するかで確かめる。違えば `ErrNotSameText` を返し、何も変えない。全部の行を比べるのは、数 GB のファイルでは成り立たない。
- 文書は新しいソースの 1 つのピースになり、ソースに対する編集は無くなる（`Edits` は空）。元に戻す履歴、選択、スクロール、検索の一致はそのまま残る。どれも文書全体の中での位置で持っていて、文書の中身は変わらないからである。

### 2. `Rebase` で選択とスクロールの位置を残す

- 置いた編集から、古い文書の行を新しい文書の行へ移す写像（`lineBuffer.lineMap`）を作る。ソースの行は、その前にある置かれた編集のずれ（`At - From`）と、それまでに置かれた編集が増減させた行の数だけ動く。編集が入れた行は、その編集が置かれた場所の同じ行へ行く。置かれなかった編集の行は、それが置き換えていた元の行が戻ってくる場所へ行く。
- 写像は**ピースを作り直す前に**引かなければならない（作り直した後に引くと、新しいピースで数えてずれる。最初の実装でこれに当たった）。そのため、選択とスクロールの新しい行を先に求めてから `rebase` する。
- 各ビューの選択とスクロール位置、ビューが無いときの選択（`base`）を移す。列はそのままにし、行に収まるように寄せる。元に戻す履歴は、位置が古い文書のものなので、これまでどおり消す。

### 4. ソースが縮むのを止める

- `SourceGrew` は、ソースの `Len` が、ピースの届いている行の数より少なくなっていたら panic する（「a source must not lose lines」）。範囲外の行を読む前に、使い方の誤りとして気づけるようにした。
- `LineSource` と `SourceGrew` の godoc に、ソースは縮まないこと、最後の行を読み直すソース（追記の追いかけ）は元の行数に届くまで古い `Len` を返し続けることを書いた。

## 結果

- テスト: 編集して書き出した中身のソースに `ReplaceSource` しても、選択、スクロール、履歴が残り、元に戻すと元の文書になる。違う中身のソースは断る。上に 3 行足されたソースへの `Rebase` で、編集より下のソースの行のキャレットとスクロールが 3 行（と、置いた編集が増やした 1 行）動く。編集が入れた行のキャレットは、その編集の置き場所へ動く。縮んだソースで `SourceGrew` を呼ぶと panic する。race 検出器あり。
