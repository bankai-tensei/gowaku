# 0094: 色の選択（ColorPicker と PropertyColor の既定の押し先）

決定日: 2026-11-13

状態: 採用

## 背景

当初の計画の `ColorPicker`。`collection.PropertyColor` は色見本と hex を見せるだけで、押した先は「自前のピッカー」だった。色相・彩度・明度の面、hex 入力、透明度を持つ部品を作り、`PropertyColor` の既定の押し先にする。Phase 18 の部品として、ほかの 9 つと並行して作った。

## 決定

### 1. 置き場所と API

- `widgets/field` に置いた。hex と数値の欄に `field.Input` を使うので `field`（段 5）より下には置けない。`DatePicker` と同じく「選んで値をもらう」部品でもある。`collection.PropertyColor` は段 6 なので `field` を使える。
- `field.ColorPicker{Value, Opaque, Numeric, Swatches, Width, Autofocus, Label, OnChange}`。ゼロ値で使える（透明な黒を見せるだけの、無効のピッカー）。
  - 透明度の帯は既定で出す。要らないときの bool は肯定形にして `Opaque`（帯を出さず、報告する色を不透明にする）。`HideAlpha` は規約 §4.1 の否定形になる。
  - `Numeric` で R・G・B（0〜255）と H・S・B（度と %）の数値欄を足す。`Input` を 6 つ並べるだけで済んだので入れた。
  - `Swatches` で色見本の並びを足す。今の色と同じ見本は `Selected` で、フォーカスリングと同じ輪を出す。
  - `Autofocus` は面にキーボードを渡す。ポップアップの中で使う。
  - 幅は `Width`（既定 240）。面の高さは幅の 0.66。
- 前後の比較: 帯の右に、開いたときの色（左半分）と今の色（右半分）を並べる。前の色を押すとそこへ戻る。「前の色」は State が初めて作られたときの `Value` で、別のフィールドは持たない。インラインで置きっぱなしのときは「画面を開いたときの色」になる。それで足りると判断した。
- `theme` に色の補助を足した（新しいファイル `hsv.go`、`hex.go`）。HCT と sRGB の計算が `theme` にあるので、色空間の型はここに置く。
  - `theme.HSV{H, S, V, A}`、`HSVFromColor`、`HSVFromColorLike(c, like)`、`HSV.Color()`。
  - `theme.ParseHex(s) (geom.Color, bool)`、`theme.FormatHex(c) string`。
- `Strings` に語を足した（`ChooseColor`、`ColorPlane`、`Hue`、`Saturation`、`Brightness`、`Opacity`、`HexCode`、`Red`、`Green`、`Blue`、`OriginalColor`）。`fillFrom` にも足したので、持たない表は英語になる。

### 2. HSV にした（HSL ではなく）

- 面は「横に彩度、縦に明度（V）」の HSV にした。
  - 線形グラデーション 2 枚で正確に描ける。横は白から純色（V=1 での彩度は sRGB の線形補間そのもの）、縦は透明な黒から黒（V を掛けるのと同じ）。HSL の正方形は、上端が白、中央が純色、下端が黒の 3 段で、角ごとに色が違うので 2 枚の線形では描けない。
  - macOS、Figma、Photoshop の正方形と同じで、利用者が見慣れている。
- 補間は sRGB のまま（GPU のグラデーションと同じ）で、ガンマを考えた補間はしない。面の中の色と、つまみの位置から計算した色は、どちらも同じ sRGB の式なので食い違わない。

### 3. 色相を失わない

- State の真の値は `theme.HSV` で、RGB は結果でしかない。面を黒（V=0）や灰（S=0）に動かしても、H と S は State に残るので、戻せば元の色相に戻る。
- 外から `Value` が来たときは、最後に報告した色と同じなら HSV をそのまま使う（親が受け取った色をそのまま返すのが普通なので、ここで RGB を通らない）。違えば `HSVFromColorLike(Value, 今のHSV)` で、灰なら色相を、黒なら色相と彩度を今のものから引き継ぐ。
- hex、数値欄、見本から色を入れるときも `HSVFromColorLike` を通す。`#808080` を打っても色相の帯は動かない。

### 4. 描画

- 新しいシェーダーは足さなかった。面は `DrawRRect` 2 回（白→純色、透明→黒）、色相の帯は 7 ストップの `Gradient.MoreStops`（ランプのテクスチャ）、透明度の帯は市松模様の上に透明→不透明の線形。
- アロケーションしない: グラデーションは描画オブジェクトのフィールドに持ち、`&r.white` のように渡す。色相のストップは最初の描画で 1 回だけ作る（`MoreStops` は `Canvas` が写すので、同じスライスを毎フレーム渡してよい）。市松模様は 6px の正方形を `ClipRRect` の中に描く。`TestColorPicker_PaintDoesNotAllocate` で、透明な色と見本を含むピッカーの描画が 0 allocs であることを確かめた。
- つまみは白い円に影と細い縁、中に今の色。フォーカスリングはつまみの外側の輪で、キーボードでフォーカスしたときだけ出す（`Slider` と同じ）。

### 5. 操作

- ポインタ: 面と帯は押した所に飛び、そのままドラッグで追う。外にはみ出しても端で止まる。押すと面や帯がキーボードを取る（`Focus` の既定）。
- キーボード: Tab で 面 → 色相 → 透明度 → 前の色 → hex → 数値欄 → 見本 の順。プレビューを帯の右に置いたのは、この順にするため（左に置くと Tab が前の色を先に通る）。
  - 面: ←→ で彩度、↑↓ で明度を 1%、Shift で 10%。PageUp/PageDown で明度 10%、Home/End で彩度 0/100%。
  - 色相: 1°、Shift で 10°、Home/End で 0°/360°。360° は赤（0° と同じ色）だが、つまみは右端に置く。
  - 透明度: 1%、Shift で 10%、Home/End で 0/100%。
- hex 欄: キーボードを持っている間は打った文字を残し、読める形になったらすぐ色に反映する。Enter か欄を離れたときに、今の色の正規形（`#RRGGBB`、不透明でなければ `#RRGGBBAA`、大文字）に戻す。読めない文字のままなら元の色の hex に戻る。
- 貼り付けへの寛容さ（`ParseHex`）: 前後の空白、引用符、末尾の `;` と `,`、`#` 無し、`0x` を許す。`#RGB`、`#RGBA`、`#RRGGBB`、`#RRGGBBAA`。`rgb()` や名前の色は読まない（CSS のパーサになってしまう）。全角の `＃` も読まない。

### 6. アクセシビリティ

- 全体は `RoleGroup`（`Label`、無ければ「色を選択」）。
- 面は「説明つきの 2 次元スライダー」にした。`RoleSlider`、ラベル「彩度と明度」、値「彩度 40%, 明度 80%」。Increase/Decrease は彩度を動かす。
  - 2 つの範囲値（彩度と明度のスライダーを子に持つ）にしなかった理由: 1 つのフォーカスに 2 つのノードを付けると、`SemanticsActor` は自分が開いたノードを区別できず、どちらへの Increase か分からない。子ノードごとに描画オブジェクトを分けると、ドラッグの当たり判定が 2 つに割れる。
- 色相と透明度は普通のスライダー（`Range` は 0〜360 と 0〜100、Step 1）。SetValue も受ける。
- hex 欄と数値欄は、見た目のラベルを出さずに `SemanticsBuilder.Name` で名前を渡す（行の前の小さな「HEX」「R」は読ませない）。
- 前の色は `RoleButton`「元の色」で、値に hex を持つ。見本は hex を名前にしたボタン。

### 7. PropertyColor の既定の押し先

- `PropertyColor` に `OnChange func(geom.Color)` を足した。`OnPress` が無く `OnChange` があるとき、色見本はボタンになり、押すと行の下に `ColorPicker` のポップアップを出す。
  - 既存の挙動は変えない: `OnPress` があれば今まで通りそれが勝ち、どちらも無ければ読み取り専用のまま。`OnPress` だけの既存コードはそのまま動く。
  - `OnChange` にしたのは、ピッカーを開くには色を返す口が要るから。`OnPress` を nil のまま既定にすると、読み取り専用の色まで押せるようになる。
- ポップアップは `DatePicker` と同じ作り（`overlay` の Entry、`kit.Barrier`、`kit.Popup`、`ModalScope`）。
  - 変更はその場で `OnChange` に届く（色を見ながら決められる）。
  - Escape: 開いたときの色に戻して閉じる（変わっていなければ何も報告しない）。外のクリックと Enter: 今の色のまま閉じる。どちらも色見本にキーボードを戻す。
  - ピッカーは開いたときの色で作るので、前後の比較は「開く前の色」と「今の色」になる。
- `propertyeditors.go` への変更はフィールド 1 つと `editor()` の分岐だけ。ポップアップは新しいファイル `propertycolor.go`。

## 結果

- テスト: 面・色相・透明度のドラッグとキー、Tab の順、hex の解析の境界（`theme` に表）、黒と灰を通っても色相が残ること、外からの灰と黒、透明度、`Opaque`、見本、前の色、数値欄、スクリーンリーダーの Increase と SetValue、無効のピッカー、ゼロ値と幅。`PropertyColor` は、押して開く・キーとドラッグが届いて報告される・外のクリックで確定・Escape で戻る・Enter で閉じる・`OnPress` が勝つ・どちらも無ければ読み取り専用。すべて GPU 無しで通る。
- gallery に `examples/gallery/pages_visual.go` を足した。インラインのピッカーと大きなプレビュー、`PropertyGrid` から開くポップアップ。登録は統合のときにする。

## 残したこと

- hex 欄に 6 桁を打つ途中で、4 桁の時点（`#RGBA`）で一瞬だけ透明度の付いた色が報告される。打ち終われば正しい色になる。気になるなら、欄を離れるまで反映しないオプションを考える。
- 面の色は sRGB の補間で、知覚的に均等ではない（OKLCH の面などは作っていない）。
- スポイト（画面から色を拾う）は無い。OS ごとの画面取得が要り、platform に手が入る。
- 見本の並びを利用者が足し引きする UI（最近使った色など）は持たない。`Swatches` をアプリが管理する。
- `collection.Table` のセルにピッカーを開く種類は無い。
