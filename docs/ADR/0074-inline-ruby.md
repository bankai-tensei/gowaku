# 0074: TextField のルビ表示（青空文庫の記法）

決定日: 2026-11-09

状態: 採用

## 背景

Phase 16b の notes サンプルは、本文をプレーンテキスト（.txt）で保存し、ルビを青空文庫の記法 `｜漢字《かんじ》` で書く（ヒアリング）。ヒアリングでは、編集中もルビを描くことを選んだ。記法を本文に持ったまま、基字の上（縦書きなら右）にルビを描き、カーソルのある語だけ記法を生で見せる。これは他のアプリも使えるライブラリの機能にする。

テキストのルビ自体は Phase 5 / 11a からある（`text.Span.Ruby`、`Shaper.ShapeSpans`、縦書き対応）。足りなかったのは、編集できる TextField でそれを使う仕組みである。

## 決定

### 1. 記法の読み取りは text/aozora、TextField は記法を知らない

- `text.RubyMark{Start, End, BaseStart, BaseEnd, RubyStart, RubyEnd}` を置いた。値（value）の中で記法全体、基字、ルビが占めるバイト範囲を表す。
- `text/aozora`: `Marks(s, dst)` と `Plain(s)`。
  - `｜基字《ルビ》` の形では、《 より前で同じ行にある最後の ｜ を使う。
  - `漢字《かんじ》` の形では、《 の直前に続く漢字（Han と 々〆ヶヵ〇）を基字にする。
  - 次のものは記法とみなさず、地の文として扱う: 基字が無い、同じ行に 》 が無い、`《》`、》 より前に 2 つ目の 《 がある。
  - 青空文庫の注記（［＃…］）による 《 のエスケープは仕様にあるが、読まない。`※《` は青空文庫の書き方ではないので、package doc から消した。
  - Marks は dst に容量があればアロケーションしない。300KB を 175µs で読む。ファズテストもある。
- `widgets.TextField.Ruby func(value string, dst []text.RubyMark) []text.RubyMark` を足した。nil なら今までどおりで、増えるコストは nil の判定だけ。
  - 記法の種類はこの関数が決める。TextField は記法を知らない。
  - 理由: 記法は他にもある（小説投稿サイトの `|漢字《かんじ》`、`{漢字|かんじ}`）。TextField に青空文庫を焼き付けない。

### 2. 表示は「射影」、値は記法のまま

- TextField は、表示用のテキスト（値に IME の未確定文字列を足したもの）から、活性でないマークの ｜ と 《ルビ》 を取り除く。基字は `Span{Ruby: …}` として並べる。こうしてできた「見えるテキスト」を組む。
- 次のものはすべて値のオフセットのまま扱う: Value、OnChange、Undo、選択、クリップボード、Semantics。
  - 表示と見えるテキストの間の写像は、隠した区間の並びと、そこまでに取り除いた量の累計で持つ。O(log マーク数) で引け、アロケーションしない。
  - 見えるテキストで記法を取り除いた位置は、マークの外側（｜ の前か 》 の後）に写す。だからクリックや上下キーで、マークの中に落ちることはない。
  - 基字は 1 つのルビのクラスタになるので、キャレットが止まるのはその前後の 2 か所だけ。
- コピーは値の範囲をそのまま写すので、記法も入る。貼り付け先で読みが失われない。

### 3. 活性（生で見せる）規則

- アンカーかキャレットがマークの内側（Start < x < End）にあれば、そのマークは生で見せる。
- IME の未確定文字列は選択を置き換えるものとして扱う。重なったマークは消え、後ろのマークは位置がずれる。
- 規則はマーク、アンカー、キャレット、未確定文字列だけで決まる。だから別の場所で打鍵しても、隠れ方は変わらない。行がちらつかない。
- 採らなかったもの:
  - **選択に含まれるマークを開く**: ドラッグ中にポインタの下で組み直しが起き、Ctrl+A で全マークが開いて文書全体を組み直すことになる。マークを丸ごと含むだけの選択では開かない。
  - **クリックで開く**: ポインタの下でレイアウトが跳ぶ。マウスで開くには、基字の隣をクリックしてから矢印キーを押す。

### 4. キー操作

- Shift なしの左右キーは、隠れたマークに 1 文字ずつ入る（｜ の後、または 》 の前）。入るとマークが開く。
- Shift+矢印はマークを飛び越える。こうしてマークを丸ごと選べる。
- 隠れたマークの直後の Backspace は 》 だけを消す（記法が開く）。直前の Delete は ｜ だけを消す。基字ごと消さない。基字ごと消す案は、読みと一緒に本文まで消えるので採らなかった。
- `｜漢字《かんじ` と打っている間は、キャレットがマークの中にあるので生のまま。`》` を打つとキャレットが End（外側）に出るので、その場でルビに畳まれる。
- Ctrl の単語移動と単語削除は、ルビのまとまりを語の一部として扱う。

### 5. スクリーンリーダーには値を渡す

- UIA / AT-SPI に渡すテキスト、選択、行頭は、値のオフセットで表す。行の矩形は見えるテキストの行を使う。
- こうすると Value、SetValue、SetSelection と一致する。マークの中に選択を置くとマークが開く。
- 見えるテキストを渡す案は採らなかった。ルビが読まれなくなり、操作のために 2 つ目のオフセット空間が要る。

### 6. 行の高さを揺らさない

- Ruby を設定すると、TextField は `Style.RubyRoom` を立てる。これは公開した新しいフィールドである。
  - 行の高さ（少なくとも `text.RubyLineHeight` = 1.75）と、最初の行の上の余白は、ルビの有無で変わらない。
  - こうしないと、画面の最後のルビが開いたり閉じたりするたびに、全行が上下に動く。
- 単一行のフィールドの余白は `max(LineHeight, RubyLineHeight)` で取る。

### 7. マークの契約と差分の組版

- マークは改行をまたがない。順序が乱れたマークや範囲外のマークは panic にする（`gowaku: TextField.Ruby must …`）。
- 編集の後は、編集した行だけで Ruby を呼び、マークを差し替える。新しい Value のときと、Ruby が nil と非 nil の間で変わったときは、全体で呼ぶ。
- text に `Shaper.ReshapeSpans(old, spans, st)` を足した。`Reshape` はこれに任せる。スパンが 1 つならコピーしない。
  - 前から一致する区間と後ろから一致する区間はクラスタを保ち、編集が触れたブロックだけ組み直す。
  - `Relayout` もルビに対応した。変わったブロックのルビだけ置き直し、他のルビは原点を動かすだけ。
  - これに合わせて、ルビのはみ出しは同じブロックの隣だけを見るようにした（ブロック単位で組めるように）。
- ADR 0024 の「差分の組版はスパンが 1 つでルビの無い段落だけ」は、ここで外れた。
- 採らなかったもの: ルビがあれば全体を組み直す案。1 打鍵 64ms 以上かかる。

### 8. 性能

10 万字（日本語）とマーク 1099 個、1 打鍵とそのフレームで測った。

| 場合 | 時間 |
|---|---|
| Ruby あり | 1.77〜1.95ms |
| 同じ文で Ruby nil | 1.54〜1.56ms |
| マークに入って出る（1 つ開いて閉じる） | 1.7〜1.9ms |

どれも Phase 11 の 2ms の目標に入る。英語の `BenchmarkTextField_Keystroke100k` と `BenchmarkLayout_100kChars` は変わらない。Paint はアロケーションしない。

## 残したこと

- マウスだけではマークを開けない。ダブルクリックで開く案は後で考える。
- RTL のテキストをマークの中に入れたとき、入り方は論理順だけで、特別な扱いをしていない。
- 青空文庫の他の注記（傍点、縦中横、字下げ）は読まない。notes の範囲はルビだけ（ヒアリング）。
