# 0089: SelectionArea（配下のテキストを選択してコピーする）

決定日: 2026-11-13

状態: 採用

## 背景

当初の計画の `SelectionArea`。`Text` / `RichText` は選択できず、選択を持つのは `Input` と `Editor` だけだった。エラーメッセージやログは、コピーできないと利用者が困る。

選択範囲を描けるのは、テキストのレイアウトを持つ `RenderParagraph` だけである。`text.Layout` には `HitTest`、`SelectionRects`、`WordRange`、`VisualMove` などがすでにあり、縦書き・BiDi・ルビのクラスタをまたいで正しく動く（ADR 0023 / 0024 / 0074）。足りないのは、段落の上に選択を描く口と、複数の段落を束ねて操作を受ける部品である。前者が `basic` の内側に手を入れる必要があるので、利用者は自分で組めない。

## 選択肢

1. **`Text` に `Selectable bool` を足す**（Flutter の `SelectableText`）。段落 1 つの中でしか選べず、ログを複数の `Text` で並べると段落をまたげない。
2. **祖先の部品が配下の段落を集めて操作を受ける**（Flutter の `SelectionArea`、ブラウザの選択）。段落をまたいで選べ、`Text` の側は描くだけでよい。
3. **段落ごとに `PointerTarget` を持たせる**。すべての `Text` のヒットテストに処理が乗り、ボタンのラベルが押下を奪う。

2 を採った。

## 決定

### 1. 置き場所と公開 API

- `field.SelectionArea{Child}` を足した（`widgets/field/selectionarea*.go`）。コンテキストメニューに `overlay` を使うので段 5 に置く。テキストの選択という意味でも `Input` と同じ層になる。
- `basic.RenderParagraph` に 3 つのメソッドを足した（`widgets/basic/text_selection.go`）。
  - `SetSelection(start, end int, color geom.Color)`: 字の下に範囲を塗る。逆順も受け、テキストの末尾より後ろは末尾で止める。
  - `ClearSelection()`
  - `Selection() (start, end int)`
- 既存の API と挙動は変えない。`Strings` に `Copy` と `SelectAll` を足した（英語 "Copy" / "Select all"、日本語「コピー」/「すべて選択」）。

### 2. 範囲外の段落にコストを乗せない

- `RenderParagraph` に足したのはポインタのフィールド 1 つ（`selection *paragraphSelection`）だけ。`Paint` での追加は nil の判定 1 つ。`SelectionArea` の外の段落ではアロケーションも毎フレームの処理も増えない。
- 選択の状態（`start`, `end`, 色、矩形の作業領域）は、最初に選択されたとき（イベントの時点）に 1 度だけ確保する。描画では `SelectionRects` の結果を作業領域に使い回すので、選択があっても `Paint` はアロケーションしない。
- ヒットテスト、段落の収集、コピーの文字列作りはすべてイベントの時点に行う。ホットパスではない。
- 確認: `TestParagraphSelection_PaintDoesNotAllocate`（選択の有無の両方で `AllocsPerRun` = 0）、`TestSelectionArea_PaintDoesNotAllocate`、`BenchmarkText_1000Paint` と新しい `BenchmarkText_1000PaintSelected`（どちらも 0 allocs/op）。

### 3. 文書順と、選ばない段落

- 段落の順は描画順（子を `ChildAt(0..n)` の順にたどる）。
- 次のものは収集しない。
  - `core.FocusTarget` の下（ボタン、リンク、`Input`、表やツリーの行など）。コントロールのラベルはコントロールのもので、地の文ではない。
  - 内側の `SelectionArea`。内側は自分の選択を持つ。
  - 隠れた部分木（`core.Hider`）と、まだレイアウトされていない段落。
- テキストでない部品（画像、区切り線など）は飛ばす。
- ネストしたコントロールは今までどおり動く。押下は深い方から配られるので、ボタンが受けた押下は `SelectionArea` に届かず、選択は始まらない。

### 4. マウス

- ドラッグ: 押した点から現在の点まで。点に一番近い段落を選び、その段落の行より前なら先頭、行より後ろなら末尾とする（横書きは上と下、縦書きは右と左）。近さは行と直交する向きの距離を 4 倍に数える。こうしないと、短い行の横では下の段落が近く出る。
- ダブルクリックは `WordRange` の単語、トリプルクリックは段落の中のハードな改行で区切られた行（改行の無い `Text` なら全体）。ログ 1 行を選べる方が使いやすい。
- Shift+クリックはアンカーを残して自由端を動かす。
- 多重クリックのあとのドラッグで単語単位に広げることはしない（`Input` に合わせた）。
- タッチでは選択しない。指はスクロールに使う（長押しで選ぶのは範囲外）。ペンはマウスと同じ。
- カーソル: 地の文の上で I ビーム、ほかは矢印。`CursorSource` は位置を受けないので、`HitTest` の結果（深い順のパス）にこの領域の段落があり、間にコントロールが無いかを覚えておく。ヒットテストでのアロケーションは無い。

### 5. キーボード

- 押下でアンカーが置かれると `SelectionArea` がフォーカスを取る。`CanFocus` はアンカーがあるときだけ true なので、選んでいない領域は Tab の止まり先にならない。
- Ctrl+C（macOS は Cmd が `ModControl` として届く）でコピー、Ctrl+A ですべて選択、Escape で自由端へ畳む（アンカーは残るのでフォーカスも残る）。
- Shift+←→ は表示順の 1 文字（`VisualMove`）、Ctrl+Shift+←→ は単語、Shift+Home / End は行頭と行末、Ctrl+Shift+Home / End は領域の先頭と末尾、Shift+↑↓ は行の移動（横の位置を保つ）。段落の端では隣の段落へ移る。縦書きでは `Input` と同じく ↓ が行に沿って進み、← が次の列へ移る。
- Shift の無い矢印は受けない。キャレットを表示して文書を歩くモード（caret browsing）は範囲外。スクロールなど上の部品に任せる。
- メニューキーと Shift+F10 でもメニューを開く（自由端の下に）。

### 6. フォーカスを失ったとき

- 窓の中の別のものにフォーカスが移ったら選択を消す。領域の外を押した（何も押下を受けなければ `Tree` がフォーカスを外す）、Tab で移った、などである。
- 窓そのものが背面に回ったときは残す（`FocusChanged(false)` のあとも `Tree.Focused()` が自分のまま）。別のアプリへ貼り付けに行って戻る使い方のため。
- 領域が開いたメニューはフォーカスを取るが、その間は消さない。メニューの項目が選択に対して働くからである。フォーカスが戻るとこの扱いをやめる。

### 7. コピーする文字列

- 段落ごとの部分を `"\n"` でつなぐ。段落の中の改行はそのまま。
- ルビは写さない。`text.Paragraph` のテキストが親文字だけなので、親文字だけが入る。ルビのグループは 1 つのクラスタなので、キャレットも選択の端もグループの中に入らず、グループは丸ごと選ばれる。
- `Text` に青空文庫の記法が書かれていれば（`Text` は記法を読まない）、記法ごと写る。
- 縦書きでも論理順の文字列になる。矩形は `SelectionRects` が列ごとに、BiDi の行では並べ替えた断片ごとに出す。

### 8. 再構築とテキストの変化

- 選択は State に持つ。再構築で同じ `RenderParagraph` が使い回される限り、ドラッグの途中でも選択は続く。
- 端の段落が領域から消えたら、選択全体を消す。
- テキストが変わった段落の端は、オフセットを保ったまま新しいテキストの長さと文字の先頭に丸める。描画も同じ長さで止める。
- 領域ごと消えたら（ドラッグ中でも）、State の `Dispose` が段落の印を外す。捕まえていた押下は `Tree` が外れたオブジェクトに配らない。

### 9. スクリーンリーダー

- semantics の層は、テキストと選択（`semantics.TextInfo`）を `RoleTextField` にしか渡していない。UIA の TextPattern、AT-SPI の Text インターフェースも `RoleTextField` のときだけ出す（`platform/win32/uiamap.go`、`platform/dbus/atspi.go`）。静的なテキストの選択を伝える口が無い。
- 今回は手を付けず、`Text` の semantics（`RoleText` とラベル）は今までどおりにした。静的テキストに TextPattern を出すには platform の 3 つの実装に手が要るので、別の判断にする。

## 結果

- `Text` / `RichText` を `field.SelectionArea` で囲めば、マウスとキーボードで選んでコピーできる。ルビと縦書き、BiDi の行をまたいでも、矩形と文字列が正しい。
- `RenderParagraph` に増えたのは 8 バイトと nil 判定 1 つ。既存の golden は 1 画素も変わらない。
- 残したもの: caret browsing、多重クリック後の単語単位のドラッグ、ドラッグでのスクロールの自動送り、タッチでの選択、静的テキストのスクリーンリーダーへの選択の公開、選択が空の改行の印（段落の境目に幅のある印を描かない）。
