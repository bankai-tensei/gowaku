# 0026: 長さが決まらない置き方を、panic と doc で明示する

決定日: 2026-11-08

状態: 採用

## 背景

公開 API だけで音楽プレーヤーの見本アプリを書いたところ、次の 3 か所で回り道をした。

1. 縦の `Scroll` の中に横の `Scroll` を置くと、横の `Scroll` の高さが無限になった。そのあとに並べた行は y = 3.4e38 に置かれ、画面から消えた。`RenderViewport` は渡された最大の大きさをそのまま自分の大きさにするので、上限の無い向きでは `geom.Inf` になる。エラーは何も出ない。
2. `Scroll` の中で `Row{Cross: CrossStretch}` を使うと panic した。止まること自体は正しい。ただ、メッセージの "unbounded cross axis" では、どの部品の何の長さが問題で、どう直せばよいかが分からなかった。
3. 再生位置の基準時刻に「まだ決めていない」という印として負の値を使ったら、`gowakutest` で時計が進まなくなった。tick の時刻は 0 から数え始める。実際の窓でもアプリの起動時刻から数えるので、`now - pos` は負になりうる。この決まりは doc に書かれていなかった。

## 選択肢と決定

### 1. 上限の無い Scroll

- (a) 上限の無い向きでは、子の大きさに縮める（Flutter の `SingleChildScrollView` の交差方向と同じ）。
  - 書いたとおりに動くことは増える。
  - ただ、スクロールする向きでは縮めても意味がない。中身がすべて見えてしまい、スクロールしないビューになる。
  - 交差方向だけ縮めると、規則が向きによって変わる。
- (b) どちらの向きでも上限が無ければ panic し、どの部品で何が足りないか、どう直すか（`SizedBox` / `Expanded`）をメッセージに書く。Flutter の `ListView` が「unbounded height」で止まるのと同じ。

**(b) を採る。** 黙って無限の大きさになるより、Layout の最初で止まるほうがずっと早く直せる。`RenderList`（`ListView`）も同じように止める。

### 2. CrossStretch と Expanded のメッセージ

- メッセージを軸ごとに 2 本ずつ持つ。
- メッセージには次の 3 つを書く。
  - 部品の名前（`Row` / `Column`、`Expanded or Flexible`）
  - 決まっていない長さ（高さ／幅）と、よくある原因（縦の `Scroll` の中など）
  - 直し方
- `CrossStretch` の doc にも同じ条件を書く。

メッセージは定数の配列に入れ、Layout の中で文字列を組み立てない（ホットパスでアロケーションしない）。

### 3. tick の時刻

- (a) 実際の窓でも `gowakutest` でも、時刻を大きな値から始める。
  - 印に負の値を使う書き方が、たまたま動くようになるだけで、正しくはならない。
  - 差を取ったときに負になる問題も残る。
- (b) 時刻はアプリの起動から数え（`gowakutest` は 0 から）、意味を持つのは差だけだと `Ticker` と `gowakutest.Tester.Now` の doc に書く。「未設定」は bool で持つよう勧める。

**(b) を採る。** 挙動は変えない。

## 影響

- 上限の無い `Scroll` / `ListView` は、これまで画面の外に消えていたが、これからは panic する。
  - リポジトリ内のテストと例、見本アプリ には該当する箇所が無かった。
  - 該当する外部のコードは、`SizedBox` か `Expanded` で長さを与えると直る。
- panic のメッセージを文字列で照合していたテストは、新しい文面に合わせた。
