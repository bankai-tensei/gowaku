# 0071: DataTable のセルの種類

決定日: 2026-11-09

状態: 採用

## 背景

DataTable（ADR 0058）の列が見せられるのは `Text func(T) string` の文字だけだった（`Editor` は編集のときだけ）。サンプルのアプリで、状態の列を色の付いたバッジに、電池の列を小さな棒にしたかったが、文字しか出せなかった。

表は 100 万行を 0 allocs/op でスクロールするために、見えている行のセルを 1 つの RenderObject が自分で描いている。セルごとにウィジェットを置くと、この前提が崩れる。

## 選択肢

1. **セルごとに利用者のウィジェットを置く**（`Cell func(T) core.Widget`）。自由度は最大だが、スクロールのたびに見えている行のウィジェットを Build し直すことになり、0 allocs/op と「スクロールでは何も Build しない」をやめることになる。
2. **決まった種類を列ごとに選び、表の中で描く。** 速さはそのまま、自由度は低い。
3. 1 と 2 の両方。

## 決定

2 にした（利用者の判断）。表計算や管理画面の表で求められる見た目は、だいたい数種類で足りる。

### 1. API

`DataColumn` に足したのはフィールドだけで、ゼロ値は今までと同じ文字の列になる。

```go
gowaku.DataColumn[Device]{
	Title: "状態", Kind: gowaku.CellBadge,
	Text: func(d Device) string { return d.Status },
	Tone: func(d Device) gowaku.CellTone { return toneOf(d) },
}
```

- `Kind CellKind`: `CellText`（ゼロ値）、`CellBadge`、`CellDot`、`CellProgress`、`CellCheck`。
- 行ごとのデータは、種類に要るものだけを関数で読む。
  - `Value func(T) float32`: 棒の長さ（0〜1。外れた値と NaN は丸める）。
  - `Checked func(T) bool`: チェックの状態。
  - `OnCheck func(row int, checked bool)`: チェックを押せるようにする。row は `Rows` の添字で、`TableEdit` と同じ。
  - `Tone func(T) CellTone`: テーマの色の名前。`CellToneDefault`（ゼロ値）、`Neutral`、`Accent`、`Success`、`Danger`。
  - `Color func(T) geom.Color`: テーマに無い色。透明を返すと Tone に戻る。
- 色を `geom.Color` だけにしなかったのは、利用者がテーマを持っていないと既定の色が使えず、ダークへの切り替えにも追従しないから。Tone ならテーマのトークンを表が引くので、テーマが変われば色も変わる。
- 既定の色: バッジとドットは中立（Ink2 の文字に FillStrong の地、Ink3 のドット）、棒とチェックはアクセント。DESIGN §2 の「色はアクセント 1 色だけ」に従い、何も指定しなければ表に色は増えない。
- `Text` は種類によらず「読み上げ、編集、絞り込みの対象」のまま。バッジとドットは Text を見せ、棒とチェックは Text があれば横に添える。

### 2. 見た目

- **バッジ**: 高さ 20 の丸い角の札。地は色の 14%、文字は同じ色の Section（12px、500）。幅は文字に合わせ、セルに収まらなければ切る。`Trailing` で右に寄る。
- **ドット**: 直径 8 の丸と、間 8 で本文の文字（Ink）。
- **棒**: ProgressBar と同じ太さ 6 の丸い棒で、トラックは FillStrong。Text があれば右に幅 44 の欄を取り、そこに Ink2 で右寄せする。欄の幅を固定したので、文字の長さによらず列の棒はみな同じ長さになる。棒の位置は `Trailing` で変わらない。
- **チェック**: Checkbox と同じ 16 の箱、角丸 Check、チェックの線は 1.75。外れは Ink3 の 1px の線。OnCheck の無い列も同じ見た目にした。灰色にすると「使えない」に見えるが、表示だけの列は使えないのではなくデータを見せているだけなので。`Trailing` では箱が右端に付き、文字はその左に右寄せ。
- 選択（AccentTint）とホバー（Fill）の上でも見えるよう、地は半透明の色を重ねる形にした。

### 3. チェックの操作

- 箱（とその周り 4px）を修飾キー無しで押すと、`OnCheck(row, !Checked)` を呼び、焦点をそのセルに移す。**選択は変えない。** チェックはデータで、行の選択ではないので、複数選択したままチェックを付けて回れるようにした。箱の外を押せば今までどおり選択する。Ctrl / Shift 付きの押下も選択の操作のまま。
- 焦点のセルがチェックの列なら、修飾キー無しの Space はチェックを切り替える。Shift+Space と Ctrl+Space は今までどおり選択。表計算のチェックボックスと同じ。
- チェックの列は `Editable` でも編集しない。Enter は `OnActivate` になる。
- 表は `Checked` を見せ続けるだけで、状態は持たない。利用者が行を変えて作り直す（ソートや絞り込みと同じく、データは利用者のもの）。

### 4. Semantics

- バッジとドットのセルは Text をそのまま名前にする。色は情報として読ませない（色だけで意味を伝えないよう、Text を必ず出す前提）。
- 棒のセルは `Range`（0〜100）を持つので、UIA では RangeValue が付く。名前は Text、無ければ「82%」。
- チェックのセルは、grid cell の子に **チェックボックスのノード** を置いた（HTML の `<td><input type=checkbox>` と同じ形）。名前は列の題、`Checked` の状態、OnCheck があればタップ（UIA の Toggle）、無ければ `ReadOnly`。
  - セルのノードのままでは UIA の DataItem になり、Toggle が付かないため。
  - このノードは各セルの子の RenderObject（何も描かない）が出す。作られるのは行のオブジェクトを作り直すときだけで、スクロールでは増えない。
- 行の名前（見えている順のセルをつないだもの）には、Text の無いチェックが付いていれば列の題を入れる。「ファイル 2 書類 共有」のように、付いている印が名前でわかる。

### 5. 速さ

- 種類ごとの関数を 1 セルにつき 1〜2 回呼ぶだけで、描くのは角丸の矩形、文字、あらかじめ作ったチェックの線。バッジの文字は Section の書式でキャッシュに入る（キャッシュの鍵を「見出しかどうか」から「書式」に変えた）。
- ベンチ（i7-12700H、並行で他の作業が走っていて数字は揺れる）: 5 種類の列の 100 万行のスクロール 1 段が約 20µs、0 allocs/op。同じ条件で文字だけの表（既存のベンチ）は 10〜17µs、0 allocs/op で、変更前と差は揺れの範囲だった。
- `TestDataTable_ScrollingCellKindsDoesNotAllocate` が 0 allocs を守る。

## 結果

- 文字だけの列の描き方は変えていないので、golden の `table` は変わらない。
- gallery の「デスクトップ」の表に、状態（バッジ）、同期（棒と %）、共有（チェック、インスペクタと連動）、優先度（ドット）の列を足した。
- 残り:
  - 利用者のウィジェットを置くセル（選択肢 1）。要望が来たら、見えている行だけを Build する別の道として考える。
  - バッジやドットの色のコントラスト（色 14% の地の上の Success の文字）は数字で確かめていない。
  - アイコンの種類、星の評価、棒の中間状態（不定）は無い。
  - チェックの列の見出しに「すべて」のチェックは無い。
  - NVDA / Narrator で、チェックボックスのノードと棒の値を耳で確かめていない。
