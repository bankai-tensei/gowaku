# 0145: ほかの欄の無効と読み取り専用、「昨日」、コピーした後の表示

決定日: 2026-11-17

状態: 採用

## 背景

ADR 0143 は `Input` にだけ `Disabled` と `ReadOnly` を足し、`Search`、`NumberField`、`Autocomplete`、`TokenField` は「必要になったら」とした。`MessageDate` には「昨日」を入れなかった（ADR 0143 の案 C）。ADR 0144 の markdown のコピーのボタンは、押しても見た目が変わらなかった。

オーナーの判断で、これらを残さずに揃えることにした。文字を入れる欄のうち `Input` だけが読み取り専用にできるのは、使う人から見て理由が分からない。メールやチャットの一覧では「昨日」が普通の書き方である。コピーのボタンは、押した後に何も変わらないと、効いたかどうかが分からない。

## 決定

- **`Search` と `Autocomplete`：** `Disabled` と `ReadOnly` を足し、中の `Input` に渡す。どちらのときも、`Search` は消すボタンを出さず、Escape で文字を消さない。拡大鏡のクリックは、無効のときフォーカスを取らない。`Autocomplete` は候補の一覧を開かない。
- **`NumberField` と `TokenField`：** `ReadOnly` だけを足す。どちらも `OnChange` が nil なら無効、という今までの決まり（`Button` の `OnPress` と同じ）があり、そちらを残す。`Input` が否定形の `Disabled` を持つのは、自分で文字を持つので `OnChange` で無効を表せないからで（ADR 0143）、この 2 つには当たらない。
  - `NumberField` の読み取り専用は、値を表示して選択とコピーはできるが、入力、上下のキー、ホイール、つまみ、スクリーンリーダーの増減は効かない。つまみは描かず、キーとホイールはページに渡す。セマンティクスは `ReadOnly` で、増減の操作を持たない。
  - `TokenField` の読み取り専用は、チップに × を出さず、文字を打つ欄を置かない。セマンティクスは `ReadOnly` で、`Disabled` ではない。
- **「昨日」：** `Strings.Yesterday` を足し（「Yesterday」「昨日」）、`MessageDate` は前日をそれで書く。曜日で書くのは、その前の 5 日になる。ほかの言語の表に言葉が 1 つ増えるが、足りない言葉は英語に戻る今までの決まりで補われる。ADR 0143 の案 C の判断はこれで置き換える。
- **コピーした後の表示：** `Strings.Copied` を足し（「Copied」「コピーしました」）、markdown のコピーのボタンは、押すと 1.5 秒のあいだチェックのアイコンと `Copied` に変わる。名前が変わるので、スクリーンリーダーにも伝わる。続けて押すと、その時間は押した時から数え直す。

## 結果

- テストは、`Search` と `Autocomplete` の無効と読み取り専用で文字が変わらず、`OnChange` が呼ばれず、消すボタンも候補も出ないこと、`NumberField` の読み取り専用で上のキー、入力、Enter が値を変えず、増減の操作が無いこと、`TokenField` の読み取り専用で文字の欄と × が無いことを確かめる。
- `MessageDate` のテストの「昨日」は `Yesterday`／「昨日」になり、2 日前（「Monday」「月曜日」）を足した。タイムゾーンのテストの期待も「Yesterday」になった。
- markdown のテストは、押した直後に `Copied` のボタンがあり、1.5 秒を過ぎると 2 つとも `Copy` に戻ることを確かめる。
