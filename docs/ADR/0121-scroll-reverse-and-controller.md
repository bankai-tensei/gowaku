# 0121: Scroll の Reverse と ScrollController

決定日: 2026-11-16

状態: 採用

## 背景

縦書き（`text.Vertical`）は gowaku の看板の機能で、段落は逆順の `basic.Row` に入れて右から左へ並べる（ADR 0023）。初めて使う人に試してもらうと、長い縦書きの文章を `basic.Scroll{Horizontal: true}` に入れたとき、表示が左端、つまり文章の終わりから始まった。読者は最後の列を最初に見る。

`basic.Scroll` には、範囲の終わりの側から始める指定がなく、スクロールの状態も外から触れなかった。そのためアプリの側では直せない。ある利用者は `Transform{Scaling(-1, 1)}` で Scroll ごと左右を反転し、中身をもう一度反転して回避していた。この回避では、ホイールの向きとヒットテストの扱いを自分で考える必要がある。

さらに、文章が枠より短いときは右端に寄ってほしい（縦書きの本は右から始まる）。ウィンドウの幅を変えたときも、右端（読み始め）の位置が動かないでほしい。

## 選択肢

1. **Scroll に `Reverse bool` を足す**（Flutter の `reverse` と同じ）。スクロールの範囲の始まりを右端（縦方向では下端）にする。オフセットはそこから数えるので、初期位置 0 が右端になり、子は右端に揃い、枠より短い子も右端に寄る。大きさが変わってもオフセットが同じなら右端からの距離が同じなので、右端は動かない。
2. **初期位置だけを指定する（`StartAtEnd bool` や初期オフセット）**。最初に開く位置は直るが、短い文章は左に寄ったままで、幅を変えると左端を基準に動く。最初のレイアウトまで範囲の長さが分からないので、「終わり」に置く処理も別に要る。
3. **ScrollController だけを足し、アプリが `JumpToEnd` を呼ぶ**。2 と同じ問題があり、縦書きのたびに同じ手当てをアプリに書かせる。

あわせて、コードから位置を読み書きする手段を足すかを考えた。読みかけの位置を保存して次に開く、章を変えたら最初の列に戻す、といった用途があり、どれも今は Key で Scroll を作り直す以外に手がない。

## 決定

1 を採り、加えて `ScrollController` を足す。

### Reverse

- `basic.Scroll.Reverse`。`layout.RenderViewport.Reverse` と `layout.RenderScrollBar.Reverse` に渡す（`basic.ScrollFrame.Reverse` も同じ）。
- `RenderViewport` は、レイアウトで `lead = 表示の長さ − 子の長さ` を覚え、子を `lead + オフセット` に置く（Reverse でないときは `−オフセット`）。子の位置は SetOffset で決まるので、ヒットテストと `ScrollIntoView` の座標の変換はそのまま正しい。`ScrollIntoView` は、オフセットを増やすと中身が逆向きに動くことだけを考慮する。
- `Scroller`（はずみとバネ）と `ScrollState` は向きを知らない。オフセットは 0 から上限までのままで、行き過ぎの戻りも同じ式で動く。
- ホイールは、中身が動く見た目の向きを Reverse でないときと同じにする。`OnScroll` に渡すノッチ（範囲の終わりの向きが正）の符号だけを反転する。ホイールを手前に回すと中身は上へ、右に振ると中身は左へ動く。範囲の端での行き過ぎも、見た目では同じ側に出る。
- スクロールバーは、オフセット 0 でつまみを右端（下端）に置き、ドラッグとつまみの外の押下も同じ変換で逆にする。

### ScrollController

`collection.ListController` と同じ形にした（ゼロ値で使え、State に置き、`Scroll.Controller` に渡す。Scroll が無い間のジャンプは次の Scroll が受け取る。1 つの Scroll にだけ付く）。

- `JumpTo(offset)`: すぐに動かし、動きを止める。利用者の操作とはみなさない。範囲の外は端に寄せる。最初のレイアウトの前は、レイアウトで上限が分かったときに寄せる。
- `Offset()`: 範囲の始まりからの距離。Scroll が無いときは、待っているジャンプか、最後の Scroll が離れたときの位置を返す。保存して次に開くための値。
- `MaxOffset()`: 前回のレイアウトでの上限。

アニメーションして動かす `ScrollTo` は入れていない。必要になったら Scroller の glide を使って足せる。

## 結果

- `examples/tategaki` の縦組みの枠は `Scroll{Horizontal: true, Reverse: true}` になった。ウィンドウが狭いときは右端の最初の列から見え、広いときは文章が右端に寄る。
- 縦書きのガイド（`docs/guide/*/text-and-ime.md`）に、長い文章をスクロールさせる書き方を足した。
- 下端から始まるログやチャットにも同じ指定が使える。
- 横向きの Scroll は、今も横向きのホイール（タッチパッドの横の動き、`Scroll.X`）だけに反応する。縦のホイールしかないマウスで縦書きを送る方法（縦のホイールを横に読み替える、Shift とホイールなど）は、向きの決め方を含めて別に決める。
- `basic.Scroll` 自体にはキー操作が無い（ADR 0078 の List と同じ）。PageUp などは、アプリが ScrollController に結ぶ。
- `notes` の縦書きモードは `field.Input` 自身がスクロールするので、この変更の対象ではない。
