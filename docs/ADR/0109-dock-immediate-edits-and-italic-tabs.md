# 0109: ドックへの即時の変更と斜体のタブ

決定日: 2026-11-13

状態: 採用

## 背景

DockLayout と TabBar を使うアプリ（コードと Markdown の閲覧アプリ）から二つの報告を受けた。

- **#12** パネルを Dock に足した直後に `DockController.Move` を呼んでも効かない。代わりに `SetArrangement` を使うと、表示中のエクスプローラー（自動で隠れる横の帯から出ているパネル）が引っ込む。アプリは、Dock がタブを受け取った 1 フレーム後に Move を呼ぶことで回避していた。
- **#13** タブの題を斜体にできない。VS Code はプレビューのタブ（次に開いたファイルが置き換えるタブ）を斜体で表すが、アプリは題の前に「◇」を付けて代わりにしていた。

## 原因（#12）

- **Move が効かない。** コントローラーの木がパネルを知るのは、DockLayout の Build の `sync` だけ（ADR 0098 §2「新しいパネルは今の群に入る」）。アプリが同じハンドラーで `Panels` に足して `Move` を呼ぶと、その時点の木にはまだそのパネルが無い。`Move` は「無いパネルは何もしない」で戻り、次の Build でパネルは今の群の最後に入る。`Activate`、`Unpin`、`Close`、`Maximize` も同じだった。`Reset` の直後（木が nil）も、どの操作も効かなかった。
- **SetArrangement で引っ込む。** `SetArrangement` は `load` で木を作り直し、その中で `flyout` を空にしていた（ADR 0102 §6「フライアウトが出ているかどうかは保存しない」を、復元以外の呼び出しにもそのまま当てていた）。加えて、作り直した群はすべて新しい番号になる。番号はタブの帯のキーなので、全部の帯の要素が作り直しになり、今の群（`current`）も最初の群に戻っていた。群に表示中のパネル自体は、各群の `Active` が保存に入っているので引っ込まない（テストで確かめた）。

## 決定

### 1. 足したばかりのパネルを、その場で扱えるようにする

選択肢:

1. 木に無い ID への操作を保留の列に積み、次の `sync` で新しいパネルを入れた後に当てる。操作の順序（保留の後に別の操作が来る）と、保留の間に `Arrangement` が返すものの扱いが複雑になる。
2. 木に無い ID への操作のときに、そのパネルを**その場で今の群に入れて**から操作する。次の Build がするはずのことを先にするだけで、`sync` は手を入れずにそのまま使える。
3. アプリに 1 フレーム待たせる（今の回避）。

2 を選ぶ。

- 非公開の `adopt(id)` を足し、`Move`、`Activate`、`Close`、`Maximize`、`Unpin`、`UnpinGroup` の入口で呼ぶ。
  - 木も帯も閉じたパネルの一覧も知らない ID なら、今の群の最後に入れる。次の Build と同じ置き方。
  - 木が nil（`Reset` の直後）で、コントローラーを表示している DockLayout があれば、その `Panels` と `Default` で先に木を作る。そのため、`Reset` の直後の `Move` も効く。
  - 表示する DockLayout がまだ無い（初めての Build の前）なら、今までどおり何もしない。
- **レイアウトが持たないパネル** は、次の Build の `sync` で木から消える（今までの「知らない ID を捨てる」規則そのまま）。打ち間違えた ID で `Move` を呼ぶと、その Build までの間だけ木に入る。どのメソッドも `refresh` で Build を頼むので、画面に出るのは同じフレームの Build の結果だけになる。
- **Move の先（target）は取り込まない。** 先は「今の配置にあるパネル」、つまり前回の Build のパネルか、前の呼び出しで取り込んだパネルに限る。先まで取り込むと、打ち間違えた先でもパネルが動いてしまうため。二つ足して片方の横に置くときは、先に置く方を先に `Move` すればよい。
- `Show` と `Pin` は隠れたパネルにしか効かないので取り込まない。
- 公開 API の形は変わらない。変わるのは「無い ID は何もしない」が「同じフレームで足したパネルとして扱う」になることだけで、doc コメント（`Activate` にまとめて書き、`Move` から参照）に書いた。
- 前提: アプリはパネルを、その操作と**同じフレーム**で `Panels` に足す（同じハンドラーで SetState する）。core の再ビルドは親から先に進むので、DockLayout の Build は新しい `Panels` を見る。

### 2. SetArrangement は、動かないものの状態を保つ

- **フライアウト。** 出ているパネルが、新しい配置でも**同じ辺に隠れている**なら出たままにする。要素もキーボードも残り、滑り直しもしない。
- **群の帯。** 新しい木の各群に、古い木で「その群の `Active`（無ければ最初に見つかったパネル）を持っていた群」の番号を引き継ぐ。1 つの古い群の番号は 1 回だけ使う。帯の TabBar の要素（フォーカス、スクロール）が残る。
- **今の群。** 番号を引き継いだ群が古い今の群なら、そのまま今の群にする。新しいパネルとキーの行き先が変わらない。
- **動くパネル**（決定）: 配置が勝つ。
  - 出ていたパネルが、新しい配置で群に入る、または別の辺に隠れるなら、フライアウトは引っ込む。群に入ったパネルが見えるかどうかは、その群の `Active` で決まる。
  - 別の辺へ移ったパネルを出したままにしなかったのは、出る辺が変わると滑る向きも矩形も変わり、「その場に残る」とは言えないため。アプリは続けて `Show` を呼べば出せる。
  - 分割の番号（区切りのキー）は引き継がない。区切りには保つべき状態がほとんど無い。
- 最大化は今までどおり `a.Maximized` に従う。`Reset` は今までどおりすべてを捨てる。

### 3. 斜体のタブ（#13）

- **API。** `TabItem.Italic bool` と `DockPanel.Italic bool`。
  - 既存の `Permanent` と同じく、タブの項目の bool のフィールドにした。ゼロ値は立体で、今のタブの見た目は変わらない。
  - より一般の「スタイル」（`text.Style` を渡す口）にはしなかった。タブの文字の大きさや色はテーマが決めるもので、項目ごとに変えてよいのは「プレビュー」という意味を表す傾きだけ。必要になったら別のフィールドを足せる。
  - `Preview` という名前にもしなかった。部品は「次に開いたものが置き換える」という振る舞いを持たず、見た目だけを変えるため。
- **描き方。** タブの題の `text.Style.Italic` を立てる。斜体の書体が無いフォント（既定の和文フォントなど）は ADR 0101 の合成の斜体で傾く。
- **計量と省略。** 合成の斜体は送りを変えない（0101 §4）ので、タブの幅、最小幅、溢れたときのスクロールは立体と同じ。省略は同じ `renderTabTitle` が同じ斜体のスタイルで切るので、「…」も斜体になる。右上のはみ出し（約 0.2em）はタブの右の余白に収まる。
- **ドラッグ。** 別の帯に出る半透明のタブは、運ばれる `TabItem` の `Italic` に従う。帯の中のドラッグはタブ自身が動くので斜体のまま。帯を離れたタブの影は 0098 の残りのとおり今も無い。
- **一覧のメニュー。** すべてのタブのメニューは、今までどおり題を普通の文字で並べる（VS Code の一覧と同じ）。メニューの項目に斜体の口は無く、足さない。
- **スクリーンリーダー。** タブの名前は題そのまま。斜体であることは伝えない（VS Code も伝えない）。
- **ドックの中。** `DockPanel.Italic` は群のタブに加えて、隠れたパネルの帯のタブとフライアウトの見出しの題も斜体にする。同じパネルがどこに出ても同じに見えるように。

### 4. ホットパス

- `adopt` と `SetArrangement` の引き継ぎはアプリの呼び出しの中だけで走り、ホットパスではない。
- 斜体は Build でスタイルの bool を 1 つ立てるだけ。レイアウトと描画の経路は変えていない。`TestTabBar_ItalicLayoutPaintDoesNotAllocate`（斜体のタブを含む帯のレイアウトと描画、100 回で 0 回）を足した。既存のドックの 0 アロケーションのテストもそのまま通る。

## 結果

- テスト（GPU 無し）: `widgets/nav/docklayout_immediate_test.go`、`widgets/nav/tabbar_italic_test.go`。
  - 足した直後の `Move`（群の横、群の中、取り込んだパネルの横）、持たないパネルが次の Build で消えること、足した直後の `Activate`・`Unpin`（と `Show`）・`Close`、`Reset` 直後の `Move`。
  - `SetArrangement` で出ているパネルが出たまま（State とキーボードを保つ）、帯の番号と今の群が残る、別の辺へ移すと引っ込む、群に表示中のパネルが表示のまま。
  - 斜体: 斜体の書体（合成）で描かれ大きさは立体と同じ、名前は題そのまま、省略、別の帯への半透明のタブ、一覧のメニュー、ドックのパネル。
- 既存のテストの変更は一つ。`TestDockController_MoveZones` の「無い ID は何もしない」を「無い ID は次の同期で消える」にし、Move の後に `sync` を挟んだ。
- ギャラリーのドックの頁に、斜体のプレビューのタブ「README.md」を足した。カタログ（`internal/catalog`）のドックの場面は変えていない。
- 残り:
  - 斜体の題の右上のはみ出しが × のボタンに触れるかは、細いタブ（最小幅）では確かめていない。ギャラリーの絵（幅に余裕のあるタブ）では触れない。
  - 初めての Build の前（コントローラーがまだどの DockLayout にも付いていない）の操作は、今までどおり何もしない。
