# 0017: MSAA は要るフレームだけ

決定日: 2026-11-07

状態: 採用

## 背景

ADR 0009 は「フレーム全体を MSAA で描く」と決めた。パスだけを別のターゲットに描くと合成の順序が崩れるため。ADR 0015 のベンチで、これが負けの原因だと分かった。リサイズのピークメモリ 680MB、スクロールの GPU 使用率が Gio の約 2 倍。

ところが MSAA が効くのはラスタライザが形を決めるものだけで、普通の画面には無い。

| 描くもの | 縁の滑らかさ | MSAA |
|---|---|---|
| 角丸、影、グラデーション | SDF（ピクセルシェーダー） | 不要 |
| 文字、64px 以下のパス（アイコン） | アトラスの被覆 | 不要 |
| 画像 | 四角形 | 不要 |
| 大きいパス、形のあるクリップ | ステンシル | **必要** |

## 選択肢

1. パスだけ別のターゲットに描いて合成する。ADR 0009 の順序の問題が残る。
2. SDF のパスに置き換える。任意の形には使えない。
3. フレームごとに、要るかどうかで描き先を切り替える。

## 決定

3 を採る。

- `gpu.Batch.Multisampled` は `DrawQuads` 以外があれば真を返す。
- `gpu.Surface.SetMultisample` で次のフレームの描き先を選ぶ。新しい Surface の既定はオンで、`SetMultisample` を呼ばない使い方は今までと同じ。
- 4x のターゲットは最初に要るフレームで作り、次のリサイズまで持つ。リサイズで捨て、また要るフレームで作る。
- Vulkan はサンプル数がレンダーパスとパイプラインに含まれるので、`framePass` を 2 組持つ。MSAA の組も最初に要るときに作る。

## 結果

切り替えは見た目に出ない。`TestParity_OnDemandMultisamplingLooksTheSame` は、全シーンを両方の経路で描いて比べる。D3D11 と Vulkan のどちらも差は 0 だった。

MSAA を初めて使うフレームは、ターゲットの作成の分だけ遅れる。大きいパスのあるダイアログを最初に開くときなどに出る。Vulkan はパイプラインの作成も重なる。

パスを常に描くアプリは今までと同じコストがかかる。数字は [BENCH.md](../BENCH.ja.md)。
