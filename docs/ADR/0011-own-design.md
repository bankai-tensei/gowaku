# 0011: マテリアルデザインをやめて独自デザインにする

決定日: 2026-11-07

状態: 採用

## 背景

Phase 6 で MD3 を実装したところ、全体が Flutter に見えた。「簡単におしゃれな GUI」が目標で、ピル型のボタン、リップル、浮くラベル、シード色に染まった面は、その目標にも「Go で書ける Flutter の下位互換」と見られない点にも合わない。MD3 はタッチ向けの寸法で、デスクトップの密度にも合わない。

## 選択肢

| 案 | 判断 |
|---|---|
| MD3 のまま | 仕様を判断基準にできるが、見た目の問題が解けない |
| MD3 + 独自の 2 テーマ | 全ウィジェットを 2 通り保守することになる |
| OS ネイティブ風 | Windows と Linux の両方を真似ることになり、ずれると偽物に見える |
| **独自デザイン 1 本** | 判断を自分たちで持つ負担はあるが、軸 2（和文）と揃う |

## 決定

独自デザインを既定かつ唯一にする。Apple の美学を少し取り入れる。仕様は [DESIGN.md](../DESIGN.ja.md)。

- HCT は色計算の基盤として残す。MD3 のロール、エレベーション、状態レイヤー、タイプスケールは消した。
- 背景はベージュにしない。無彩色に見える `f5f5f7`。`theme` のテストが「面が暖色にならないこと」を確かめている。
- アクセントは塗り用（`Accent`）と文字用（`AccentInk`）を分ける。テストが WCAG のコントラスト 4.5 を確かめている。
- ボタンは `Button{Style}` に戻した。Phase 6 の `FilledButton` 系は公開前なので別名を残さない。

### 押す動きは背景だけ

`Decoration.Sink` で背景だけを縮め、文字は動かさない。文字ごと 0.97 にすると、グリフのラスタサイズが整数に量子化されるので（ADR 0010）、等倍の非整数サイズとの間で字が飛ぶ。1px 未満の動きなので、背景だけでも押した手応えは出る。

### SpringValue

`motion.SpringValue` は速度を保ったまま目標を変えられる値。内部は 1000 倍の単位で持つ。`SpringSimulation.Settled` の閾値がピクセル基準で、0〜1 の値にそのまま使うと 0.75 で止まるため。`Set` はコールバックを呼ばないので Build 中に呼べる。

ダイアログだけは固定長の `AnimationController` に `motion.SpringOut` のカーブを使う。閉じ終わりの通知が要るため。

### SegmentedControl は描画を 1 つの RenderObject に

板がスライドするには全セグメントの幅が要る。ウィジェットの組み合わせでは測れないので `layout.RenderSegmented` が子を同じ幅に並べ、板を描く。

### 格子と物理ピクセル

実測で、同じ 1px の線が場所により 2〜3 物理ピクセルに分かれ、濃さも違っていた。原因は 2 つ。

1. 行送りが倍率で、32.4 や 20.8 のような端数を生み、その下の要素が全部小数座標になっていた。行の高さをピクセルで決め、全部偶数にした。
2. 150% では整数の座標でも半ピクセルに落ちる。これはレイアウトでは解けないので `render/snap.go` で角丸矩形を物理ピクセルに揃える。

長さは位置と無関係に丸める（端の座標をそれぞれ丸めない）。端を丸める方法だと、同じ線が場所により 1 と 2 物理ピクセルに分かれ、直したい症状が残る。代わりに隣り合う図形の間に 1 物理ピクセルの隙間が出ることがあるが、今の部品では見えていない。

スケール中の図形と円はスナップしない。押す動きは 1 ピクセル未満なので消えてしまい、つまみは階段状に動くため。枠線の太さだけは常に揃える。押した瞬間に線の太さが変わるとちらつくため。

## 結果

- `widgets` と `theme` の公開 API が変わった。v1 公開前なので互換は考えない。
- 「MD3 と並べて違和感ない」という客観的な基準を失った。代わりに DESIGN.md と gallery が基準になる。
