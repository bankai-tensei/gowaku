# 0107: 表の列は単語の幅より細くしない

決定日: 2026-11-13

状態: 採用

## 背景

`markdown` の表（`renderTable`、ADR 0099）は、列の自然な幅（いちばん広いセルを 1 行に置いた幅）を足して、外に収まらなければ全部の列を同じ比で縮めていた。比で縮めると、短い語しかない列も単語の幅を下回る。そのうえ改行（`jlreq.Breaker.Break`）は、行のどこにも切れる所が無いと最後の手段として語の途中で切る。結果、900px の窓で「banana」が「banan / a」、「100」が「10 / 0」に割れていた。長い説明の列は十分に縮められるのに、短い列が割を食っていた。

`text` には、切れる所でしか切らないときの最小の幅（CSS の min-content）を知る口が無かった。

## 選択肢

1. 比で縮めるのをやめ、どの列にも同じ下限（例: 4em）を付ける。語の長さを見ないので、長い語はまだ割れ、短い列は無駄に広い。
2. 列ごとに「最長の語の幅」を下限にし、残りの幅を列の伸び代に比例して配る（HTML の表の自動レイアウトと同じ考え）。`text` に最小の幅を測る口が要る。
3. 表を横スクロールの中に置き、縮めない。`basic.Scroll` は子に無限の幅を渡すので、長い説明の列も折り返さなくなり、普通の幅の窓で表が横に長く伸びる。

## 決定

2 を採った。

### `text` と `jlreq`

- `jlreq.Breaker.MinWidth(units, opts) float32` を足した。`Break` と同じ準備（`prepare`）をして、改行できる所（`canBreak`）で区切った塊のうち最も広いものの幅を返す。行頭の字下げ・開き括弧の半角の詰め・和欧間の四分アキは `Break` と同じに数える。行末の空白は数えない。ハイフンの位置は改行できる所に数えない（語を割らない幅を求めるため）。ぶら下げの句読点も数えない（ぶら下げる分だけ広めに出るが、割れることはない）。
- `text.Paragraph.MinLength() float32` で公開した。段落のブロックごとの `MinWidth` の最大。縦書きでは列の長さになる。名前は `Layout(maxLength)` に合わせた。どちらもアロケーションしない（テストで確認）。
- 和文は字ごとに切れるので、ふつう 1 字分（禁則で離れない句読点や括弧が付けばその分）になる。数字の並びと欧文の語は 1 つの塊。

### 表の列の幅

- 列の最小の幅 = その列のセルの `renderRich.minWidth()`（`MinLength` を段落ごとに 1 度だけ求めて覚える）+ セルの余白。セルは `Semantics` → `Padding` → `renderRich` の入れ子なので、子が 1 つの所をたどって `renderRich` を探し、余白はセルの自然な幅と文字の自然な幅の差で求める。
- 配り方（`room` は罫線を除いた幅）:
  - 自然な幅の合計 ≦ room: 自然な幅のまま（今までどおり）。
  - 最小の幅の合計 < room: 各列 = 最小 + (自然 − 最小) × (room − 最小の合計) / (自然の合計 − 最小の合計)。伸び代の大きい列（長い説明）ほど縮む。
  - それより狭い: 語すら収まらないので、最小の幅を比で縮める。語は割れるが、表は外にはみ出さない（今までどおり窓に収める方を選ぶ）。
- 浮動小数で余白を足して引くと、文字に渡る幅が最長の語（や自然な幅の 1 行）より 1ulp 狭くなりうるので、最小の幅と自然な幅の両方に 1/64px の余裕（`minSlack`）を足す。最小の幅を自然な幅で頭打ちにするときも、余裕は頭打ちの後に足す（1 語だけのセルで余裕が消え、端数のある幅の「（1）」が割れていた。`TestMarkdown_TableCellWithAFractionalWidthStaysWhole`）。

## 結果

- example の表は 900px の窓で「banana」「100」が 1 行に収まり、説明の列だけが語の間で折り返す。
- テスト: `jlreq.TestJLReq_MinWidth`（欧文の語、数字、和文、禁則、行末の空白、括弧）、`TestJLReq_MinWidthDoesNotAllocate`、`text.TestParagraph_MinLength`（その幅で組むと語が割れない、0 アロケーション）、`markdown.TestMarkdown_TableColumnsKeepTheirWords`（360・480・640px で、どのセルも語の途中で折れない。直す前のコードでは 14 件落ちる）、`TestMarkdown_TableTooNarrowForItsWordsStillFits`。
- 毎フレームの処理は増えない。表のレイアウトは列の数だけの作業領域（`mins`）を使い回す。
- `widgets` の `Table` / `DataTable` は列の幅を利用者が決めるので、この変更の対象外。
