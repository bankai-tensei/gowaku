# 0066: Canvas はパスを写して記録する

決定日: 2026-11-09

状態: 採用

## 背景

- `paint.Canvas.DrawPath` と `ClipPath` は、渡された `*Path` のポインタを次の `Reset` まで持っていた。
- 一方で `layout.Painter` は「毎回の描画で走るのでアロケーションしない」と書いてある。素直に従うと、`paint.Path` を 1 つ持って図形ごとに `Reset` して詰め直すことになる。
- そうすると、同じ描画の中で先に `DrawPath` した図形が、全部最後の中身で描かれる。図形が黙って消える。
  - サンプルのアプリで実際に踏んだ。2 系列のグラフを 1 つのパスで描き、1 つ目の系列の面が消えた。
- 調べると、もう 1 つ同じ根の不具合があった。小さいパス（物理 64px 以下）を焼く `text.Atlas` の形のキャッシュが `*Path` のアドレスを鍵にしていた。
  - 中身を変えたパスを次のフレームで描くと、古い絵がそのまま出る。
  - `RenderProgressRing` は 1 つの `Path` を値が変わるたびに作り直すので、小さいリングでは値の変化が絵に出ないはずだった。

## 決定

### 1. Canvas がパスを写す

- `DrawPath` と `ClipPath` は、記録するときにパスを Canvas が持つ置き場（アリーナ）へ写す。`Op.Path` は写しを指す。
  - 置き場は `[]*Path` と使った数。`Reset` で数を 0 に戻すだけで、写しの `Path` と中のスライスはフレームをまたいで使い回す。育ちきったら写してもアロケーションしない。
  - 各 `Path` は個別にヒープにあるので、置き場が伸びても先に配ったポインタは動かない。
  - `ClipRRect` と、回転の下の `ClipRect` が作っていた形の置き場（`shapes`）も同じ置き場にまとめた。こちらは置き場の上で直接組み立てるので写しは要らない。
- 写すのは、動詞と点だけでなく平らにした形（`flat` / `starts` / `closed` / 外接矩形）とハッシュも。`DrawPath` はもともと `Bounds()` で元のパスを平らにするので、その結果を写すだけで、render 側でもう一度平らにすることは無い。
  - 変わらないアイコンは、元のパスの平らな形がずっと有効なので、平らにするのは中身が変わったときだけで、これまでと同じ。
  - 見えない図形、空の図形は写さない（記録しないので）。
- **変わらないパスは写し直さない。** 置き場の各枠は「前に何から写したか」（元の `*Path`、その変更回数、ハッシュ）を覚える。同じ枠に同じパスが変わらないまま来たら、写しはもうあるので確かめるだけで済ませる。
  - 部品は毎フレーム同じアイコンを同じ順に描くので、定常状態ではほぼ全部これに当たる。
  - 変更回数は `Path` の非公開の `gen` で、`Reset`、`MoveTo` などの追加、`Set` のたびに増える。
  - ハッシュも比べるのは、`*p = other` と値で上書きされたとき、別の中身が同じ変更回数を連れてくることがあるため。
  - `ClipRRect` などが枠を直接使ったら、その枠の記憶を消す。
  - `Rule` は公開のフィールドで変更回数に数えないので、毎回写す。
  - 覚えている元の `*Path` は、枠が使い回されるまで GC から生き残る。置き場の大きさは 1 フレームに描いたパスの数までなので、問題にならない。
- 利用者のコードは、`Path` を好きに使い回してよくなった。`DrawPath` / `ClipPath` / `Path` / `Painter` の doc にそう書いた。

### 2. 公開 API の追加（ADR 0016 の範囲で、足すだけ）

- `(*Path).Set(q *Path) *Path`: q を写す。p の記憶域を使い回す。`math/big` の `Set` と同じ形。
- `(*Path).Equal(q *Path) bool`: 動詞、点、塗りの規則が同じか。
- `(*Path).Hash() uint64`: 動詞と点の FNV-1a。平らにするときに一緒に計算して覚えるので、変わらないパスでは只。`Rule` は含めない（`Rule` は公開のフィールドで、変えても平らな形の無効化が起きないため）。-0 と 0 は同じ値にする（`Equal` が等しいと言うものは同じハッシュになるように）。
- `Op.Path` は「Canvas の写しで、次の `Reset` まで有効」と doc に書いた。型は変えていない。

### 3. アトラスの形のキャッシュは中身で引く

- 写しのアドレスはフレームごとに別の中身を指すので、アドレスを鍵にしたままでは間違った絵が出る。
- 内部の鍵を `{Hash, Scale, Subpixel}` にし、値に絵とパスの写しを持たせた。当たったら `Equal` で写しと比べ、違えば（ハッシュの衝突）焼き直してその場所を取る。
  - 公開の `text.ShapeKey{Path, Scale, Subpixel}` と `Atlas.Shape` の形はそのまま。中で変換する。
  - 当たりの道はアロケーションしない（マップの参照と、小さいパスの `slices.Equal`）。外れのときだけ写しの `Path` を 1 つ作る。
  - 同じ中身の別のパスは 1 つの絵を共有するようになった。中身を変えたパスは新しい絵になる。1 で書いた進捗リングの不具合もこれで直る。

## 検討して捨てたもの

- **ポインタを持ったまま、パスに世代番号を持たせて検出する**: 2 回目の `DrawPath` の時点で 1 回目の中身はもう上書きされているので、検出できても描けない。panic にすると、`Painter` の doc どおりに書いたコードが落ちる。
- **写しを平らな形だけにする**: アトラスは曲線のまま `vector.Rasterizer` に渡すので、動詞と点も要る。写しは memcpy なので全部写す。
- **アトラスをハッシュだけで引く**: 64 ビットなら衝突はまず無いが、起きたら黙って別の絵が出る。小さいパスの比較は安いので確かめる。

## 結果

- 同じ `Path` を 1 フレームの中で使い回しても、どの図形も描かれる。テスト: `paint.TestCanvas_ReusedPathKeepsEachShape`、`TestCanvas_ReusedClipPathKeepsEachShape`、`render.TestEncode_ReusedPathDrawsEveryShape`（ステンシル）、`TestEncode_ReusedSmallPathDrawsEveryShape`（アトラス、次のフレームで中身を変えた場合も）、`text.TestAtlas_ShapeGoesByWhatThePathHolds`。いずれも変更前のコードでは落ちる。
- 定常状態で 0 allocs/op（`TestCanvas_ReusedPathDoesNotAllocate`、ベンチ）。
- ベンチ。変更前と変更後のテストのバイナリを交互に 6 回ずつ走らせた中央値（Windows、20 スレッド。ほかの作業と同居していて揺れがあるので、±5% は誤差）。変更前のバイナリも `Path` は新しいもの（ハッシュの計算を含む）で、Canvas とアトラスだけが古い。

  | ベンチ | 変更前 | 変更後 | 差 | allocs/op |
  |---|---|---|---|---|
  | Canvas_ReusedPath（1 つのパスで 200 点の系列を 8 本） | 21.2µs | 21.8µs | +3% | 0 |
  | Canvas_1kIcons（変わらないパス 1000 個） | 34.3µs | 39.1µs | +14% | 0 |
  | SVG_DrawIcon | 65ns | 61ns | 誤差 | 0 |
  | Canvas_10kRects | 505µs | 500µs | 誤差 | 0 |
  | Canvas_10kTurnedRects | 1.30ms | 1.28ms | 誤差 | 0 |
  | Canvas_DrawShader | 2.5µs | 2.2µs | 誤差 | 0 |
  | Encode_1kSmallPaths（アトラス、記録込み） | 103µs | 120µs | +16% | 0 |
  | Encode_1kLargePaths（ステンシル、記録込み） | 151µs | 155µs | +3% | 0 |
  | Encode_10kRects | 358µs | 354µs | 誤差 | 0 |
  | Encode_CleanLayers | 1.89µs | 1.90µs | 誤差 | 0 |

  - 変わらないパスの記録は 1 個あたり約 5ns 増えた。写し直さない工夫の前は約 36ns 増えていた（1kIcons が 34µs → 70µs）。
  - アトラスの当たりは 1 個あたり約 17ns 増えた。アドレスのマップ引きが、ハッシュの鍵と `Equal` の比較になったため。

- golden は変わらない（`go test -tags gpu ./internal/golden` が通る）。
- 費用: 中身の変わったパスを描くたびに、平らにした点を含めた memcpy が 1 回増える。1 万点のグラフでも 1 フレーム 100KB 台で、平らにする計算より十分安い。置き場は一度大きなパスを持つと容量を持ち続ける（ほかの置き場と同じ）。
