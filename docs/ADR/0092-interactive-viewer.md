# 0092: InteractiveViewer（パンとズームの面）

決定日: 2026-11-13

状態: 採用

## 背景

当初の計画の `InteractiveViewer`。画像ビューア、図面、ノードエディタの土台になる、パンとズームの面である。部品はそろっていた。ピンチと Ctrl+ホイール（ADR 0052）、任意の Affine と、それに従うヒットテスト・IME・Semantics（ADR 0044 の `core.Transformer`）、スプリング（`motion`）。それでも組み合わせは毎回の自作になり、`examples/zoom` は倍率を State に持って毎フレーム作り直していた。

求められたこと:

- ドラッグでパン、ピンチと Ctrl+ホイールでポインタの位置を中心にズーム、倍率の上下限、フリックの慣性はスプリング（ReduceMotion を守る）、境界の有無。
- State に置くコントローラ（ゼロ値で使える）で、変換の読み書き、リセット、全体表示、矩形へのズーム、アニメーションの有無、OnChange。
- フォーカス中のキー操作。
- 子は変換で描くだけで、パンとズームで作り直しもレイアウトもしない。子のヒットテストは逆変換を通し、中のボタンは押せる。ホットパスはアロケーションしない。

## 選択肢

1. **置き場所**
   - (a) `widgets/basic`：`Transform` と `Scroll` の隣。
   - (b) `widgets/interact`：入力を受ける側。
2. **変換の持ち主**
   - (a) State に持ち、変わるたびに `SetState` で `basic.Transform` を作り直す。
   - (b) コントローラに持ち、自前の RenderObject が描画とヒットテストのたびに読む。`ScrollOffset` と同じ形。
3. **素のホイール**
   - (a) ズーム（画像ビューアや Blender の流儀）。
   - (b) パン（ブラウザ、Figma、タッチパッドの 2 本指）。
4. **子のボタンを押してから動かしたとき**
   - (a) core に「祖先が移動を横取りする」仕組みを足し、マウスでもスロップを超えたらパンにする。
   - (b) 今のジェスチャの約束（ADR 0052）に従う。

## 決定

### 1. `widgets/interact` に置く

1(b)。ポインタ、ピンチ、ホイール、フォーカス、キーを受けるのが本体で、`GestureDetector` や `Focus` と同じ段の仕事である。`basic` に置くと `FocusRing` が使えない。`basic.MediaQueryOf`（ReduceMotion）と `kit` は下の段なので使える。上の段（`collection` のノードエディタなど）からも使える。

### 2. API

```go
type InteractiveViewer struct {
	core.StatefulBase
	Controller         *ViewerController
	MinScale, MaxScale float32        // 0 なら 0.1 と 10
	Boundary           ViewerBoundary // ViewerBounded（既定）/ ViewerUnbounded
	BoundaryMargin     float32
	Constrained        bool
	DoubleTapZoom      bool
	Label              string
	OnChange           func(scale float32, offset geom.Offset)
	Child              core.Widget
}
```

`ViewerController` のメソッド: `Scale`、`Offset`、`Transform`、`ToChild`、`FromChild`、`Set(scale, offset, animate)`、`PanBy(d, animate)`、`ZoomBy(factor, focus, animate)`、`Reset(animate)`、`Fit(animate)`、`ZoomToRect(r, animate)`、`Stop`、`Moving`。

- **変換は「倍率 + 子の左上の位置」だけ。** 回転は持たない。ビューアで回す需要は少なく、回すとキャンバスの速い道（平行移動と一様拡大、ADR 0044）から外れる。
- **ゼロ値:** `InteractiveViewer{}` は子なしで動き、`ViewerController{}` は倍率 1・位置 0。倍率の 0 は 1 と読む。
- **`Constrained`（既定 false）:** 既定では子に無限の広さを渡し、子は自分の大きさを取る（大きな図、ノードの面）。true にすると、ビューアの大きさを上限に配る（画像をビューアに合わせたいとき）。無限の大きさを返す子は panic する。ビューア自身は `Scroll` と同じく、与えられた広さを全部取る。
- **境界:** `ViewerBounded` は、子（四辺に `BoundaryMargin` を足した大きさ）がビューアを覆うように位置を丸める。ビューアより小さい軸では中央に置く。`ViewerUnbounded` は丸めない。境界でのゴムのような引っ張りは作らなかった。止まるだけである。
- **`animate`:** bool の引数にした。`Reset(true)` は少し読みにくいが、型付き定数を 2 つ足すほどではない。ReduceMotion のときは常に即時。
- **`Fit` と `ZoomToRect` はビューアの大きさが要る。** 最初のレイアウトの前に呼ぶと覚えておき、レイアウトで即時に適用する。`Set`、`ZoomBy`、`Reset` は前でも値を書き換えるだけで済む。コントローラは変換を持つので、同じコントローラで作り直したビューアは同じ所を見せる。最後に作られたビューアがコントローラを取る（TextFieldController と同じ）。
- **OnChange** は、利用者・モーション・コントローラのどれで変わっても呼ぶ。ただし Build（`DidUpdateWidget`）とレイアウト（リサイズで丸めたとき、待っていた Fit）の中では呼ばず、次の tick に回す。利用者がコールバックで `SetState` してもよいように。

### 3. 変換はコントローラに持ち、自前の RenderObject が読む

2(b)。`renderViewer` は子を 1 度だけレイアウトし、`Paint` でクリップしてから `cv.Transform` で描く。`core.Transformer` を実装するので、`GlobalToLocal`、IME の位置、Semantics の矩形は何もしなくても絵に従う。`HitTest` は逆変換を通して子に渡し、子に当たらなかった所はビューア自身が受けてパンにする。

変わるたびにするのは `MarkNeedsPaint` だけで、Build も Layout も起きない。2(a) だと毎フレーム子の部分木を突き合わせることになり、要件に反する。

拡大はキャンバスの `Scale` の道を通る。文字はその倍率でラスタライズされるので、拡大しても滲まない。代わりに、連続したズームの間は倍率ごとにグリフがアトラスに入る（ADR 0079 の LRU が追い出す）。

### 4. 入力

| 入力 | 動き |
|---|---|
| 背景を主ボタンか中ボタンでドラッグ | 即時にパン。離したときの速さが 60px/s を超えればフリック |
| 指 1 本で背景をドラッグ | 同じ（core はビューアの押下をそのまま配る。ビューアは `PanYielder` にしない） |
| 子のボタンを指で押して 8px 以上動かす | core がボタンの押下を取り消し、スクロールとして配る（ADR 0052）。ビューアは指の動きのとおりにパン |
| 子のボタンをマウスで押して動かす | パンしない（ボタンが押下を持ち続ける）。中ボタンのドラッグならボタンの上からでもパンできる |
| ピンチ、Ctrl+ホイール | ポインタの点を固定してズーム。上下限で止まっても、その点は動かない |
| 素のホイール | パン。縦、Shift で横、横ホイールは横 |
| タッチパッドの 2 本指（端数の notch） | 即時にパン |
| クリックの止まるホイール（整数の notch） | `Scroll` と同じ 40ms の滑り |
| 矢印キー | 40px 滑ってパン |
| `+` `=` `-` `0`（文字）、Ctrl+`=` `-` `0`（キー） | 中央を固定して 1.25 倍・1/1.25 倍、0 は倍率 1 に戻す（滑らかに） |
| ダブルクリック・ダブルタップ | `DoubleTapZoom` のときだけ。2 倍に寄るか、拡大中なら倍率 1 に戻る |

- **素のホイールはパン**（3(b)）。タッチパッドの 2 本指は Windows でもホイールとして来るので、ホイールをズームにすると 2 本指でパンできなくなる。ズームは Ctrl+ホイールとピンチ（タッチパッドのピンチは DirectManipulation か Ctrl+ホイールで来る）に任せた。OS が付けるタッチパッドの慣性はホイールのまま来るので、ホイールには自前の慣性を付けない。
- **境界のあるビューアが動けないホイールは親に渡す**（`Handled` にしない）。ページの `Scroll` の中に置いた図が端まで来たら、ページが続けてスクロールする。境界のないビューアは常に受ける。
- **子のボタンからのドラッグ**は 4(b)。マウスで core に横取りの仕組みを足すと、`Draggable`、スライダー、ノードを動かすドラッグなど、押下を持つ物すべての約束に触れる。デスクトップの図面ツールも、ボタンの上からの主ボタンのドラッグではパンしないのが普通で、代わりに中ボタンでパンする。指はすでに core の約束（PanYielder）があるので、そのまま乗った。
- **`+` を文字で受ける。** キーコードの `=` は US 配列でしか `+` の位置に無い。JIS 配列やテンキーの `+` は文字としてなら届く。Ctrl 付きは文字にならないので、キーで受ける。キーと文字の両方で受けないようにして、1 回の押下で 2 回ズームしない。
- **ダブルクリックは既定で切った。** ノードエディタでは背景のダブルクリックに「ノードを足す」などの意味がある。
- **フォーカス:** ビューアは Tab で止まり、背景を押すとフォーカスを取る。キーボードで来たときだけ `FocusRing` を出す。子の中のボタンにフォーカスがあるとき、ボタンが使わなかった矢印キーはビューアに上がってくる（core の FocusTarget の連鎖）。

### 5. モーション

1 つの Ticker で、3 種類のどれか 1 つを動かす。どれも値だけの構造体で、アロケーションしない。

- **フリック:** 軸ごとに臨界減衰のスプリング（`motion.CriticalSpring(12)`）を、今の位置と速度から「速度 / ω」先（ω = √12）に向けて走らせる。この目標だと解は純粋な指数減衰になり（速度は 1/ω 秒ごとに 1/e）、摩擦で止まるのと同じ見え方で、行き過ぎない。境界に当たった軸はそこで止める。速度はドラッグの最後の 100ms の 2 点から測り、離す前に 40ms 以上止まっていたら慣性は無い。最大 8000px/s。
- **滑り（ホイールの notch、矢印キー）:** `Scroll` と同じ指数の接近（40ms）。動いている間の次の notch は、行き先から足す。
- **アニメーションの移動（コントローラ、キーのズーム、ダブルクリック）:** 0 から 1000 へのスプリング（剛性 300、約 0.4 秒）で進み具合を作り、倍率は等比で、ビューアの中央に見える子の点は直線で動かす。始点と終点の位置を直線で補間すると、ズームしながら弧を描いて流れて見えるため。
- **ReduceMotion:** フリックはしない。滑りもアニメーションも即時に移る。押下、ピンチ、別の移動は、動いているモーションをその場で止める。

### 6. Semantics

`RoleGroup` に `Label`、値は倍率の百分率（「125%」）、アクションは Increase / Decrease（中央を固定して 1.25 倍・1/1.25 倍）。semantics にスクロールやズームのアクションは無いので、増減で代えた。子のノードの矩形は `Transformer` を通るので、画面に見えている場所で読み上げの枠が出る。

- テスト（GPU なし）: ドラッグのパン、中ボタン、Ctrl+ホイールでポインタの下の点が動かない、ピンチ（2 本指のタッチも）、上下限、既定の上下限、境界・余白・境界なし、小さい子の中央寄せ、フリックが止まる・境界で止まる・止まってから離すと慣性なし・押下で止まる、ReduceMotion、変換を通した子のヒットテスト、マウスでボタンから動かしてもパンしない、指はスロップを超えるとパンしてタップしない、ホイール・タッチパッド・Shift、境界で動けないホイールは親へ、コントローラの各メソッド（即時とアニメーション）、レイアウト前のコントローラ、作り直し、リサイズでの丸め、Constrained、パンとズームで子をレイアウトしない（`wtest.LayoutCount`）、キー、ダブルクリック、Semantics、ゼロ値、コントローラの差し替え、上下限の panic、速度の計測が時計の一周をまたぐ。
- ベンチ（i7-12700H）: パン 1 フレーム 412ns・0 allocs、ズーム 645ns・0 allocs、アニメーション 542ns・0 allocs、ズーム中のヒットテスト 130ns・0 allocs。木を通してポインタを配ると 1 フレームに 1 回（64B）のアロケーションがあるが、これは `core.Tree.deliver` がイベントの写しをインターフェース越しに渡すためで、どのウィジェットのポインタイベントでも起きる（ビューア側では直していない）。
- カタログのページ `examples/gallery/pages_viewer.go`。1600×1200 の方眼の図に図形とボタンを置き、「全体を表示」「等倍に戻す」「中央の円へ」と倍率の表示を付けた。倍率の表示は小さな State だけを作り直し、図は作り直さない。

## 残したこと

- マウスの主ボタンで、子のボタンを押してから動かしたときのパン（4(a)）。要るなら core に横取りの仕組みが要る。
- 子のボタンを指で押して始めたパンの慣性。core はそのパンの終わりを配らない（ADR 0052 の残し）。背景から始めた指のパンには慣性がある。
- 2 本指のピンチ中の、中点の移動によるパン。core のタッチのピンチは距離の変化しか配らない。
- 回転、境界でのゴムのような引っ張り、倍率の段（スナップ）、見えている範囲だけを作る仮想化（巨大なノードの面では、子は全体を描く）。
- 実機での確認: タッチパッドのピンチと 2 本指のパン、タッチ画面、スクリーンリーダーでの読み上げは、この環境では注入とテストだけで確かめた。
