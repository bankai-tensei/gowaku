# 0039: UI のファイルは gowaku 1 つの import で書け、ドットインポートを勧める

決定日: 2026-11-08

状態: ADR 0081 で置き換え

## 背景

見本アプリ（約 2000 行）を書くと、構造体リテラルの入れ子が深くなるうえに、接頭辞が繰り返し出てきた。数えると次のとおりだった。

- `gowaku.` が 548 回、`[]gowaku.Widget{` が 77 回出てくる。
- `layout.MainMin`、`theme.Space12`、`geom.Offset`、`paint.Stroke` のような下の層の名前も、合わせて約 300 回出てくる。
- gowaku 関係の import が、ファイルの数をはるかに超える 41 行ある。

既存のヘルパー（`VStack` など）は `Cross` も `Spacing` も設定できない。見本アプリ の `Row` / `Column` の大半は、この 2 つを設定している（`Size: MainMin, Cross: CrossStretch` だけで 14 回）。関数オプションとメソッドチェーンは規約 §5.3 で禁じているので、ヘルパーに設定を渡す手段は増やせない。

## 選択肢と決定

- (a) `Cross` や `Spacing` を引数に取るヘルパーを増やす。引数が 4 つを超えるとオプション構造体が要る、という規約に当たり、結局は構造体リテラルと変わらない。
- (b) 子の並びの型に短い別名を付ける（`type Ws = []Widget`）。`[]gowaku.Widget{` が `gowaku.Ws{` になるだけで、ほとんど短くならない。
- (c) UI のファイルが必要とする名前を、すべてルートから再エクスポートする。そのうえで、UI のファイルではドットインポートを勧める。

**(c) を採る。** 足したのは次の名前。

- `KeyCode` と主なキー
- `StackFit` と `StackExpand`
- `TextAlign` と `TextAlignStart` などの行の揃え。`AlignCenter` は箱の中の位置の名前としてすでに使っているので、接頭辞を付けた。
- `Gradient`、`GradientStop`、`GradientKind`、`MaxGradientStops`
- `RRect` と `RRectAll`
- 曲線の `Linear`、`Standard`、`SpringOut`

ドットインポートは一般には勧められない書き方なので、勧めるのは UI のファイルに限る、とパッケージの doc に書いた。そのファイルでは、名前のほとんどがこのパッケージから来るからである。staticcheck の ST1001 を切ることと、アプリのパッケージレベルの名前とぶつかったときの対処も、あわせて書いた。

入れ子の深さそのものは変わらない。これは Flutter も同じで、Go に末尾ラムダも型の省略もない以上、ここが限界だと判断した。

## 結果

見本アプリ を書き換えて、変わる前と後で比べた。

| | 前 | 後 |
|---|---:|---:|
| 行数 | 1978 | 1947 |
| バイト数 | 71,228 | 64,025（−10%） |
| gowaku 関係の import の行 | 41 | 10 |
| `gowaku.` などの接頭辞 | 約 850 | 0 |

6 画面のスクリーンショットは、書き換えの前と後でピクセル単位まで一致した。`[]Widget{` は 77 回のまま残る。
