# 0038: macOS 対応を v2 の最後のフェーズに回す

決定日: 2026-11-08

状態: 採用

## 背景

v2 では、Phase 11（縦書きと組版）の次に Phase 12 として macOS を置いていた。ところが、大手のフレームワークと比べて足りないもの（スクリーンリーダーへの接続、メニュー、タブ、表、ツリー）は、どれも Phase 13 以降にある。そこでヒアリングをして、macOS は最後に置くことにした。

## 決定

macOS を最後の Phase 17 に回し、その間のフェーズの番号を 1 つずつ前に詰める。v2 の公開（notes サンプルが 3 OS で動くこと）は Phase 17 の完了条件に移す。

| 旧 | 新 | 内容 |
|---|---|---|
| 12 | 17 | macOS と v2 公開（NSAccessibility、Finder からの DnD、sbix 絵文字、ベンチの 3 OS 更新を含める） |
| 13 | 12 | アクセシビリティ（UIA / AT-SPI2） |
| 14 | 13 | 描画拡張 |
| 15 | 14 | OS 統合（メニュー、DnD、トレイなど） |
| 16 | 15 | ウィジェット拡充（タブ、表、ツリー、Navigator など） |
| 17 | 16 | ツール（Inspector など）。完了条件は Windows と Linux の 2 OS |

ADR 0022〜0024 にあるフェーズ番号は旧番号のまま残し、この表で読み替える。当初の計画と DESIGN は新しい番号に直した。

## 影響

- **利点：** スクリーンリーダー、メニュー、タブ、表、ツリーが、macOS の 5〜6 週間分だけ早く揃う。
- **リスク：** Phase 12〜16 の API（`A11yBridge`、メニュー、DnD、トレイ）を、macOS で確かめないまま決めることになる。対策として、決めるときに NSAccessibility、`NSMenu` など Cocoa の対応する API と突き合わせる。合わない所が出たら、Phase 17 で ADR を書いて直す。
- purego/objc と Metal が安定しない場合は、これまでどおり 2 週間で見切りをつける。ただ、送る先は「後ろのフェーズ」ではなく v3 になる。
