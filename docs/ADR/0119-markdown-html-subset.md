# 0119: Markdown の中の HTML を安全な部分集合だけ解釈する

決定日: 2026-11-14

状態: 採用

## 背景

gowaku の Markdown を使うアプリ（Nople）で gowaku 自身の README.ja.md を開くと、先頭の `<p align="center">` の塊（`<picture>` のワードマーク、`<b>` の一文、`<a><img></a>` のバッジ）がすべてタグの文字のまま出た。ADR 0099 は生の HTML を「解釈せず、書いたままの文字として出す」としていた。

GitHub の README は、中央揃え、ダークテーマ用の絵、バッジ、折りたたみ（`<details>`）、絵の表をほぼ HTML で書く。これが文字で出ると、README を読む用途で使えない。

守ること:

- スクリプト、スタイル、イベントハンドラーは決して動かさない。ライブラリはネットワークに出ない（ADR 0099 のまま）。
- 解釈しないものは今までどおり文字で出す（消さない）。
- Layout と Paint はアロケーションしない。解析はアロケーションしてよいが、入力の長さに線形。

## 選択肢

1. **HTML の木を作るパーサ（golang.org/x/net/html）を入れる**。依存が 1 つ増える（ADR 0099 の「本体 + x/text だけ」に反する）。HTML5 の木の構築の全規則は、README の範囲には要らない。
2. **CommonMark の規則で HTML の範囲を見つけ、中を小さな字句解析器で読み、許可したタグだけを今の AST（block / inline）に写す**。ウィジェットへの変換、見出しのアンカー、選択とコピー、リンクの扱いは今の仕組みがそのまま使える。
3. **README の決まった形だけをパターンで拾う**。少し形が変わると壊れる。

2 を採った。

## 決定

### 1. HTML の範囲（ブロック）

CommonMark 0.31 の HTML ブロックの開始と終了の条件（4.6、型 1〜7）をそのまま実装した（`htmlblock.go`）。GitHub と同じ所が HTML になる。

- 型 1（`<pre` `<script` `<style` `<textarea`）は対の閉じタグのある行まで、型 2〜5（コメント、処理命令、宣言、CDATA）はそれぞれの終わりの印のある行まで、型 6（ブロックの要素名）と型 7（完全なタグだけの行）は空行まで。
- 型 7 は段落を割り込めない（`a` の次の行の `<img src=x>` は段落の中のインラインの HTML）。型 1〜6 は割り込める。
- 行の先頭の 3 桁までの字下げは HTML ブロックの中身に入る。リストや引用の中でもブロックとして開く。

### 2. ブロックをまたぐ要素と、中の Markdown

CommonMark では HTML ブロックは空行で終わり、その後は Markdown に戻る。GitHub はでき上がった HTML をブラウザが読むので、次のように書くと Markdown の部分が `<details>` の中に入る:

```
<details>
<summary>もっと</summary>

- 中の **Markdown**

</details>
```

これに合わせた。ある容器（文書、引用、リストの項目）の子の列で、HTML ブロックの字句と、その間の Markdown のブロックを 1 本の列にして、小さな木の構築器（`treeBuilder`）に通す（`htmltree.go`）。

- 入れ子にするのはブロックの要素（`p` `div` `h1`〜`h6` `details` `summary` `table` `thead` `tbody` `tfoot` `tr` `td` `th` `pre`）だけ。文字とインラインのタグは平らな列のまま残し、後で対にする（§4）。
- 暗黙に閉じるもの: ブロックの要素の開始は開いている `<p>` を閉じる。見出しは見出しを閉じる。`<tr>` は表の中でだけ開き、`<td>` / `<th>` は `<tr>` を補う。閉じタグは、開いている同じ名前の要素までを閉じ、無ければ捨てる。セルの外へは閉じない。
- **Markdown のブロックが入れるのは `div` `details` `td` `th` だけ**。`<p>` や見出しの中に Markdown のブロックが来たら、ブラウザで内側の `<p>` が外側の `<p>` を閉じるのと同じく、そこで閉じる。つまり `<p align="center">` の後に空行を置いて書いた Markdown は中央に揃わない（GitHub と同じ）。`<div align="center">` の中の Markdown は揃う。
- HTML ブロックの中の文字は Markdown として読まない（`<p>**x**</p>` は `**x**` のまま。CommonMark と GitHub と同じ）。文字参照は読む。
- 要素の入れ子は 32 段まで（`maxNesting`）。数え始めは容器の深さ（引用、リストの項目、details の数）で、それより深い開始タグは捨てて中身を今の要素に入れる。木の深さが入力の長さに比例しない。処理は容器ごとに上から下へ（外の `<details>` を先に作る）なので、details の中の引用の中の details も同じ上限に入る。

### 3. タグの字句解析

`scanTag`（`htmltag.go`）が開始タグと閉じタグを読む。名前は大文字小文字を区別せず小文字にし、属性は引用符あり・なし・値なしを読み、値の文字参照を戻す。自己終了の `/>` も読む。

- Markdown の文中（インラインの生の HTML）は CommonMark の文法どおり厳密に読む。合わなければ `<` は文字。
- HTML ブロックの中はブラウザ寄りに緩く読む（引用符の無い値は空白か `>` まで）。
- どちらも名前と引用符の無い値に `<` を含めないので、走査は次の引用符の外の `<` で止まる。すべての `<` から走査しても線形。
- コメント、処理命令、宣言、CDATA は出さない（ブラウザが出さないので）。文中で閉じていないものは CommonMark どおり文字。HTML ブロックの中で閉じていないものは残りを全部コメントとして捨てる（ブラウザと同じ）。文中で一度閉じの印が見つからなかった種類は、以降探さない（`<!--` が 3 万個あっても毎回末尾まで探さない）。
- 解釈しない要素のタグは書いたままの文字にする。`script` `style` `textarea` `title` `iframe` `noscript` など中身が生の文字の要素は、閉じタグまでの中身も書いたままの文字にする（中の `<b>` を解釈しない）。

### 4. 対にすること（インライン）

文中の HTML も、HTML ブロックの中の文字の列も、同じ `pairTags` で開始タグと閉じタグを対にして要素にする。

- Markdown の強調やリンクの中にタグがあってよい（子の列ごとに対にする）。
- 閉じていない要素は列の終わりまで（ブラウザと同じ）。開始の無い閉じタグは捨てる。入れ子は 32 段まで。
- `<a>` の中の Markdown のリンク、Markdown のリンクの中の `<a>` はリンクを入れ子にしない（外側が勝つ）。

### 5. 解釈するタグと属性

| タグ | 解釈 |
|---|---|
| `p`, `div` | `align="left|center|right"`（`middle` も中央）。`div` の揃えは中の段落、見出し、絵の行、Markdown の段落と見出しに効く（継承）。リスト、コード、引用、表の中身には効かせない |
| `h1`〜`h6` | 見出し。`align` も。Markdown の見出しと同じく slug を持ち（ADR 0106 の規則）、`Headings()` / `Controller` に出て、`#` のリンクで移る。絵だけの見出し（`<h1><img alt="gowaku"></h1>`）は代替テキストが文字になり、アンカーは絵を囲む箱が持つ |
| `details`, `summary` | 折りたたみ。`open` が無ければ閉じている。最初の `summary` が見出しの行（無ければ「Details」）。押すか Enter / Space で開閉。支援技術にはボタンで、`Expanded` / `Collapsed`。開閉の状態は State に持ち、文書が替わると捨てる。閉じた details の中の見出しへのリンク（と `Controller.ShowHeading`）は、ブラウザと同じく details を開いてから移る |
| `img` | `src` `alt` `width` `height`（§6） |
| `picture`, `source` | `media="(prefers-color-scheme: dark|light)"` と `srcset`（§6） |
| `a` | `href` があり安全（§8）なら Markdown のリンクと同じリンク（`OnLinkTap`、ADR 0106 の `#` のアンカーと `OnAnchorTap`、Tab のフォーカス、選択の扱い）。`href` が無い `<a name>` などは中身だけ |
| `b`, `strong` / `i`, `em` / `s`, `del`, `strike` / `code` | Markdown の強い強調・強調・取り消し線・コードと同じ |
| `kbd` | キーキャップ: 等幅、コードの地に 1px の枠（`Rule` の色） |
| `sub`, `sup` | 0.75 倍の大きさで、下付きは 0.2em 下、上付きは 0.4em 上に描く。テキスト層にベースラインをずらす口が無いので、`renderRich` がレイアウトのときに該当する字の連なり（run）を求め、Paint でその run だけ原点をずらす。選択の矩形とキャレットはずらさない |
| `br`, `hr` | 改行、区切り線 |
| `pre` | コードブロック（中のタグは捨て、文字だけ。先頭の改行 1 つを除く） |
| `table`, `thead`, `tbody`, `tfoot`, `tr`, `td`, `th` | 表（README の絵の表のため。タスクの範囲の外だが、README.md / README.ja.md にあり、文字で出ると壊れて見えるので入れた）。セルはブロックを持て、絵も入る。列の幅は Markdown の表と同じ配り方（ADR 0107）。最初の行がすべて `th` のときだけ見出しの地を塗る。`td` / `th` の `align`。欠けたセルは空。セルの外の文字は表の前の段落に出す |

これ以外の属性（`style`、`class`、`id`、`on*` など）は読むだけで使わない。ほかの要素（`span`、`ul` / `li`、`center`、`font`、`iframe`、`form`、`input`、`object`、`script`、`style` など）のタグは**書いたままの文字**として出す。GitHub は知らないタグを消して中身だけ出すが、「解釈しないものは今までどおり文字」の方を取った（何が解釈されなかったかが見える。危険なものも害なく見える）。

### 6. 絵

- **相対パス**は Markdown の画像と同じく `Images`（`fs.FS`）か `ImageProvider` から。
- **SVG**: 名前が `.svg` で終わるファイルは `paint.ParseSVG` で読み（8 MiB まで）、`layout.RenderSVG` で描く。文字は上の `text.Shaper` で `SetText` する。`currentColor` はテーマの Ink。Markdown の `![](x.svg)` も同じになった（ADR 0099 の追記の「SVG は読まない」を置き換える）。`basic.SVG` は正方形にしか描けないので使わず、`shrinkBox` の中で `RenderSVG` を直接使った（本体は変えていない）。大きさは SVG の `width` / `height`、無ければ viewBox、それも無ければ 150×150。
- **width / height**（CSS の px。`280` と `280px` を読む）: 両方あればその大きさ、片方だけなら絵の縦横比で他方を決める。`width="50%"` は使える幅に対する割合（高さは比で決まる）。高さの % は読まない。どれも文書の幅より広ければ比を保って縮める。上限は 16384。
- **ImageProvider** が返したウィジェットには、`width` と `height` の両方があるときだけその大きさを与える（片方だけでは比が分からない）。
- **picture**: テーマが暗いときは `prefers-color-scheme: dark` の source、明るいときは `light` の source、どちらも無ければ `img`。`media` の無い source はどちらにも合う（ブラウザと同じく最初に合ったものを使う）。ほかの media（`min-width` など）と、読めない `type`（`image/avif` など）の source は捨てる。テーマは `basic.ThemeOf` で読むので、テーマが替われば作り直されて絵も替わる（読んだ絵は両方とも State の表に残る）。
- **srcset** は密度の記述子を見て `1x`（か記述子なし）の候補、無ければ最初の候補。高密度の画面でも 1x を使う（どの絵を出すかは 1 つに決めたい。2x の絵を縮めて出す最適化はしない）。
- GitHub の `#gh-dark-mode-only` / `#gh-light-mode-only` で終わる画像の宛先も、そのテーマのときだけ出す（Markdown の `![]()` でも HTML でも）。
- **リモートの URL**（`https:` など）は今までどおり取得しない。`ImageProvider` があればそこへ（テーマで選んだ宛先を渡す）、無ければ代替テキスト。
- **代替テキストの見た目**: 絵の出ない画像は、文の中ではその位置に代替テキストを文字として出す（ADR 0099 と同じ灰色。リンクの中ならリンクの色と下線）。README のバッジは「Go Reference CI MIT License」が中央に 1 行に並び、それぞれが押せるリンクになる。段落にその画像 1 つだけのときは今までどおり灰色の斜体のブロック（`RoleImage`）。

### 7. 空白と並び

- HTML の中の文字の空白は HTML と同じく畳む: 連続する空白は 1 つ、ブロックの最初と最後と `<br>` の後ろの空白は捨てる、要素の境をまたいだ連続も 1 つ。改行を含む空白はソフト改行にするので、全角どうしの間には何も入らない（ADR 0099 の Markdown と同じ。ブラウザは空白を入れる）。
- **絵の行**: 段落の中で、単独の絵（画像か、画像だけを包むリンク）が空白だけを挟んで続くものは 1 つの行（`basic.Wrap`、下揃え、幅いっぱい）に並べ、揃えに従って寄せる。間に空白があれば 4px、無ければ 0。`<br>` で行を変える。行の前後の文字は別の段落になる（文と絵が 1 行に混ざる組版はしない）。Markdown の段落でも同じなので、`[![a](a.svg)](x) [![b](b.svg)](y)` のバッジも 1 行に並ぶ（今までは絵ごとにブロックだった）。

### 8. 安全

- `javascript:` `vbscript:` `data:` の宛先（大文字小文字、途中のタブや改行、先頭の空白や制御文字を除いて比べる）は、HTML の `<a>` でも Markdown のリンクでもリンクにしない（文字だけ残す）。`OnLinkTap` には決して渡らない。`img` の `src` と `srcset` でも捨てる。
- `style` 属性と `<style>` は解釈しないので、色、位置、大きさを文書が変えることはない。`on*` 属性も読まない。スクリプトを動かす仕組みはそもそも無い。
- 読むファイルは `Images` の中だけ（`fs.ValidPath`）。ネットワークには出ない。

### 9. 選択とコピー（ADR 0105）

HTML から作った段落、見出し、セルは Markdown のものと同じ `renderRich` なので、選べてコピーできる（ブロックの間は空行、セルの間はタブ）。絵はコピーに入らず、代替テキストを文字で出した画像は文字として入る（ADR 0105 の画像の規則のまま）。summary の文字はボタンの中なので、リンクと同じく選択に入らない。

### 10. ホットパス

- `renderRich` に足したのは `<kbd>` の矩形、`sub` / `sup` の run ごとのずれ、もう 1 つの幅のレイアウト（下記）。どれもレイアウトの幅が変わったときに作り、Paint は読むだけ。
- **表のセルのレイアウトのアロケーションを無くした**: 表はセルを無制限の幅と列の幅で 2 回レイアウトするので、`renderRich` は幅が替わるたびに `text.Paragraph.Layout` をやり直していた（Markdown の表もそうで、表のある文書をレイアウトし直すたびにアロケーションしていた）。直前の幅のレイアウトと飾りの位置を 1 組だけ持っておき、同じ幅に戻ったら入れ替える。
- 確認: `TestHTML_PaintAndLayoutDoNotAllocate`（README.ja.md 全体を `SelectionArea` と `Scroll` に入れ、Paint と、全ノードを汚してのレイアウトの両方で `AllocsPerRun` = 0）。

### 11. 解析の費用

文字列の長さに線形。`TestParse_Pathological` に HTML の病的な入力 17 種（閉じない属性、閉じないコメント・宣言・処理命令・CDATA、`<div>` / `<b>` / `</b>` / `<td>` / `<script>` の山、食い違うタグ、型 6 と型 7 の行の山、source の山など、3 万文字規模）を足し、どれも 30ms 以内。`FuzzParse` に HTML の seed を足し、タグの字句解析器の `FuzzHTMLTags`（`scanTag` の長さと `raw` の一致、`markupEnd` の範囲、トークンが入力を超えないこと、木の深さ）を足した。このマシンで各 30 秒（FuzzHTMLTags 110 万回、FuzzParse 270 万回）、失敗なし。

## 結果

- README.md / README.ja.md の先頭が GitHub と同じ意図で出る: 中央のワードマーク（ダークテーマでは白い版）、中央の太字の一文、中央に 1 行のバッジ（代替テキストのリンク）、中央の言語のリンク、中央の 584px のスクリーンショット（テーマで替わる）。下の絵の表も 2×2 で出る。
- API の変化: 公開の型と関数は変わらない。`Markdown` の doc コメント（HTML の部分集合、`Images` が SVG を読むこと、`ImageProvider` が受ける宛先と大きさ）と `doc.go` を直した。挙動の変化は、生の HTML の解釈、SVG の画像、絵の行、`javascript:` のリンクが文字になること、HTML のコメントが出なくなること。
- テスト: `html_test.go`（HTML ブロックの範囲と木 35 件、インライン 16 件、HTML の見出しの slug、`scanTag`、型の判定、`safeURL`、長さ）、`htmlview_test.go`（README の先頭、テーマで替わる picture と gh-*-mode-only、絵の大きさと SVG 10 件、絵の行、details の開閉とアンカーで開くこと、絵だけの見出しのアンカー、危険なリンク、kbd / sub / sup、コピー、アロケーション、スクリーンショット）。既存のテストのうち、生の HTML を文字として期待していた 4 件を新しい挙動に直した。
- スクリーンショット: `TestHTML_ReadmeShots` を `MARKDOWN_SHOTS` に書き出し先を入れて走らせる（README の日英の先頭、絵の表、HTML の見本、それぞれ明暗）。

## 残したこと

- `ul` / `ol` / `li`、`blockquote`、`dl`、`center`、`span` などは文字のまま。要望が出たら §5 の表に足す（木の構築器はブロックの要素を入れ子にできる）。
- 文と絵を 1 行に混ぜる組版（インラインの絵）。今は絵の行と文の段落を分ける。
- `vertical-align`、セルの `width`、`colspan` / `rowspan`。セルの中身は上揃え。
- `<a name>` / `id` へのアンカー（GitHub は `user-content-` を付ける）。
- 高密度の画面での `2x` の絵。
- 閉じた details の中の見出しは `Headings()` には出るが、移るまでは描かない（移ると開く）。
- 名前付きの文字参照は ADR 0099 の約 40 個のまま。
