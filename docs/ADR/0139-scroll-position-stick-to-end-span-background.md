# 0139: スクロール位置の読み取りと末尾への追従、再構築前のジャンプ、スパンの背景色、ルビの読み上げ

決定日: 2026-11-17

状態: 採用

## 背景

初めて使う人に、ログビューア、チャット、アドレス帳を作ってもらったところ、次のことが分かった。

1. **`collection.List` の位置が読めない：** オフセットも、末尾にいるかどうかも読めず、スクロールの通知も無かった。ログやチャットでよくある「末尾にいる間は新しい行に追従し、上に戻したら止まる」を作れなかった。
2. **追加の直後の `JumpToEnd` が古い末尾に飛ぶ：** 行を足す `SetState` の直後に `ListController.JumpToEnd()` を呼ぶと、リストはまだ再構築されておらず古い `ItemCount` のままなので、古い最後の行に飛んだ。`After(1ms)` で遅らせて回避していた。`basic.ScrollController.JumpTo` も、前回のレイアウトの最大オフセットで切り詰めるので同じだった。
3. **スパンに背景色が無い：** 検索の一致を示すのに、太字のアクセント色の文字で代用していた。
4. **ルビの読み上げが書かれていない：** ルビ付きの `RichText` をスクリーンリーダーがどう読むか、ルビを探す人が見る場所に書いていなかった。

## 選択肢

### 通知の形

- **A. ウィジェットの `OnScroll func(basic.ScrollPosition)`。** 他の `On` と同じで、コントローラーが無くても使える。
- **B. コントローラーにリスナーを登録する。** 登録と解除が要り、パッケージのほかの部品に例が無い。

A を採った。コントローラーは同じ位置を読むメソッド（`Position`、`AtEnd`）を持つ。

### 末尾への追従

- **A. ウィジェットの `StickToEnd bool`。** 末尾にいる間だけ追従し、ユーザーがスクロールで離れたら止まり、末尾に戻ったら再び追従する。
- **B. アプリが `OnScroll` と `JumpToEnd` で作る。** 毎回同じコードになり、追加とレイアウトの順序を正しく扱うのが難しい（2 がその例）。

A を採った。「末尾にいる」は、動きが止まった時点でオフセットが最大オフセットの 0.5 ピクセル以内にあることとする。ホイールやスクロールバーの操作で追従を外し、動きが末尾で止まったら戻す。コードのジャンプ（`JumpToIndex(0, 0)` など）で末尾から離れた場合も外れる。

### 再構築の前に頼まれたジャンプ

- **A. 文書に「再構築の後に呼ぶ」と書く。** アプリには再構築の後に呼ぶ手段が無い（それが `After` の回避策だった）。
- **B. ジャンプはすぐに適用し、次のレイアウトでもう一度適用する。** 行の番号（`JumpToEnd` は「最後の行」）は適用するときの行数で解釈する。ジャンプの直後に `Offset` を読めば、今ある内容の範囲で移った位置が返る。
- **C. 次のレイアウトでだけ適用する。** 直後に読む `Offset` が古いままになる。

B を採った。

### `Scroll{Reverse}`（チャット）

`Reverse` の範囲は下端から始まり、内容が伸びても下端は動かない。最新の行を下に置くチャットは、表示が下端にある間、`StickToEnd` なしで最新の行に留まる。`StickToEnd` は範囲の終わりに追従するので、`Reverse` では上端（縦書きでは左端、つまり文章の終わり）に追従する。これを `Scroll` の godoc に書いた。`Reverse` で上に戻して読んでいる間に下に行が足されると、オフセット（下端からの距離）が保たれるので、読んでいる行は上に動く。足されたのが上（古い履歴）か下かは区別できないので、今回は変えない。

### 背景の範囲

- **A. 行の高さ全体（`SelectionRects` と同じ）。** 隣の行の背景とつながり、ルビや傍点まで覆う。
- **B. 親文字の em ボックス。横書きはフォントの descent まで下に伸ばす。** CSS の `mark` 要素の背景のように、ルビと傍点は背景の外に出る。行間は空いたまま残る。
- **C. ルビまで覆う。** ルビの無い字との高さがそろわない。

B を採った。横書きでは下端を descent まで伸ばし、欧文のディセンダーを覆う。

## 決定

### widgets/basic

- `basic.ScrollPosition{Offset, MaxOffset}` と `AtStart()`、`AtEnd()` を足した。どちらも 0.5 ピクセルの余裕を持つ。内容が表示に収まるときは両端にいる。
- `Scroll.StickToEnd`、`Scroll.OnScroll` を足した。`OnScroll` は動きの各フレーム、ジャンプの後、最大オフセットが変わったレイアウトの後、最初のレイアウトの後に、前回と違う位置のときだけ呼ばれる。`SetState` を呼んでよい。アロケーションしない。
- `ScrollController.Position`、`AtEnd`、`JumpToEnd` を足した。`JumpTo` は次のレイアウトでもう一度適用する。
- 共有の `ScrollState` に `OnScroll`、`StickToEnd`、`Position()`、`StuckToEnd()`、`Measure(view, content)` を足した。`Measure` はレイアウトの後に `Metrics` と最大オフセットを設定し、やり直すジャンプと追従を処理し、`OnScroll` に知らせる。`Viewport` は `Measure` を使う。
- `RichText` の godoc に、スクリーンリーダーはスパンの文字列をつないだもの、つまりルビを除いた親文字だけを読むこと、読みを聞かせたいときは `interact.Semantics` に `Label` を付けることを書いた。`text.Span.Ruby` にも書いた。

### widgets/collection

- `List.StickToEnd`、`List.OnScroll` を足した。`StickToEnd` のリストは末尾で開く。
- `ListController.Position`、`Offset`、`MaxOffset`、`AtEnd` を足した。
- ジャンプの行番号は適用するときの行数で切り詰める。行の高さが決まっているリストでは、ジャンプをすぐに適用し、再構築（`DidUpdateWidget`、行を作る前）と次のレイアウトでもう一度適用して終える。`MeasureItems` のリストは今までどおり、ユーザーがスクロールするまで `Reveal` で行を保ち、再構築のたびに新しい行数で `Reveal` し直す。
- 末尾に追従しているリストは、再構築で行数が変わったら、行を作る前に新しい末尾へ移る（大量に足しても、1 フレームだけ行の無い所が見えることがない）。最後の行が伸びた場合（流れてくるチャットの返事など）はレイアウトの後に末尾へ移る。

### text

- `text.Span.Background` を足した。`Layout.Backgrounds()` が `text.Background{Rect, Color}` を行ごとに返す。同じ行で隣り合う同じ色の字は 1 つの箱になる（右から左の行でもつながる）。箱はレイアウトのときに作るので、描画はアロケーションしない。背景の無い段落では字を調べない。
- 背景だけが変わったスパンも `ReshapeSpans` の変更として扱う。`Relayout` は箱をすべて作り直す。
- `basic.Text`/`RichText`（`RenderParagraph`）は、選択と字の前に箱を塗る。

### widgets/field

- `FuzzySpans` の `hit` を `text.Style` から `text.Span` に変えた。一致した区間は `hit` の `Text` を一致したバイト列に替えたもので、`Style`、`Background`、`Emphasis` を引き継ぐ。`FuzzyHighlight` は `text.Span` を返す。範囲がラベルへのバイトオフセット（ルーンの境界上）であることを godoc に書いた。
- `CommandPalette` の見た目は変えない（太字のアクセント色）。

### カタログ

- `basic.RichText` の例に背景色のスパンを足した（色は `Warning` の 35%）。

## 結果

- ログとチャットは `List{StickToEnd: true}` だけで最新の行に追従する。「最新へ」ボタンは `OnScroll` で `AtEnd` を見て出し入れできる。
- `SetState` で行を足した直後の `JumpToEnd` が新しい最後の行に届く。`After` の回避策は要らない。
- 行の高さが決まっているリストでジャンプを頼むと、レイアウトが 1 回増える。
- 1 回のレイアウトで、コードのジャンプと最大オフセットの変化が重なると、`OnScroll` が 2 回呼ばれることがある（古い最大オフセットとの組と、新しい組）。
- 検索の一致を背景色で示せる。入力欄（`field.Input` など）と `markdown` は自前で描くので、まだ背景を描かない。
- 残したこと: `Reverse` で離れて読んでいる間に足された行で内容が動くこと、`Tree`・`Table`・エディターの `OnScroll` と `StickToEnd`、入力欄と `markdown` の背景。
