# 0023: 縦書きと組版の拡張（Phase 11a）

決定日: 2026-11-08

状態: 採用

## 背景

文字組みの拡張（Phase 11）は 10 項目あるので、Wayland 対応（Phase 10）と同じく 2 回に分けた。

- **11a**（この ADR）: 縦書き、縦中横、縦書きのルビ、両端揃え、インデント、タブストップ。日本語組版を先に固めてレビューする。
- **11b**: カラー絵文字（COLRv0 / COLRv1 / CBDT。sbix は macOS の Phase 12）、BiDi、可変フォント、欧文ハイフネーション、編集の増分レイアウト。

ヒアリングで次も決めた。

- 縦書きの見本は Word の縦書き。作品は『坊っちゃん』の冒頭。手順は Phase 3 と同じく行分割の突き合わせ。
- 縦書きは表示（Text / RichText）だけでなく TextField も対象。v2 の notes サンプルで縦横を切り替えるため。
- 既定フォントは縦でも Yu Gothic のまま（当初の計画の「既定値は変えない」）。明朝は利用者が `Family` で指定する。見本は Yu Mincho で組む。
- 両端揃えも Word と比べ、違いは記録する。規則は JLReq を優先する。

## 決定

### 公開 API（追加のみ）

```go
text.Style{
    Orientation:   text.Vertical,     // 既定は Horizontal
    Align:         text.AlignJustify, // 追加
    Indent:        16,                // 各ブロックの 1 行目（論理ピクセル）
    HangingIndent: 0,                 // 2 行目以降
    TabStop:       64,                // 0 ならタブは空白 1 個（今まで通り）
}
text.Span{TateChuYoko: true}  // 縦中横
text.Span{Upright: true}      // 欧文を正立
paint.GlyphRun{Sideways: true}
text.GlyphKey{Sideways: true}
(*text.Layout).Orientation(), CaretPosition(offset)
core.VerticalIMEHost          // 任意の interface。Host に足すと既存の実装が壊れるため
```

`Paragraph.Layout(maxWidth)` の引数は「行の長さの上限」と読み替えた。縦書きでは列の高さ。名前は互換のため変えず、doc を直した。`VerticalMove` の `x` も「行に沿った位置」で、縦書きでは y。

### 座標: 行に沿った軸と行を重ねる軸

`text` の内部はすべて **inline**（行に沿う）と **cross**（行を重ねる）で持つ。横組は (inline, cross) = (x, y)。縦組は cross を右端から左へ測り、物理座標は (W − cross, inline)。こうすると最初の行はいつも cross 0 から始まり、`jlreq` の Breaker、行の積み上げ、選択とキャレットの計算は向きを知らずに済む。当初の計画の「(y, −x) の座標変換」はこの形にした。

グリフは、横組では行のベースライン、縦組では列の中心線からの位置を持つ。物理座標に直すのは `Layout.buildRuns` と `lineRect` / `toLine` の 3 箇所だけ。

### シェイピング

- go-text（HarfBuzz の移植）を `DirectionTTB` で呼ぶ。`vert` / `vrt2` の置換、`vmtx` の送り、`VORG` か `glyf` のファントム点からの縦の原点は go-text が扱う。**当初の計画が挙げていたリスク（縦メトリクスの不足）は起きなかった。**
- 正立か横倒しかは go-text のセグメンタ（UAX #50）に任せ、そのうえで **全角・広い文字は正立に戻す**。UAX #50 の Tr（ー、〜、（ など）をセグメンタは横倒しにするが、日本語フォントはこれらに縦の字形を持っていて、`vert` で拾う方が字形が正しい。東アジアの文字幅は `golang.org/x/text/width`（当初の計画で許した依存）。
- 横倒しの run は横組として整形し、描くときに 90° 回す。go-text も横倒しの出力を作れるが、位置の決め方が gowaku の中心線と合わないので使わない。横倒しの字は **全角の字面（em ボックス）の中心を列の中心に合わせる**。字面の中心は「あ」の縦の原点から取る（Yu Gothic で 0.38 em）。
- 回転はアトラスでする。`GlyphKey.Sideways` のグリフはアウトラインを回してラスタライズする。シェーダーにもインスタンスにも変更は無く、D3D11 / Vulkan / soft のどれでも同じに出る。
- 縦組でも和文の run ではカーニングを切る（ADR 0007 と同じ理由）。

### 縦中横（JLReq 3.4.3）

- `Span{TateChuYoko: true}` の文字を横組で整形し、1 em の中に置いて 1 つのクラスタにする。2 字なら `hwid`、3 字なら `twid` を付けて字幅を合わせ、それでも 1 em を超えれば文字の大きさを縮める（クラスタごとに描く大きさを持たせた）。
- 行分割では漢字と同じ扱いにするため、`jlreq.Unit` に `Ideographic` を足した。数字のまま分類すると和欧間アキが付いてしまう。
- フォールバックで 2 つ以上のフォントにまたがる縦中横は、ふつうの縦組に戻す。クラスタは 1 つのフォントしか持てないため。まず起きない。

### 縦組の禁則とぶら下げ

`jlreq` は Unit の列に対する純粋なアルゴリズム（ADR 0007）なので、縦組でもそのまま使う。送りは縦の advance、全角かどうか（`FullWidth`）も縦の advance で判定する。縦の字形の約物は空きの位置が横組と同じ（始め括弧は先頭側が空き）なので、詰めの規則も変えずに済んだ。ぶら下げは列の下端の外に出る。

### ルビ

縦書きのルビは列の右に置く。ルビの列の中心は親文字の列の中心から (親文字の em + ルビの em) / 2 右。親文字との配分（1:2:1、仮名への掛け）は横組と共通で、ルビ自身も縦に整形する。最初の列の右にルビの場所を空ける。

### 両端揃え（JLReq 3.8.3）

- `jlreq.Options.Justify`。ブロックの最後の行以外を行の長さまで伸ばす。
- 伸ばす順番: まず欧文の語間と和欧間を 1 箇所につき四分まで、残りを和文の字間に均等に。字間が無い行は語間に全部。どちらも無い行は伸ばさない。
- 伸ばさない箇所: 欧文の単語の中、数字の中、ダッシュとリーダーの中、始め括弧の後、終わり括弧・句読点・中点の前。
- 約物の詰めは戻さない。詰めたまま字間を伸ばす。
- ぶら下げた句読点は前の字と一緒に動き、行の外に出たまま。

### インデントとタブストップ

- `Indent` は各ブロック（改行で区切られた段落）の 1 行目、`HangingIndent` は 2 行目以降。Breaker の行の幅から引き、`X` と `Width` はインデント込みで返す。行揃えはインデント込みの幅で計算する。
- `TabStop` は等間隔のタブ位置。行の始端（インデントの前）から測る。タブの送りは置かれた位置で決まるので、Breaker が行ごとに計算して `Breaker.Advance` に入れ、`Layout` はそれを使う。Style を比較可能に保つため、任意のタブ位置の列（`[]float32`）は持たない。

### TextField

- 縦書きの TextField は高さを受け取り、列が増えると左へ伸びる。最初の列は右端に付ける。
- 矢印キーは向きに合わせて読み替える: ↓↑ が行に沿った移動、←→ が行の移動（← が次の列）。
- 変換中の文節の下線は列の右に引く（傍線）。キャレットは列を横切る横線。
- IME: Win32 の IMM には縦書きのフラグが無い。Word と同じく、合成フォントの `lfEscapement` を 2700 にして知らせる（`ImmSetCompositionFontW`、フォント名は `@Yu Gothic`）。候補ウィンドウの位置は列の矩形を除外領域にして渡す。`platform.Window.SetIMEVertical` を足し、X11（XIM）と Wayland（text-input-v3）は何もしない。どちらのプロトコルにも縦書きの概念が無い。

## 含めなかったもの

- **縦書きの欧文の行揃え**: 横倒しの欧文は字面の中心を列の中心に合わせるだけで、ベースラインを列で揃える指定（CSS の `text-orientation: sideways` と `mixed` の細かな違い）は無い。
- **割注、圏点、縦書きの傍線（下線以外の装飾）**: 当初の計画に無い。
- **任意位置のタブストップ、右揃え・小数点揃えのタブ**: 必要になったら `TabStops` を別の型で足す。

## 結果

- 『坊っちゃん』冒頭 3 段落を Word の縦書きと突き合わせ、行長 360〜630、約物の全角 / 詰め、字下げの 8 条件で行分割が全行一致した。
- 両端揃えは、Word が行末の句読点を詰めて追い込むので、`AlignJustify` だけでは一致しない。`Kinsoku: Oikomi` と組み合わせると縦横とも一致した。既定は変えず、README に書いた。
- Mozc は合成フォントの 270° を見て、予測と候補の窓を列の左に縦組で出した。MS-IME と Linux の IME は未確認。
- 描画のホットパス（Encode）は 0 allocs のまま。縦書きの golden（Go フォントの欧文を縦に組む場面）を足し、soft / D3D11 / Vulkan が一致した。
