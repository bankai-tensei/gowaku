# 0135: 傍点（圏点）、青空文庫の傍点の注記、そろえの幅、DrawRect、Positioned の注意書き

決定日: 2026-11-16

状態: 採用

## 背景

初めて使う人に gowaku を試してもらったところ、次のことが分かった。

1. **傍点が無い：** 縦書き・ルビ・JLReq の組版をうたいながら、強調の傍点（圏点）を付ける手段が無かった。青空文庫の本文には `対象［＃「対象」に傍点］` の注記が多く、`aozora.Spans` に通すと注記がそのまま本文に出た。`field.Input{Ruby: aozora.Marks}` でも同じだった。
2. **自作のウィジェットや Painter から Shaper を取る方法が分からない：** `core.DependOn[*text.Shaper](ctx)` で取れるが、`text.Shaper` にも `control.CustomPaint` にも書いていなかった。
3. **`Paragraph.Layout(w)` の中央そろえが w の中央にならない：** レイアウトの長さは最長の行で、`AlignCenter` はその中でそろえていた。`basic.Text` を幅の決まった箱（`CrossStretch` の `Column` など）に置くと、中央そろえの 1 行が左に寄った。`markdown` はこれを自前でずらして補っていた。
4. **`paint.Canvas` に `DrawRect` が無い。**
5. **`basic.Positioned` の `Left` と `Right` を両方指定しても子が伸びない：** `Right` は `AnchorRight` のときだけ読む。

## 選択肢

### ルビと同じ文字に付く傍点

JLReq の本文は、傍点とルビが同じ親文字に付く場合を明記していない（確かめた範囲で）。CSS Text Decoration 3 は、JLReq をもとに、ルビと同じ側に描く傍点は「ルビの外側」に置くとしている。

- **A. ルビの外側（親文字から見てルビの先）に置く。** CSS と同じで、ブラウザや EPUB の表示とそろう。行間を広げる必要がある。
- **B. 親文字とルビの間に置く。** ルビが親文字から離れ、ルビの位置が傍点の有無で変わる。
- **C. 反対側（縦書きの左、横書きの下）に置く。** 行間は増えないが、「傍点はルビの側」という原則に反し、同じ文の中で傍点の側が変わる。

A を採った。

### 傍点の位置の基準

フォントによって、傍点の字形が em ボックスのどこにあるかが違う。游ゴシックの ﹅ は em ボックスの中央にあるが、縦書き用に右上へ寄せたフォントもある。

- **A. em ボックスで置く。** 字形の置き方がフォントに左右される。
- **B. 字形の墨（グリフの外接矩形）の中心で置く。** フォントに依らず、傍点の列の中央に墨が来る。

B を採った。外接矩形が取れないとき（ビットマップだけの字形など）は em ボックスの中心を使う。

### 青空文庫の注記と入力欄

`［＃「対象」に傍点］` は直前の本文を指す。本文がルビの記法を含むとき（`｜青空《あおぞら》［＃「青空」に傍点］`）、注記の「青空」は記法を除いた本文である。

- **A. 注記を独立したマークにし、対象は別に持つ。** `text.RubyMark` は重ならない前提（入力欄が隠す範囲を決める）で、ルビのマークと重なる。
- **B. 対象をマークにし、注記を対象のマークの記法の一部にする。** 対象がちょうど 1 つのルビの親文字なら、そのルビのマークに傍点を付け、記法の範囲を注記の終わりまで延ばす。対象がルビの親文字とその前後の地の文にまたがるなら、ひと続きの区間ごとにマークを作り、最後のマークが注記を持つ。マークは重ならず、入力欄はルビと同じ規則で注記を隠す。

B を採った。

### そろえの幅

- **A. 文書に書くだけにする。** `basic.Text` の中央そろえが左に寄る問題が残る。
- **B. `AlignCenter` と `AlignEnd` は、有限の maxLength が与えられたら、その長さ全体を使う。** 右から左の段落は既にこうしている。無限の長さ（`geom.Inf`）なら今までどおり最長の行。
- **C. `basic.Text` の描画だけずらす。** キャレットや選択（`SelectionArea`）の座標とずれる。

B を採った。

## 決定

### text

- `text.Emphasis` を足した。`EmphasisNone`（ゼロ値）、`EmphasisSesame`（﹅、JIS X 4051 の既定）、`EmphasisOpenSesame`（﹆）、`EmphasisDot`（•）、`EmphasisCircle`（●）、`EmphasisOpenCircle`（○）、`EmphasisDoubleCircle`（◎）、`EmphasisBullseye`（◉）、`EmphasisTriangle`（▲）、`EmphasisOpenTriangle`（△）、`EmphasisCross`（×）。
- `text.Span.Emphasis` を足した。置き方は次のとおり。
  - 1 字（書記素クラスタ）に 1 つ、親文字の半分の大きさで、字の送りの中央に置く。縦中横はまとまりに 1 つ。
  - 空白（Unicode の Z）、句読点・括弧などの約物（P）、制御文字（Cc、Cf）には付けない。
  - ルビの側、つまり横書きは上、縦書きは右に置く。傍点の列は em ボックスに接する半角幅で、墨の中心をその列の中央に合わせる。ルビのある字では、ルビの列の外にもう 1 列とって置く（案 A）。
  - 縦書きでは傍点を正立させる（三角が上を向く）。
  - ルビの親文字を 1:2:1 に広げたときは、傍点も字に付いて動く。
  - 長いルビは、傍点の付いた仮名には掛けない（掛けると傍点に重なる）。親文字の側を広げる。
- 傍点のある段落は、ルビのある段落と同じ行の高さ（`RubyLineHeight` = 1.75）と最初の行の上の余白をとる。ルビの外に傍点が付く字があれば、行の高さは 1.75 + 0.5 = 2.25 になる。
- 差分の組版（`ReshapeSpans`、`Relayout`）も傍点に対応した。傍点はブロックごとに差し替える。`Relayout` は傍点をすべて置き直す（傍点の数に比例するが、アロケーションは容量が足りる限り無い）。行の高さが変わる場合（最初の傍点が付いた、ルビの外の傍点が現れた・消えたなど）は全体を組み直す。
- `text.RubyMark.Emphasis` を足した。傍点だけのマークは `RubyStart == RubyEnd` とする。
- `Paragraph.Layout` は、`AlignCenter` と `AlignEnd` の段落では、有限の maxLength 全体をレイアウトの長さにする（案 B）。`text.Shaper`、`Paragraph.Layout`、`Layout.Size`、`Align` の godoc に書いた。

### text/aozora

- `［＃「対象」に傍点］` を読む。種類は 傍点、白ゴマ傍点、丸傍点、白丸傍点、二重丸傍点、蛇の目傍点、黒三角傍点、白三角傍点、ばつ傍点。
- 対象は注記の直前の、同じ行の本文で、ルビの記法を除いて照合する。対象がルビの親文字の途中で始まる・終わる場合、直前の本文と一致しない場合、前の注記の範囲に入る場合は、注記を地の文として残す。
- 範囲の注記（`［＃傍点］…［＃傍点終わり］`）、左側の傍点（`［＃「対象」の左に傍点］`）、傍線などほかの注記は読まない（地の文のまま）。
- `Marks` は傍点のマークも返す（案 B）。`dst` に容量があればアロケーションしない。`Plain` は注記も取り除き、`Spans` は `Emphasis` の付いたスパンを返す。`Spans` のアロケーションは、スパンのスライスとマークのスライスの 2 回になった。

### widgets

- `field.Input` は、マークの `Emphasis` をそのまま親文字のスパンに渡す。注記はルビの記法と同じ規則で隠れ、キャレットが入ると記法のまま見える。
- `paint.Canvas.DrawRect(r, p)` を足した。`DrawRRect(geom.RRectAll(r, 0), p)` と同じである。
- `basic.Positioned` の godoc に、`Left` と `Right` を両方指定しても伸びないこと、`PositionedFill`、`Width`/`Height`、`LayoutBuilder` を使うことを書いた。
- `text.Shaper`、`layout.Painter`、`control.CustomPaint` の godoc と、ガイド（英語と日本語）の text-and-ime に、`core.DependOn[*text.Shaper](ctx)` で Shaper を取ることを書いた。

## 結果

- `aozora.Spans` を通した青空文庫の本文に、注記が出なくなり、傍点が付く。
- 入力欄でルビの外に傍点が付くマークを開閉すると、行の高さが 1.75 と 2.25 の間で変わり、行が動く。`Style.RubyRoom` はルビの分しか取らない。傍点とルビが同じ字に付く本文はまれなので、これを受け入れた。
- 中央そろえ・末尾そろえの `basic.Text` は、有限の幅の中で、その幅全体を占める。ゆるい制約（`CrossStart` の `Column` など）でも幅いっぱいになり、ヒットテストと読み上げの矩形も広がる。`markdown` の自前のずらしは 0 になる（残してある）。
- golden の `ruby-vertical` に、地の文の傍点とルビの外の傍点を加えた（テスト用のフォントは欧文だけなので、丸傍点 ● を使う）。
- 残したこと: 範囲の注記と左側の傍点、傍線、横書きの右から左の行の傍点の位置の調整。
