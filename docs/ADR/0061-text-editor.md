# 0061: TextEditor（15b）

決定日: 2026-11-09

状態: 採用

## 背景

ADR 0053 §3 で、`CodeEditor` をやめて汎用の編集面にすると決めた。

- 作るもの:
  - 10 万行の仮想化した編集
  - 検索と置換
  - 範囲にスタイルを載せるフック
  - 行の横の飾りの場所
- 作らないもの: 括弧の対応、インデントガイド、折りたたみ、複数カーソル、ミニマップ

名前は `TextEditor` にした。

## 決定

### 1. API

- `TextEditor{Controller, Label, Style, Wrap, ReadOnly, TabMovesFocus, LineNumbers, HighlightCurrentLine, Border, GutterWidth, Gutter, Decorations, OnChange}`。
- 文書は `*TextEditorController` に持つ。10 万行を毎フレーム文字列で受け渡しすることはできないため。
  - 文字: `Text`、`SetText`、`Line`、`Insert`、`Replace`
  - 選択: `Selection`
  - 履歴: `Undo` / `Redo`
  - 検索: `Find`、`FindNext`、`ReplaceAll`
  - 飾り: `Redecorate`
- Controller が無ければ状態が自分で持つので、ゼロ値でも使える。等幅にするかどうかは、渡すフォントだけで決まる。

### 2. 文書は行の文字列の配列

- ピーステーブルやロープにはしなかった。画面は毎フレーム行を丸ごと求めるので、配列なら O(1) で答えられる。
- 編集の手間は、触れた行の長さに比例する。行の数が変わるときは、後ろの行ごとに 16 バイトずつ動かす手間が加わる。
- 行の先頭のバイト位置は必要になったときに数え、編集した行から先を捨てる。だから、キャレットの近くでの位置の変換は安い。このおかげで、文書全体のバイト位置で動く `widgets/history.go` をそのまま使えた。

### 3. 仮想化

- 論理行ごとに 1 つの `text.Paragraph` を、その行の飾りと一緒に整形する。
- 各行の段の数（折り返したときの見た目の行数）は Fenwick 木に持つ。
  - 整形した行は正確な数を持つ。まだの行は「長さ × 測った平均の文字幅」で見積もる。
  - これで、ピクセル位置にある行も、行のピクセル位置も O(log n) で分かる。
- 整形した行は、画面と前後半ページの範囲でキャッシュする。範囲は連続していて、アロケーションせずに動く。
- 編集では、キャッシュと段の数をずらすだけにする。整形し直すのは編集した行だけ。
- **スクロールを安定させる。** 画面の一番上の行と、そのずれを錨にする。上の見積もりが正確になったら、その差だけスクロール位置を動かす（動いている途中の慣性も一緒に）。
- スクロールは `scrollState` / `scroller` / `scrollFrame` を使うので、ほかのリストと同じホイールの慣性とスクロールバーになる。
- ベンチ（i7-12700H）:

  | 内容 | 時間 | アロケーション |
  |---|---|---|
  | 10 万行の読み込み（最初のフレームまで） | 2.6ms | |
  | スクロールと描画（折り返し無し） | 1.5µs | 0 |
  | スクロールと描画（折り返し有り） | 1.7µs | 0 |
  | 5 万行目に 1 文字打って戻す | 35µs | 72 |

### 4. 飾りのフック

- `Decorations func(行, 文字列, dst) []EditorDecoration` は、行を整形するとき（行が見えてきたときと変わったとき）だけ呼ぶ。返す飾りは、編集面が用意したスライスに足していく。
- 文字の色と太字は整形に入れる。背景、下線、波線は描画で描く。
- 波線は、行ごとにキャッシュした塗りの波形にした。線の描画が要らず、描画はアロケーションしない。
- 関数は比べられないので、ほかの理由で飾りが変わったときは、利用者が `Redecorate` / `RedecorateLines` を呼ぶ。
- 同じ仕組みで、検索結果の強調も、スペルチェックの波線も、構文の色付けも作れる。gallery では「TODO:」の色と、送り仮名の誤りの波線に使った。

### 5. 検索バー

- 右上に置く、目立たない Raised のカード（影は LiftFloat）。中身は次のとおり。
  - 検索語の欄と件数（"k of n" / 「k / n 件」）
  - 大文字と小文字の区別、単語単位、正規表現の切り替え
  - 前へ、次へ、閉じる
  - Ctrl+H で出る置換の行
- 一致はすべて Accent の 22% で塗り、今の一致には髪の毛の線を引く。
- 一致は編集に合わせてずらす。一致は 10 万件まで持ち、改行をまたがない。
- **Ctrl+F の直後に打った文字が、本文に入っていた。** gallery の画面を作る途中で見つけた。検索語の欄がキーボードを取るのは次のレイアウトなので、それまでの打鍵は本文に届く。そこで、その間の文字は編集面が検索語に回し、欄がキーボードを取ったらキャレットをその後ろに置くようにした（テストあり）。

### 6. Semantics と UIA のテキスト

- `RoleTextField` に `Multiline` を付け、`ReadOnly` も持つ。編集できるときだけ `ActionSetValue` を出す。
- 2,000 行までは、文書全体を出す。それより長い文書は、論理行の窓だけを出す。窓は「画面とキャレットの前後 100 行」で、上限は 1,000 行。キャレットが画面から遠ければ、キャレットを中心にする（VS Code のアクセシビリティのページと同じ考え方）。
- 窓の文字と `LineStarts` は、編集の世代と窓ごとにキャッシュする。読み上げ中のスクリーンリーダーに毎フレーム同じ文字列が渡るので、差分を取るのも安い。
- `SetValue` と `SetSelection` は窓に対して働く。ここでの「行」は論理行で、折り返した段ではない。

## 結果

- golden は `editor`、`editor-dark`、`editor-find`、`editor-find-dark`。
- gallery の「デスクトップ」の「会議のメモ.txt」タブで、行番号、飾り、検索を確かめた。
- 残り:
  - 縦書きの編集。
  - 折り返さないときの横のスクロールバー（横へはホイールとキャレットでだけ動く）。
  - 太字は太字の書体があるときだけ効く（golden の goregular には無い）。
  - ダブルクリックしてからのドラッグで、単語単位に広がらない。
  - 検索語の欄で Shift+Enter を押しても前の一致へ行かない。
  - 正規表現の一致は行をまたがない。
  - 検索バーが最初の数行を隠し、キャレットを見せる動きもそれを考えない。
  - 実機のスクリーンリーダーで確かめていない。
