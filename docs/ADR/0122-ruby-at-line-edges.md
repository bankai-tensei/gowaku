# 0122: 長いルビを行頭・行末からはみ出させず、掛けるのは仮名の側だけにする

決定日: 2026-11-16

状態: 採用

## 背景

初めて使う人の試用で、縦書きの段落の先頭に `考《かんがえ》えた`（32px）を置くと、ルビが列の上端より上から始まり、`Scroll` に切られた。

`Paragraph.fitRubies` は、親文字より長いルビを中央に置き、両隣の仮名の数だけ（1 字につきルビ 1 字分まで）掛けてよいとして、足りない分だけ親文字を広げていた。掛けてよい量は両隣の合計で、置き方は常に中央だった。このため:

- 段落の先頭で右（後ろ）だけが仮名のとき、合計の掛け量を左右に半分ずつ割り、行頭より前にはみ出した（上の例で 8px）。
- 改行で行頭に来たルビは、前の行に移った仮名を「隣」と数えたまま、行頭の外に掛けた。行末も同じ。
- 段落の途中でも、片側が漢字なら、その漢字の上に半分掛かった。

JLReq 3.3.6 は、ルビを掛けてよいのは隣の仮名だけで、行頭では親文字の先頭に、行末では親文字の末尾にそろえる（行の外にはみ出さない）とする。横組みでも同じ。

掛ける量は段落の形（幅に依らない）で決まるが、どの字が行頭・行末に来るかは改行（幅）で決まる。

## 選択肢

1. **Layout でルビを行の中に押し込むだけにする**。行頭ではみ出した分は反対側に移るので、反対側が漢字ならその上に掛かる。行末も同じ。
2. **改行のたびに段落の形でルビを置き直す**。fitRubies は幅に依らない Paragraph の仕事で、幅ごとにやり直すと Relayout と ReshapeSpans の分担が崩れる。
3. **掛け量を前後に分けて単位（jlreq.Unit）に持たせ、行頭・行末に来たときだけ、その分を単位の送りに足す**。改行の判断も同じ値を使う。

3 を採った。

## 決定

- `allowedOverhang` は前と後ろの掛けてよい量を別々に返す（隣が同じブロックの、ルビの無い仮名ならルビ 1 字分、それ以外は 0）。
- `fitRubies` は、まず左右に半分ずつ、片側が足りなければもう片側に寄せて掛け、それでも余る分だけ親文字を 1:2:1 に広げる。前に掛ける量を `StartExtra`、後ろに掛ける量を `EndExtra` として単位に記録する。
- `jlreq.Unit` に `StartExtra` と `EndExtra` を加えた。`Breaker` は、単位が行頭に来たら `StartExtra` を、行末に来たら `EndExtra` を、その単位の送り（`Advance`）と行の幅に足す。行末に置けるかの判断も `EndExtra` を含めて行う。追い込み、`MinWidth` も同じ。
- `Layout.addRubySpans` は、行頭の単位のルビを親文字の先頭にそろえる（前に掛けない）。行末では送りが `EndExtra` だけ伸びているので、ルビの末尾は送りの末尾にそろう。
- 右から左の行のルビは扱いを変えていない（日本語のルビの対象外）。

## 結果

- 行頭・行末のルビは、縦書き・横書きとも行の範囲 [0, 行長] に収まる（`text/ruby_edge_test.go`）。片側が漢字のとき、ルビは漢字に掛からず仮名の側だけに掛かる。
- 段落の途中で両隣が仮名の場合の組み方は変わらない。片側が漢字の場合は、その側に掛かっていた分だけ親文字が広がるか、仮名の側に寄る。既存のゴールデン画像には該当がなく、変化しなかった。
- 行頭・行末のルビの付いた字は、掛けられなかった分だけ送りが長い。キャレットとヒットテストはこの送りに従う。
- `jlreq.Unit` が 8 バイト大きくなった。
