# 0027: 透明度 0 の部分木を、ヒットテスト・Semantics・Tab から外す

決定日: 2026-11-08

状態: 採用

## 背景

音楽プレーヤーの見本アプリで、アルバムのタイルにホバーで出る再生ボタンを置いた。ふだんは `AnimatedOpacity` で透明度 0 にしてある。

- `gowakutest.Tester.Tap("再生")` が、プレーヤーバーの見えている再生ボタンではなく、見えないタイルの再生ボタンを押した。
- Semantics ツリーにも、見えない「再生」ボタンがタイルの数だけ並ぶ。v2 で UIA / AT-SPI につなぐと、スクリーンリーダーがそれを全部読み上げる。
- Tab のフォーカス移動も、見えないボタンに止まる。
- 透明度 0 のボタンは、見えないのにクリックを受ける。下にあるタイル自身のタップ（アルバムを開く）を横取りする。

アプリはラベルを変えて逃げていた。

リポジトリ内で、子を残したまま隠す部品は `Opacity`（`AnimatedOpacity`、`AnimatedSwitcher` とダイアログのフェードも中身は `Opacity`）だけだった。`Offstage` / `Visibility` に当たるものはまだ無い。

## 選択肢と決定

### 1. どこで外すか

- (a) `layout.RenderOpacity` が `HitTest` と `Semantics` を上書きする。
  - Tab の順番を集める `collectFocus` は core にあり、`layout` を import できない（CODING_STYLE §3.1）。フォーカスだけ別の仕組みが要る。
- (b) core に interface `Hider { Hidden() bool }` を置き、木をたどる core の処理がすべて見る。
  - `RenderBase.HitTest` の子のループ、`SemanticsBuilder.Visit`、`collectFocus`、`modalScope`、根の扱い。
  - `RenderOpacity` は `Hidden()` で `Opacity <= 0` を返すだけ。
  - 子をたどるヒットテストと Semantics は、どれもこの 2 か所を通る。利用者の RenderObject も、`Hider` を実装すれば同じように隠れる。

**(b) を採る。** 規則が 1 か所にまとまり、v2 で `Offstage` / `Visibility` を足すときも `Hidden()` を書くだけで済む。

### 2. ヒットテストも外すか

Flutter の `Opacity` は、透明度 0 で Semantics だけを外し、ヒットテストは残す。見えないボタンを押せないようにするには、別に `IgnorePointer` を重ねる。

- (a) Flutter と同じにする。Semantics とフォーカスだけ外す。
  - `gowakutest` の `Tap` は Semantics で見つけた場所を押すので、今回の不具合は直る。
  - ただ、マウスやタッチでは見えないボタンが押せたまま残る。タイル自身のタップを横取りし、カーソルも手の形になる。
  - タッチのようにホバーの無い入力では、最初のタップで見えない再生ボタンが動いてしまう。
  - 「Semantics には無いが押せる」という食い違いも残る。
- (b) ヒットテストも外す。

**(b) を採る。** 見えないものは押せない、読み上げられない、Tab で止まらない、と 3 つをそろえる。

ホバーで出すオーバーレイは、そのままでも動く。

- `RenderBase.HitTest` は、子が当たらなくても、範囲の中なら自分を結果に入れる。
- そのため、隠れた子を囲む `MouseRegion` は、これまでどおり入った・出たを受け取る。
- 隠れた子の場所を押すと、下のタイルに届く。
- ホバーでフェードが始まり、透明度が 0 を超えたフレームから、ボタンは押せるようになる。
- 押したときのヒットテストは毎回やり直す。ポインタを動かさずに押しても、表示中のボタンに当たる。

隠れるのは透明度がちょうど 0 以下のときだけ。フェードの途中は見えているので、普通に押せる。`Opacity` の doc には、`MouseRegion` を `Opacity` の外に置く書き方を例で示した。

### 3. gowakutest

`Find` / `FindAll` / `Tap` は Semantics ツリーを探す。隠れた部分木は、もともとツリーに入らない。`gowakutest` の側には手を入れていない。

### 4. ホットパス

- `Hidden()` は、ヒットテストで子ごとに 1 回呼ぶ。interface への型アサーションと比較だけで、アロケーションしない。
- テストで、ポインタの移動が 0 allocs のままであることを確かめた。
- reconcile / Layout / Paint には触れていない。`RenderOpacity.Paint` は、以前から 0 で何も描かない。

## 影響

- 透明度 0 の `Opacity` / `AnimatedOpacity` の中身は、ヒットテスト・Semantics・Tab のフォーカス移動に出てこなくなる。
  - `AnimatedSwitcher` で消えていく側と、ダイアログのフェードも同じ。
  - ダイアログが出る最初のフレーム（fade 0）では、中身は押せない。押すと外側の幕のタップ（閉じる）に届く。人の手では起きない長さなので、そのままにする。
- 見えない部品を「当たり判定だけ」に使っていたコードは動かなくなる。リポジトリ内と 見本アプリ には無かった。必要なら、透明な `Container` に `GestureDetector` を付ける。
- 隠れた部品の中にポインタの入った・出たを取る `MouseRegion` を置くと、表示のきっかけを失う。外側に置く（doc に記載）。
- すでにフォーカスを持つ部品が隠れても、フォーカスは取り上げない。次の Tab で順番の外になるだけ。
- ポインタを動かさないうちに隠れた部品は、次のポインタイベントまでホバー中のまま。
