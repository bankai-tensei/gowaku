# 0091: ReorderableList（並べ替えられるリスト）

決定日: 2026-11-13

状態: 採用

## 背景

当初の計画の `ReorderableList`。ドラッグでの並べ替えは `Tree`（ADR 0059）と `TabBar`（ADR 0060）にだけあり、普通のリストを並べ替える部品が無い。やることリスト、優先順位、プレイリストなどで毎回要る。キーボードでも動かせ、スクリーンリーダーに移動を伝える。

## 選択肢

1. `List` のモードにする（`List.OnReorder` を足す）。
2. `List` を包む別のウィジェットにし、`List` の行に押下を受ける部品を被せる。
3. `Tree` と同じ形の別のウィジェットにし、本体の render object を自前で持つ。

## 決定

選択肢 3。`ReorderableList` を `collection` に新しく足し、`List` と `layout.RenderList` には触れない。

- 1 は `List` の State と、`layout` の共有の `RenderList` に、並べ替えのための分岐と状態（押下、ずらし、時計）が入る。今の `List` は 0 allocs のスクロールを測ったベンチを持ち、ホットパスに分岐を足したくない。`RenderList` には「範囲外のフォーカスの行を残す」仕組みも無い。
- 2 は `List` を変えずに済むが、自動スクロールでドラッグ中の行が作る範囲の外に出ると、その行の render object が消え、捕まえていたポインターのイベントが届かなくなる。行の Element を範囲外に残す口は `List` に無い。キーボードの止まり先（フォーカスの行）も同じ理由で失う。
- 3 は `Tree` が 10 万行で使っている形そのもの。フォーカスの行（＝ドラッグ中の行）だけは範囲外でも作り続ける。行の高さの表は `layout.ExtentTable` を使い回すので、`ItemExtent` と `ItemExtentOf` は `List` と同じ意味で持てる。

`Draggable` / `DragTarget`（ADR 0050）は使わず、`Tree` と同じ自前の押下・移動の処理にした。`Draggable` はウィンドウのどこへでも持っていけるペイロードの仕組みで、同じリストの中での並べ替えには、行の位置からの差し込み先の計算、端での自動スクロール、他の行のずらしが要り、どれも `DragTarget` の外の仕事になる。`Tree` も同じ理由で自前で持っている。

### 1. API

```go
type ReorderableList struct {
    ItemCount int
    ItemExtent float32                 // 0 なら 48。List と同じ
    ItemExtentOf func(i int) float32   // List と同じ
    Label string
    LabelOf func(i int) string         // スクリーンリーダー向けの名前。移動の読み上げにも使う
    OnReorder func(from, to int)
    ItemBuilder func(i int) core.Widget
}
```

- データはウィジェットが持たない。`OnReorder(from, to)` の `to` は「移動した後の添字」で、`slices.Insert(slices.Delete(s, from, from+1), to, item)` でそのまま使える（`TabBar.OnMove` と同じ数え方）。`OnReorder` が無ければ何も動かない。
- `MeasureItems`（ADR 0078）は持たない。ずらしと差し込み先の計算が行の高さを前もって要るため。

### 2. ポインター

- 行のどこを押してもよい。ただし行の中のチェックボックスやボタンのように、押下を自分で受ける部品が先に取る（ヒットテストは子が先）。押しただけではフォーカスが移るだけで、4px 動いたら持ち上がる。
- 持ち上げた行はポインターに付いて動き、影と地（`Raised`）を付けて他の行の上に描く。ビューの外へは半分までしか出ない。
- 差し込み先は、持ち上げた行の中央の下にある位置。間の行は持ち上げた行の高さだけずれて場所を空ける（ライブのすき間）。これで中央が隣の行の半分を越えたところで入れ替わる。
- 離すと `OnReorder` を呼ぶ。元の位置で離したとき、Escape、ポインターのキャンセルでは、行は離した所から元の位置へ戻る。
- ビューの上下の帯（最大 48px、ビューの 1/4 まで）では、`Tree` と同じく最大 900px/s でスクロールする。それ以上動けない向きでは時計を止める。

### 3. キーボード

- リストは Tab で 1 回だけ止まる。上下で移動、Home / End で端、PageUp / PageDown で 1 画面。
- Ctrl+Shift+上下でフォーカスの行を 1 つ動かす。Ctrl+Shift+Home / End で先頭・末尾へ。`TabBar` の Ctrl+Shift+矢印に合わせた（Alt+上下は `Table` のフィルターを開くキーと重なる）。動かした行がフォーカスを持ち続ける。

### 4. 動き

- 行ごとに「静止位置からのずれ」を render object に持ち、目標へ指数的に近づける（時定数 60ms）。行ごとのばねを作るとアロケーションが要るので、これにした。新しく作られた行は目標の位置にいきなり置く。
- 移動を頼んだ後は、次のレイアウトで「前の見た目の位置」から新しい位置へ滑らせる（FLIP）。キーボードの移動では、動かした行は元の位置から、間の行は 1 つずれた位置から。ドロップでは、動かした行だけが離した所から（間の行はもう場所を空けている）。
- `ReduceMotion` のときは、ずらしも戻りも移動後もすべて即座。持ち上げた行がポインターに付いて動くのは操作そのものなので残す。
- 時計は、ずれが残っているか、端で自動スクロールしている間だけ動く。

### 5. Semantics

- `RoleList`（`Label`）の下に、見えている行とフォーカスの行だけが `RoleListItem` を開く。`PosInSet` / `SetSize` で全体の中の位置を言う（仮想化しているので、プラットフォームには数えられない）。
- 移動の後は、隣に置いた `LivePolite` のテキストが「牛乳を 5 件中 2 番目に移動しました」と言う。文言は `basic.Strings.MovedTo`（`FormatMovedTo`）に足した。英語は "Moved Milk to position 2 of 5"。フォーカスは移動した行に付いていくので、読み上げは新しい位置の行でも起きる。
- Semantics に「上へ移動」のような独自の操作は無いので、スクリーンリーダーから直接動かす口は作っていない。キーボードの Ctrl+Shift+上下で動かす。

### 6. 作り直しとの関係

- ドラッグ中に項目が減り、持ち上げた行が無くなったら、ドラッグを捨てる（`OnReorder` は呼ばない）。行が残っていれば続け、差し込み先は最後の行までに詰める。
- 移動の後のすべりは、次の Build の後のレイアウトで始める。呼び出し側が `OnReorder` の中で `SetState` すれば、その Build で新しい並びになる。呼び出し側が並びを変えなかった（拒んだ）場合も、見た目は 1 回すべって元の並びに落ち着く。

## 結果

- 本体と行の Layout / Paint、すべりの時計、ドラッグ中の移動はアロケーションしない（テストで確認。ポインターのイベントを配る core の側は 1 回 1 アロケーションあり、`Tree` のドラッグも同じ）。
- 10 万項目のスクロール: 同じ範囲の中で 0 allocs/op（`BenchmarkReorderableList_ScrollFrame_100k`）。

## 残したこと

- 複数の行をまとめて動かす（`Tree` の選択ごとのドラッグ）。`ReorderableList` には選択が無い。
- 別のリストへのドラッグ、リストの外へのドロップでの削除。
- つまみ（ハンドル）だけで持ち上げる設定、タッチの長押し。
- `MeasureItems` の行。
